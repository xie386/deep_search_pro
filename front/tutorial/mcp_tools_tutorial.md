# MCP 工具接入教程 —— 以「bnf 本地服务」与「12306 车票服务」为例

> **目标**：把 MCP 服务接成 Agent 能调用的工具 —— 一个本地命令服务（法国国家图书馆 bnf，走 `stdio`）＋一个远程端点服务（12306 铁路车票，走 `http`），两条路都走一遍。
> **适用范围**：任意 MCP 服务（本机跑的 Python/Node 服务、远程 Streamable HTTP 端点）。
> **前提**：服务本身能跑起来（本教程第 1 步教你各验一次）。
> **耗时**：约 10 分钟（其中大半是填表与点按钮）。

---

## 0. 五条必须先知道的规则

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | **一个来源 = 一个 MCP 服务；工具由服务自己说了算** | 与 API 那套不同：这里你**不写文档**，服务报什么就有什么。模型只认识**工具**（`mcp:<短名>/<工具名>`） |
| 2 | **接得上 ≠ 想得起（两条独立的质量线）** | 「发现工具 + 勾选确认」只保证**能跑**；工具**能不能被想起**取决于你给它写的**显示名 + 描述 + 关键词**。只做前者，工具就在池子里没人用（bnf 早期就是这样：8 个检索函数全能跑，离线基准里 5 个用例期望工具一个都没进前三） |
| 3 | **未确认的工具，Agent 看不到也调不到** | 发现出来的只是「候选」：落库但不进能力池（路由都不出现），直接调用也会被拒 |
| 4 | **没声明"只读"的工具一律按写操作处理** | MCP 的只读标记只是提示，**不能当安全保证**；写操作要单独勾一次「我确认这是写操作」 |
| 5 | **命令白名单 / 密钥只在本机** | `stdio` 来源只允许跑你填进白名单的那几个可执行文件；密钥只在你本机库里、调用时才注入，界面永远打码 |

> ⚠️ 「发现工具」会真连一次服务（握手 → 列工具 → 用不存在的工具试一次容错），约几秒到几十秒；`stdio` 首次启动要等它加载完。

## 1. 先在外部把服务跑通（省一半排障时间）

**bnf（本地 stdio）** —— 记住一句话：**用服务自己的虚拟环境起它**。

```bash
cd D:\LLM\mcp_servers\bnf
D:\LLM\mcp_servers\bnf\env\Scripts\python.exe bnf_server.py
```

看到 `Starting Gallica BnF API MCP Server` 就成了。
🔴 **实测踩过的坑**：拿本项目 venv 的 python 去起它会报 `No module named 'mcp.server.fastmcp'` —— 项目是 `mcp 2.x`（FastMCP 已改名），这个服务是 `mcp 1.x` 代码。**每个 MCP 服务带自己的 env，不要混用**。

**12306（远程 http）** —— 浏览器直接打开端点 URL，能看到"MCP 端点"的响应（通常是 400/405 之类"请求方式不对"的提示）就说明**网络可达**；打不开就是网络/代理问题，不是本项目的问题。

## 2. 新增来源（「＋ 新增 MCP 来源」）

同一个表单，两种连接方式。下面把**两个实例的填法并排给出**，照抄改路径即可。

| 字段 | 说明 | bnf（stdio） | 12306（http） |
| --- | --- | --- | --- |
| **名称** | 卡片上显示的名字 | `法国国家图书馆（Gallica）` | `12306铁路车票信息查询` |
| **短名** | 进工具 ref，只能 ASCII 字母/数字/`-`/`_`；**定下别改** | `bnf` | `12306-mcp` |
| **连接方式** | stdio / http | `stdio —— 本地命令` | `http —— Streamable HTTP 端点` |
| **命令** | 可执行文件路径（stdio） | `D:\LLM\mcp_servers\bnf\env\Scripts\python.exe` | — |
| **参数** | 每行一个（stdio） | `D:/LLM/mcp_servers/bnf/bnf_server.py` | — |
| **工作目录** | 服务的相对路径基准（stdio） | `D:\LLM\mcp_servers\bnf` | — |
| **环境变量** | JSON（stdio） | `{}` | — |
| **URL** | 端点地址（http） | — | `https://mcp.api-inference.modelscope.net/<端点ID>/mcp` |
| **超时（秒）** | 慢服务调大 | `120` | `60` |
| **命令白名单** | stdio 只允许跑这些可执行名 | `["python"]` | 默认即可 |
| **我声明全只读** | 见下方说明 | 勾 | 勾 |
| **能力描述** | 你自己的话：这个来源是干什么的 | `查法国国家图书馆（Gallica）数字馆藏：按书名/作者/主题/年代/文献类型检索，返回书目元数据` | `查看车票信息,查看当天从出发点到目的地的车票剩余,路程需要中转车票购买规划` |
| **官方介绍文案** | AI 预写的**主要依据**（贴服务方介绍段） | 可留空 | **建议补**（现在两个都空 → 只能手写描述） |
| **README / 文档地址** | AI 预写的**辅助依据**（远程填网址、本地填 README 路径） | 可留空 | 可留空 |

**「我声明全只读」是什么意思**：它只是"你担保这个服务整体只读"这一层**来源级声明**，**绕不过**逐条写操作确认那条闸门。服务里有会改外部状态的工具，就别勾它。

**关于 AI 预写的两份依据**：两者至少填一个，否则点「✨ AI 预写」会被明确拒绝（它会告诉你缺什么）。**这不是 bug** —— 没有依据就不许猜着写。

## 3. 测试连接 → 发现工具 → 勾选确认

1. **保存**来源 → 卡片上点测试/发现（「🔍 发现 / 查看工具」）会跑一次**多步体检**：URL（或命令）合法吗 → 鉴权完整吗 → 内网允许吗 → **真的连得上吗** → 能列出工具吗。**哪一步失败就写在弹窗里**，照提示改，不用猜。
2. 体检通过 → 服务报出工具清单 → 落成**候选**。每行给出：工具名 / 只读或写 / 参数 / 完整 ref（Agent 调用时要照抄它）。
3. 勾选 → 点「✅ 确认勾选」。
   * 只读工具：直接进池。
   * 写操作工具：要**额外勾**「我确认这是写操作」（这也是 M5c-1 立下的人工闸门，任何自动动作都绕不过）。
4. 已确认过的工具**再次发现时，你改过的名字、只读判定、启用状态都会保留** —— 刷新只更新服务自报的东西。

★ **这一步现在会顺带做一件事**：如果来源填了 README 或官方介绍文案，**会自动跑一次 AI 预写**，把「显示名 + 关键词 + 描述」草稿准备好（只在内存里，等你确认）。两个依据都空就跳过，并提示你补一个。

![发现工具与多步体检](/front/tutorial/mcp-03-discover.svg)

**两个实例发现后的样子**：bnf 8 个工具（自然语言检索 / 按主题 / 按书名 / 按作者 / 按年代 / 按文献类型 / CQL 高级检索 / 分节写研究报告）；12306 8 个工具（取日期 / 城市换站码 / 车站名换站码 / 城市全部车站 / 查余票 / 查换乘 / 经停站 / 站码反查车站）。

## 4. 补素材：让 Agent「想得起」它（决定成败的一步）

打开「📝 工具描述」，给**每条工具**填两样：

| 填什么 | 作用 | 怎么写 |
| --- | --- | --- |
| **显示名** | 进卡片标题、词法匹配、向量文本 | 说人话。例：`get-station-by-telecode` → 「站码反查车站」；`search_by_document_type` → 「Gallica 按文献类型检索」 |
| **工具描述** | 顶掉服务的自动摘要；**开头写一行「关键词：」会被当关键词用** | 见下方四条纪律 |

**懒人路径**：点「✨ AI 预写全部描述」→ 它按（官方文案 + README + 工具清单与参数 + 你写的来源级描述）产出草稿 → **你逐条过一眼、改一改** → 「💾 保存全部」。草稿从不自动落库，必须过你的眼。

**四条写作纪律（都是实测逼出来的）**

1. **领域锚定** —— 写清服务于哪个领域/平台，别只写功能。
   *反例*：`取当前日期（查票前先取一次）` 会变成向量里的"离群点"，"今天心情有点好"这类无关问题也会命中它（实测把噪声假阳性从 0 顶到 0.333）。改成「铁路余票查询的第一步：取当前日期，供查火车票时填 date 参数」后归零。
2. **不要写否定式措辞** —— 「与编程/算法里的『排序』无关」反而让"写个快速排序"命中了拼多多商品搜索。只写"它是什么、什么时候用"。
3. **避开跨领域通用词** —— 「今天」「排序」「搜索」「信息」写进关键词就是误触发源。
4. **同源近名工具必须能分开** —— 例：12306 三个站码工具分别是「城市换代表站码 / 城市全部车站清单 / 车站名换站码」，描述里要写清谁是谁。

**卡片上的「⚠️ N 条素材待补」**：这是素材体检结果（只数**硬问题**），点它直接打开工具描述弹窗，每条工具下面会列出它自己的问题与改法。硬判据：显示名是英文标识符 / 取不到任何关键词 / 只有英文或超长的自动摘要 / 描述含否定式措辞 / 同源关键词高度重叠。

> ⚠️ **「🔍 发现 / 查看工具」不会让这个徽标消失** —— 它只刷新服务自报的自动摘要，**明确不碰**你手写的内容（重新发现不会冲掉你写的东西，同一条纪律的两面）。徽标只能靠改显示名 / 补描述消掉，保存后徽标会自动更新。

## 5. 在「AI 助手」里验证

用人话问一句，看它有没有被调到：

| 服务 | 试这一句 | 期望的调用链 |
| --- | --- | --- |
| bnf | 法国国家图书馆里有没有讲巴黎公社的资料 | 走到按主题/自然语言检索类工具（中文主题要先译成法语，如 `Commune de Paris 1871`） |
| 12306 | 我想下周去广州，帮我查从成都出发的火车票 | `取当前日期` → `城市换代表站码`（出发地、目的地各一次）→ `查火车余票` |

**判定"真的调用了"看这几处**：右栏会推「工具路由：命中 N 个完整能力卡」；回答里出现真实数据（车次、票价、书目）；引用来源标注了工具名。

**没被调到怎么办**（九成是描述没写清，不是 Agent 笨）：

1. 看卡片上有没有「⚠️ 素材待补」→ 有就点进去按提示补；
2. 补完再问一次；仍不行，就把那条工具的描述改得更贴近你实际的问法（把你平时会说的词写进「关键词：」行）。

## 6. 维护：日常会遇到的八件事

| # | 场景 | 怎么做 | 注意 |
| --- | --- | --- | --- |
| 1 | 服务升级 / 加了新工具 | 重新「🔍 发现 / 查看工具」→ 勾选新工具 → 确认 | 已确认行的名字/只读/启用状态保留；自动摘要刷新，人工描述不被冲掉 |
| 2 | 改某条工具的描述或显示名 | 「📝 工具描述」→ 改 → 「💾 保存全部」 | 保存后自动重拉来源列表，徽标随之更新 |
| 3 | 临时停用某个工具 | 在发现列表里**取消勾选**它 → 确认（回到未确认态，不进池） | 不用删来源，随时可再勾回来 |
| 4 | 改连接配置（换 URL / venv 路径 / 超时） | 「✏️ 编辑」→ 改 → 保存 → 再走一次发现 | 改 stdio 的命令/工作目录最容易出错，改完必测 |
| 5 | 删除来源 | 卡片「🗑 删除」 | **连带它下面全部工具一起删**，不可撤销；只想去掉几个工具请用第 3 条 |
| 6 | 服务换了机器/端口 | 编辑 URL 或命令/工作目录 → 保存 → 测试连接 | 远程服务核对是否还在允许网段 |
| 7 | 某个工具太爱抢戏 / 老被误调 | 收窄它的关键词与描述；**不要**用「与 X 无关」这类否定式（会反噬） | 例：`IP 归属地` 只写"明确给出 IP 时用" |
| 8 | 改前备份 / 事后回滚 | 素材存在 `data/personal.db`；改前整库快照：`cp data/personal.db "docs/v3.1/backups/personal_db_$(date +%Y%m%d_%H%M%S).db"` | 回滚：停后端 → 用快照覆盖 `data/personal.db` → 重启 |

## 7. 常见问题（FAQ）

**Q：徽标点了「发现工具」怎么还不消失？**
A：按设计，发现工具只刷新自动摘要，**不会**改你的名字与描述。点徽标进弹窗，按每条工具下面的提示补。

**Q：报「参数 xx 类型应为 integer（收到 str）」？**
A：模型把数字写成了字符串。**现在已经自动转换**（`"15"`→15、`"true"`→true）；若仍报错，说明类型真的不对，按报错改。

**Q：结果被截断了 / Agent 老把同一个查询连发两次？**
A：窗口是 6000 字符。服务侧对超长载荷会**自动退回核心字段并提示用 `page` 翻页**；描述里也写清怎么翻页最稳。

**Q：中文关键词查不到东西（返回 0 条）？**
A：Gallica 只认拉丁字母，中文主题要先译（返回里会给提示）。这类"服务自身限制"要写进描述，Agent 才知道怎么绕。

**Q：stdio 服务起不来，日志说 `No module named 'mcp.server.fastmcp'`？**
A：Python 用错了。填**服务自己的 env**：`<服务目录>\env\Scripts\python.exe`。

**Q：报告/长任务写到一半就停？**
A：那个服务把状态存在内存，而本项目**每次调用都是一条新连接**（新进程）。服务侧要把状态落盘（bnf 已做：`_state/` 目录 + 6 小时过期）。接新服务时把这条列进你的检查清单。

**Q：什么时候该用 MCP、什么时候直接用 CLI / API？**
A：服务**已经提供 MCP 端点**就用它；只是本机命令、没有 MCP 封装用**自定义 CLI**；只有 HTTP 接口没有 MCP 用**API 工具**。三者进池后的路由、执行、审计是同一套。

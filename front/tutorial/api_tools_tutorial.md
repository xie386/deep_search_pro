# API 工具接入教程 —— 以「小小API」为例

> **目标**：把 `https://v2.xxapi.cn` 的「抖音热榜」「IP 查询」接成 Agent 能调用的工具 —— 之后你用大白话提问，它会取**真实数据**回答，而不是凭记忆编。
> **适用范围**：任意 HTTP / REST 接口（第三方的、公司内部的、你自己写的）。系统**不预设厂商**：你填 base_url 与鉴权，工具由**一份文档**决定。
> **前提**：厂商**不提供** OpenAPI 文档也能接 —— 第 3 步教你自己写一份最小文档（4 行 JSON 起步，不用学 Swagger 全家桶）。
> **耗时**：约 8 分钟（其中大半是复制粘贴与点按钮）。

---

## 0. 四条必须先知道的规则

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | **「来源」是配置单位，「工具」是调用单位** | 一个来源 = 一份 `base_url` + 一套鉴权（整域名共用）；工具 = 文档里的一个操作（`GET /api/ip`）。模型只认识**工具**（`api:<短名>#<操作名>`），不认识来源 |
| 2 | **没确认的工具，Agent 看不到也调不到** | 解析出来的只是「候选」：它落库、但不进能力池 —— 不注入给模型（路由都不出现），直接调用也会被拒 |
| 3 | **写操作要额外确认一次** | `POST / PUT / PATCH / DELETE` 判定为写操作。即使这个工具已确认，导入时还要单独勾「我确认这是写操作」 |
| 4 | **密钥只存你本机、界面永远打码；文档只在本机解析** | 密钥调用时才注入，列表里显示为掩码；OpenAPI 文档不会外发到任何第三方 |

> ⚠️ 「体检」只校验配置（字段是否齐全、base_url 是否合法），**不联网**。真正发请求是在你问 Agent 的时候 —— 所以体检通过 ≠ 接口可用，反过来也一样。

## 1. 先用 curl 摸清接口（可选，但强烈建议）

接之前先确认三件事：**接口能通**、**参数是什么**、**返回长什么样**。

```bash
# 抖音热榜：没有参数
curl -X GET 'https://v2.xxapi.cn/api/douyinhot'

# IP 查询：ip 是必传参数
curl -X GET 'https://v2.xxapi.cn/api/ip?ip=122.228.216.223'
```

返回形态：

```json
{ "code": 200, "msg": "数据请求成功",
  "data": { "address": "中国浙江温州 电信", "type": "数据中心",
            "begin": "122.228.192.0", "end": "122.228.255.255" } }
```

**为什么值得先跑一次**：返回字段决定了第 2 步「能力描述」怎么写、第 3 步参数怎么描述，也决定了第 5 步该怎么提问（返回体太大的接口要换个问法）。

## 2. 在「🔗 API 工具」页新增来源

进入 **🧩 技能与工具 → 🔗 API 工具**，点指导栏上的 **「＋ 新增 API 来源」**：

![新增来源](/front/tutorial/api-01-entry.svg)

弹出配置表单（**表单平时不占页面，只有点按钮才出现**）：

![来源配置弹窗](/front/tutorial/api-02-source-modal.svg)

以小小API 为例，照下面填：

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| **短名 *** | `xxapi` | 只能用 ASCII 字母/数字/`-`/`_`；它进工具 ref 的前半段（`api:xxapi#…`），**保存后不可改** |
| 展示名 | `小小API（抖音热榜）` | 只给你自己看 |
| **base_url *** | `https://v2.xxapi.cn` | ★ **只写到域名**，不要带 `/api/ip` —— 路径由文档决定 |
| 鉴权方式 | `无鉴权` | 这个站免密钥。要密钥的选「Header 里带」/「Query 参数里带」 |
| 鉴权参数名 / 前缀 | （无鉴权时隐藏） | 例：`Authorization` + `Bearer `（注意 Bearer 后面那个空格） |
| 密钥 | 留空 | **编辑时留空 = 不修改**；只在调用时注入，界面永远打码 |
| 超时（秒） | `30` | 够用；实测这两个接口 0.2~0.4 秒 |
| 默认请求头 | `{}` | 需要版本头之类才填，例：`{"X-Api-Version":"1"}` |
| **能力描述** | `抖音热榜、抖音热搜、实时热点榜单、抖音热门视频排名` | ★ 见下面的说明，**这行决定 Agent 什么时候想起它** |
| 文档链接 | `https://xxapi.cn/doc/douyinhot` | 只做记录，点开在你浏览器里看 |
| 备注 | `免密钥公开接口，免费额度 50 QPS` | 只给你自己看 |
| 允许访问内网 | 不勾 | 只有自建的内网服务才需要勾（默认允许环回地址） |

> 💡 **「能力描述」怎么写**：写**用户会说的话**，不是写技术术语。
> 好例子：`抖音热榜、抖音热搜、实时热点榜单` —— 用户问「今天抖音有什么热点」时能命中。
> 差例子：`GET /api/douyinhot` —— 用户不会这么说。
> 池子小的时候所有工具都会直接注入给模型；池子大了要走向量检索，那时这句话就是**能不能被挑中**的关键。

点 **💾 保存** → 自动进入「导入工具」弹窗。

## 3. 写一份最小 OpenAPI 文档（本文重点）

这一节不用你学 Swagger：**只描述"这个接口怎么调"**，不写 schema、不写示例、不写服务器地址。

### 3.1 最小可用骨架（复制即用）

```json
{
  "openapi": "3.0.0",
  "info": { "title": "小小API", "version": "1.0.0" },
  "paths": {
    "/api/ip": {
      "get": {
        "operationId": "ipQuery",
        "summary": "查询IP归属地",
        "parameters": [
          { "name": "ip", "in": "query", "required": true,
            "schema": { "type": "string" }, "description": "要查询的 IP 地址" }
        ],
        "responses": { "200": { "description": "OK" } }
      }
    }
  }
}
```

就这些。系统会从里面读出：**路径** `/api/ip`、**方法** `GET`、**工具名** `ipQuery`、**参数** `ip`（必填、query 位置、字符串）→ 生成工具 `api:xxapi#ipQuery`。

### 3.2 逐字段含义

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `openapi` | ✅ | 版本号，写 `3.0.0` 就行 |
| `info.title` / `info.version` | ✅ | 随便写，解析时用来显示 |
| `paths` | ✅ | 以**路径**为键（`/api/ip`，**相对路径**，不要写完整 URL） |
| 路径下的 `get` / `post` / … | ✅ | **方法**。写 `post`/`put`/`patch`/`delete` 会被判定为**写操作** |
| `operationId` | 推荐 | **工具名**（`api:xxapi#ipQuery` 里的后半段）。不写会按路径自动兜底（如 `getApiIp`） |
| `summary` / `description` | 推荐 | 工具在中台显示的名字与说明；`summary` 是候选列表里那个名字 |
| `parameters` | 有参数才写 | 参数列表，见 3.3 |
| `requestBody` | 写接口才用 | `POST` 的请求体；支持 `application/json` 与表单 |
| `responses` | ✅ | 只为了格式合法，写 `{ "200": { "description": "OK" } }` 即可 |

### 3.3 三个参数位置（`in`）怎么选

| `in` | 出现在哪 | 例子 | 填法 |
| --- | --- | --- | --- |
| `path` | 路径里 `{}` 的位置 | `GET /orders/{id}` | `{"name":"id","in":"path","required":true,"schema":{"type":"string"}}` ★ 必须是 `required: true` |
| `query` | URL 问号后面 | `GET /api/ip?ip=` | `{"name":"ip","in":"query","required":true,...}` |
| `header` | 请求头里 | 版本头、灰度标 | `{"name":"X-Api-Version","in":"header","required":false,...}` |

`required: true` 的参数**必须由模型给出**，缺了会被网关拒掉（提示缺哪个参数）；`required: false` 的可选。
类型 `schema.type` 支持 `string` / `integer` / `number` / `boolean`；枚举用 `"enum": ["a","b"]`（给的值不在枚举里会被拒）。

### 3.4 三份可直接抄的文档

**① 没有参数（抖音热榜）**

```json
{ "openapi": "3.0.0", "info": { "title": "小小API · 抖音热榜", "version": "1.0.0" },
  "paths": { "/api/douyinhot": { "get": {
    "operationId": "douyinHot", "summary": "获取抖音实时热榜",
    "description": "返回抖音热榜前 50 条：词条 word、热度 hot_value、排名 position。无需参数。",
    "responses": { "200": { "description": "OK" } } } } } }
```

**② 带必填 query 参数（IP 查询）**

```json
{ "openapi": "3.0.0", "info": { "title": "小小API · IP 查询", "version": "1.0.0" },
  "paths": { "/api/ip": { "get": {
    "operationId": "ipQuery", "summary": "查询IP归属地",
    "parameters": [ { "name": "ip", "in": "query", "required": true,
                      "schema": { "type": "string" }, "description": "要查询的 IP" } ],
    "responses": { "200": { "description": "OK" } } } } } }
```

**③ 带路径参数 + 写操作**（示意，接你自己的接口时照改）

```json
{ "openapi": "3.0.0", "info": { "title": "内部订单服务", "version": "1.0.0" },
  "paths": { "/orders/{id}/cancel": { "post": {
    "operationId": "cancelOrder", "summary": "取消订单（写操作）",
    "parameters": [ { "name": "id", "in": "path", "required": true,
                      "schema": { "type": "string" } } ],
    "responses": { "200": { "description": "OK" } } } } } }
```

> 一份文档里可以写**多个路径**（`paths` 下并列多个键），解析时会一次给出多条候选。

### 3.5 七个常见坑（实测踩过）

| 坑 | 现象 / 正确做法 |
| --- | --- |
| 贴了 **OpenAI** 的文档 | **OpenAPI ≠ OpenAI**（前者描述 HTTP 接口，后者是模型厂商）。本框只认 OpenAPI / Swagger 的 JSON 或 YAML |
| 路径里写了完整 URL | `"paths": { "https://v2.xxapi.cn/api/ip": …}` ✗ → 只能写 **相对路径** `/api/ip`，域名由来源的 base_url 提供 |
| 给路径参数漏了 `required: true` | 解析时会被降级/报缺失（路径参数必须 required） |
| JSON 里写了注释 | JSON 不允许注释 → 解析失败。要写注释就改用 YAML |
| 工具名重复 | 同一份文档里两个 `operationId` 重名会自动加后缀区分，但建议你自己起清楚的名字 |
| 方法写错 | 把写接口写成 `get` → 系统当它是只读、不做二次确认；请如实写 `post`/`put`/`patch`/`delete` |
| **把"承重"参数留成可选** | 有些接口**默认参数下会返回空**：实测 Steam 搜索不带 `cc/l` 就返回 `{"total":0,"items":[]}`（看着像"工具坏了"）。**固定值请写进路径**：`"paths": { "/api/storesearch/?cc=cn&l=schinese": { "get": … } }` —— 系统会把 `?` 后面的部分拆成"固定参数"，模型既看不到也不用填（显式写法：操作里加 `"x-static-query": { "cc": "cn" }`）。**同理，价格/货币、语言、版本号这类"只有一个正确答案"的参数都该固化** |

> 💡 不用写 `servers`（服务器地址）—— 域名已经在来源里了；写了也不会被用。

> 🔎 **判断某个参数是不是"承重"的**：在终端把接口手工 curl 两次 —— **带这个参数 vs 不带**，对比返回。
> 两者结果一样就说明它可省；结果不同（尤其是不带时返回空/默认区域/默认语言）就必须固化进文档。
> 这一步花一分钟，能省掉"工具看起来配好了、问它却是空的"这种最难查的问题。

## 4. 解析候选 → 勾选 → 确认

把文档贴进「导入工具」弹窗，点 **🔍 解析候选**：

![导入工具弹窗](/front/tutorial/api-03-import-modal.svg)

- 每个操作先变成**候选（○ 待确认）** —— 此时 Agent 完全看不到它；
- 勾选你要放行的 → 点 **✅ 确认勾选（N）** → 状态变 **✅ 已确认**，它也立刻进能力池；
- **写操作**默认不勾、勾选框是灰的：要先勾「我确认这是写操作」才能选它。

弹窗里同时列出这个来源**已保存**的工具，所以：

- 上次漏勾了一个候选？**不用重新贴文档**，直接在来源卡上点「＋ 导入 / 查看工具」回来勾；
- 重复贴同一份文档是**幂等更新**：已确认的工具**保留你的设置**（名字、只读判定、启用状态都不会被覆盖）。

| 状态 | 含义 |
| --- | --- |
| ○ 待确认 | 已落库、不进池：Agent 看不到、调不到 |
| ✅ 已确认 / 已确认 | 进池：会被注入给模型、可以调用 |
| 已停用 | 来源被停用，它下面的工具全部不可用 |

## 5. 在「AI 助手」里验证

### 5.1 先确认 Agent 知道你有哪些工具

问它：**「你有哪些 API 工具可以用？」** —— 回答里应该出现你刚确认的工具名与 ref。

### 5.2 用大白话提问（两条真实问答）

| 你的提问 | 预期行为 |
| --- | --- |
| 「抖音热榜现在前几名是什么？」 | 调 `api:xxapi#douyinHot`（无参数） |
| 「查一下 122.228.216.223 这个 IP 是哪里的」 | 调 `api:xxapi#ipQuery`，`params={"ip":"122.228.216.223"}` |

> 参数是**必填**的接口，提问里要带上具体值（IP / 城市 / 订单号）—— 否则模型只能先反问你。

### 5.3 判定「真的调用了」的四个证据

![AI 助手验证](/front/tutorial/api-04-ai-verify.svg)

1. **对话里的工具调用卡片**：工具名「调用 API/MCP 能力」+ `ref` + `params` + 状态码/耗时；
2. **右侧「工具调用监控」**：出现同一条记录（工具名 / ref / 状态码 / 耗时）；
3. **审计日志** `data/audit/commands.jsonl`：一行 `{"tool":"invoke_tool","ref":"api:xxapi#ipQuery","ok":true,"status":200,...}`；
4. **数据是"此刻的真实值"**：热榜词条天天在变、IP 归属地不可能被模型凭空编出来 —— 这一条最说明问题。

### 5.4 返回体很大的接口：换个问法

工具返回给模型的文本上限是 **6000 字符**，超出会被截断（末尾会标「…（内容过长已截断）」）。

以抖音热榜为例：接口原始返回 **52 KB**，截断后模型大约能看到**前 6 条**。

- ✅ 好问法：「热榜**第一**是什么？」「**前三条**分别是什么？」
- ❌ 差问法：「把 50 条全列出来」（超出被截掉的部分它确实看不到）

> 这类"胖返回"（一堆图片 URL、无关字段）目前只能靠**问得聚焦**来规避；按字段裁剪属于后续增强，不在当前版本里。

💡 **更有效的办法：先看接口有没有自带的"裁剪/过滤"参数** —— 很多接口支持只返回你关心的字段。
实测例子（Steam 官方 `appdetails`）：不带裁剪返回**几万字符**（含简介 HTML，必被截断）；加上 `filters=price_overview` 只剩 **250 字符**，
价格信息完整保留。把这种参数写进文档的 `parameters`（可用 `enum` 限定取值），模型就会照传。

### 5.5 什么时候"没调用"是正常的

- 问题跟你的工具**无关**（例如问"今天几号"）—— 不该调用；
- 工具是**写操作**且你只是随口问 —— 提示词要求它先跟你确认；
- 池子大、你的问题跟「能力描述」差太远 —— 回到第 2 步把那句话改得更像用户的语言。

## 6. 什么会被拒绝（安全边界）

| 情形 | 表现 |
| --- | --- |
| 工具**未确认** | 拒绝：不进池、调用直接报「未确认」 |
| 来源**被停用** | 拒绝：来源下的工具一律不可用 |
| **缺少必填参数** | 拒绝：提示缺哪个参数 |
| **参数类型不符** | 拒绝：例如该给整数却给了文字 |
| **取值不在枚举里** | 拒绝：提示允许的取值 |
| 来源**没勾「允许访问内网」**却指向内网/环回地址 | 拒绝：模型可控的参数值若是 URL，一律做守卫 |
| 接口返回**跨主机重定向** | 不跟随（避免被跳到别的域名去） |
| `POST / PUT / PATCH / DELETE` 没勾「我确认这是写操作」 | 跳过：确认清单里不包含它 |

任何一次调用（成功或拒绝）都会写进 `data/audit/commands.jsonl`，可以回查。

## 7. 常见问题（FAQ）

**Q：状态显示「未体检」/「✗ 体检失败」怎么办？**
体检只看配置：失败通常是 `base_url` 不合法（没写 `http(s)://`）或鉴权配置不完整。点来源卡上的「🩺 体检」看是哪一项 —— 它**不联网**，所以「通过」也不代表接口真能通（那要靠第 5 步）。

**Q：密钥填错了 / 要换密钥？**
点来源卡「✏️ 编辑」→ 重新填密钥 → 保存。编辑时**密钥留空 = 不修改**。

**Q：短名写错了能改吗？**
不能（工具 ref 依赖它）。删掉来源重建，或者新建一个来源。

**Q：一个来源能放多少个工具？**
没有硬上限。注意：工具越多，注入给模型的候选文本越长、路由越可能走检索模式 —— 所以**能力描述要写准**，别指望靠堆工具。

**Q：怎么删掉其中一个工具？**
目前只能**整源删除**（连带它的所有工具）；只想停用其中一个的话，把这个操作从文档里去掉再重贴，它会被标成待确认（不再进池）。单工具停用按钮登记为后续小功能。

**Q：粘贴文档时提示"解析失败"？**
看提示里的原因：JSON 语法错误（多了逗号/注释）、不是对象结构、或者根本不是 OpenAPI（比如贴了 Markdown 文档页）。对照 3.1 的骨架检查一遍。

**Q：Agent 没调用我的工具，但监控里也没报错？**
说明路由**没把它注入**给模型。检查 ① 工具是 ✅ 已确认 ② 来源是启用状态 ③ 「能力描述」写的是用户会说的话。

**Q：这些配置存在哪里？会同步到云端吗？**
只存在你本机的个人库里（按账号隔离），不上传任何地方。

## 8. 什么时候该用 API、什么时候该用 CLI

| 场景 | 更合适的选择 |
| --- | --- |
| 有稳定的 HTTP 接口 + 明确文档 | **API 工具**（本模块）——不依赖本机装环境，换台机器照样用 |
| 只有命令行工具、或依赖你本机凭证/登录态 | **自定义 CLI** ——它能用你已经认证过的本地环境 |
| 接口要密钥、且厂商提供了 OpenAPI | **API 工具** ——密钥进配置，工具自动生成 |
| 返回体是巨量 JSON、你要的字段很少 | 两者都行，但记住 6000 字符上限：**问得聚焦**比什么都重要 |

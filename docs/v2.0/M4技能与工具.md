## 〇、一句话目标 + 设计来源

**让用户能给 Agent 添加"技能说明书"（SKILL.md），Agent 在对话中按需加载使用——类似 Claude Code 的 slash 命令选单，但技能内容是用户自定义的。**

### 设计来源：AstrBot C-6 + Claude Code slash 命令

| 参考点 | 它怎么做的 | 我们借鉴什么 |
|---|---|---|
| AstrBot Skills | 给 Agent 一份带脚本的技能文档（SKILL.md + scripts），Agent 查说明书干活 | 技能 = 说明书文档，省 token、好维护 |
| Claude Code slash | 输入 `/` 展开技能目录，选中后注入 prompt | 交互形态：输入框 `/` 触发技能选单 |
| 本项目 SOUL.md | 已有 agents_docs/{user}/SOUL.md 人格注入机制 | 复用目录结构 + 读写工具，加一类"技能目录"即可 |

### 核心区别：AstrBot vs 我们的定位

- **AstrBot**：通用机器人基础设施，Skills 是"给 Agent 一份带脚本的技能文档"，面向多用户/多平台
- **我们**：单机个人情报助手，Skills 是"用户写给 Agent 的任务说明书"，面向单账号、快速迭代、Web 端交互

## 一、技能是什么？

### 1.1 技能的定义

一个技能 = 一份 Markdown 文档（SKILL.md），描述"怎么做某件事"的说明书。

```
示例：技能/降价分析流程.md
---
name: 降价分析流程
description: 当用户询问某商品是否值得买、价格走势、降价预测时使用
---

# 降价分析流程

## 触发条件
用户询问某商品的价格、降价、性价比、是否值得买。

## 执行步骤
1. 先查个人库（products/collection/watchlist）看用户是否收藏过该商品
2. 调用网络搜索工具，查询该商品近期价格动态、促销信息
3. 对比历史价格（如有），给出"现在买 / 再等等"的建议
4. 输出格式：先给结论（一句话），再列价格事实（带来源），最后给建议

## 输出模板
**结论**：[现在入手 / 建议等待]
**价格事实**：
- 当前价：¥XXX（来源：京东/天猫）
- 历史低：¥XXX（来源：什么值得买）
**建议**：[1-2 句具体建议]
```

### 1.2 技能 vs 人格(SOUL) vs 知识库(KB)

| 维度 | 人格 SOUL.md | 知识库 KB | 技能 SKILL.md |
|---|---|---|---|
| 定位 | Agent "是什么人" | Agent "知道什么" | Agent "怎么做" |
| 注入方式 | 每次对话都注入 | 按需检索注入 | 选中后注入 |
| 内容 | 说话风格、人设 | 私有文档资料 | 任务执行流程 |
| 粒度 | 1 个（激活人格） | 多篇文档 | 多个技能，按需选 |
| 触发 | 自动 | Agent 模型自主判断 | 用户手动 `/` 选择 |

### 1.3 技能的存储

```
agents_docs/{username}/
├── SOUL.md              # 人格（已有）
├── MEMORY.md            # 记忆画像（已有）
├── SOUL/                # 多人格集（已有）
│   └── 稳重管家.md
└── skills/              # ★ 新增：技能目录
    ├── 降价分析流程.md
    ├── 周报撰写规范.md
    └── 竞品对比模板.md
```

**交互**：


- 标签可点击 `×` 移除
- 发送消息时，技能内容注入到 prompt 中

### 3.4 技能注入

选中技能后，发送消息时：

```python
# build_request_context 中
if selected_skills:
    skill_docs = []
    for skill_name in selected_skills:
        skill_text = read_skill(username, skill_name)
        skill_docs.append(f"### 技能：{skill_name}\n{skill_text}")
    # 拼入 user message 前缀
    user_message_prefix = "## 当前激活技能\n\n请按照以下技能说明书执行任务：\n\n" + "\n\n---\n\n".join(skill_docs)
    user_message = user_message_prefix + "\n\n---\n\n" + original_user_message
```

注入位置：user message 前缀（在用户原始消息之前追加技能说明书）。

**为什么拼入 user message 而非 SystemMessage**：
- 技能是"任务说明书"，拼入 user message 让模型更容易理解为"用户要求我按这个流程做"
- 多个技能时，拼接在 user message 前缀更直观、便于调试
- 不占用 SystemMessage 槽位（SOUL/MEMORY 已经占了）

### 3.5 技能叠加

**支持同时选择多个技能**：

- 输入 `/` → 选中第一个技能 → 再次输入 `/` → 选中第二个技能
- 输入框显示多个技能标签，每个标签独立可移除
- 发送时，所有选中技能内容按顺序拼入 user message 前缀

```
┌─────────────────────────────────────┐
│ [⚡ 降价分析流程 ×] [⚡ 周报撰写规范 ×] 输入问题... │
└─────────────────────────────────────┘
```

### 3.6 一次性使用

- 技能选中后，**发送消息时随 prompt 一起传后端**
- 发送完成后自动清除所有选中技能（不影响下次对话）
- 用户可随时通过 `×` 手动移除单个技能

## 五、技能选单交互设计

### 5.1 触发逻辑

```javascript
// 输入框 @input 事件
function onInput(e) {
  const val = e.target.value
  if (val.startsWith('/')) {
    skillMenuOpen.value = true
    skillFilter.value = val.slice(1)  // 去掉 / 后的过滤词
  } else {
    skillMenuOpen.value = false
  }
}
```

### 5.2 过滤

```javascript
const filteredSkills = computed(() =>
  skills.value.filter(s =>
    s.name.includes(skillFilter.value) || s.description.includes(skillFilter.value)
  )
)
```

### 5.3 键盘导航

```javascript
function onKeyDown(e) {
  if (!skillMenuOpen.value) return
  if (e.key === 'ArrowDown') { e.preventDefault(); selectedIndex.value++ }
  if (e.key === 'ArrowUp') { e.preventDefault(); selectedIndex.value-- }
  if (e.key === 'Enter') { e.preventDefault(); selectSkill(filteredSkills.value[selectedIndex.value]) }
  if (e.key === 'Escape') { skillMenuOpen.value = false }
}
```

### 5.4 选中状态

- 选中技能后，`selectedSkills.value.push(skill.name)`（支持多选）
- 输入框显示多个技能标签（每个标签独立 × 移除按钮）
- 发送消息时，`selectedSkills` 数组随 prompt 一起传后端
- 发送后自动清除全部（`selectedSkills.value = []`）
- 用户可随时通过 `×` 手动移除单个技能

### 6.3 技能注入

```python
def _apply_skills(user_message: str, username: str, skill_names: list[str] | None) -> str:
    """选中技能后，将其内容拼入 user message 前缀。"""
    if not skill_names:
        return user_message
    skill_docs = []
    for skill_name in skill_names:
        skill_path = _user_doc_dir(username) / "skills" / f"{skill_name}.md"
        if not skill_path.exists():
            continue
        content = skill_path.read_text(encoding="utf-8")
        skill_docs.append(f"### 技能：{skill_name}\n{content}")
    if not skill_docs:
        return user_message
    prefix = "## 当前激活技能\n\n请按照以下技能说明书执行任务：\n\n" + "\n\n---\n\n".join(skill_docs)
    return prefix + "\n\n---\n\n" + user_message
```

### D.6 配色：默认松绿（对齐项目主色系）+ 4 套可选

```css
.wx-dock[data-wx="indigo"] { ... }   /* 靛蓝 */
.wx-dock[data-wx="violet"] { ... }   /* 紫罗兰（012 原味，想复刻原图就选它） */
```

### A.1.1 为什么是 CLI 而不是 MCP？（设计哲学）

> **"CLI is the new API"** —— Shawn Yeager

文章https://b23.tv/kbeIm3R《CLI 是什么？为什么大厂突然集体卷命令行？》揭示了 2026 年大厂（Google、飞书、钉钉、企业微信）集体开源 CLI 的根本原因：**CLI 是 AI 的母语**。

| 维度 | MCP | CLI |
|---|---|---|
| Token 消耗 | 所有工具定义一次性注入上下文，工具一多 Token 爆炸（基准测试：MCP 消耗是 CLI 的几十倍） | 按需 `--help` 查用法，零额外消耗 |
| AI 学习成本 | 需要学习结构化 schema | AI 训练了大量命令行语料，天然会用 |
| 调试体验 | 黑盒，出错难排查 | 命令 + 报错一目了然 |
| 鉴权标准化 | 统一规范，适合企业 | 需要自行实现 |

**本项目选择 CLI 路线的理由**：
1. **省 Token**：技能/工具一多，MCP 的上下文膨胀会让免费模型立刻崩窗
2. **AI 友好**：模型对命令行的理解远强于结构化 API
3. **渐进扩展**：新工具 = 新命令，无需改代码、无需重新发布 schema
4. **人类可用**：CLI 面板同时服务用户和 Agent，一套接口两套前端

> 注：MCP 在企业级统一鉴权场景仍有价值，本项目未来可按需补充；MVP 阶段 CLI 是性价比最高的方案。

```javascript
  const cmd = cliInput.value.trim()
  if (!cmd) return
```

### A.5 能力层实现

`tools/_runtime/shell_runtime.py`：

```python
"""Shell 能力层 — 实际执行命令（CLI 面板 + Agent 工具共用）"""
import subprocess
import time
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parents[2]
SANDBOX = PROJECT_ROOT / "data" / "sandbox"

ALLOWED_COMMANDS = {
    "ffmpeg":     {"description": "音视频处理",     "max_runtime": 300},
    "git":        {"description": "版本控制",       "max_runtime": 10},
    "curl":       {"description": "HTTP GET 请求",  "max_runtime": 30},
    "ls":         {"description": "列出文件",       "max_runtime": 5},
    "cat":        {"description": "查看文件内容",   "max_runtime": 5},
    "grep":       {"description": "文件内容搜索",   "max_runtime": 5},
    "echo":       {"description": "输出文本",       "max_runtime": 5},
    "pwd":        {"description": "当前目录",       "max_runtime": 5},
    "mkdir":      {"description": "创建目录",       "max_runtime": 5},
    "python":     {"description": "执行 Python",    "max_runtime": 120},
}

def execute(command: str, args: list[str] = None, timeout: int = 30, username: str = "") -> dict:
    """执行白名单命令，返回结构化结果。"""
    args = args or []
    
    # 1. 白名单校验
    if command not in ALLOWED_COMMANDS:
        return {"ok": False, "error": f"命令 '{command}' 不在白名单", "stdout": "", "stderr": ""}
    
    cmd_meta = ALLOWED_COMMANDS[command]
    user_sandbox = SANDBOX / username
    user_sandbox.mkdir(parents=True, exist_ok=True)
    
    # 2. 执行
    try:
        start = time.time()
        proc = subprocess.run(
            [command, *args],
            cwd=str(user_sandbox),
            capture_output=True,
            timeout=min(timeout, cmd_meta["max_runtime"]),
            env={"PATH": os.environ.get("PATH", "/usr/bin:/usr/local/bin")},
            shell=False,
        )
        elapsed = time.time() - start
        
        # 3. 输出限制
        stdout = proc.stdout[:1_000_000].decode(errors="replace")
        stderr = proc.stderr[:1_000_000].decode(errors="replace")
        
        # 4. 审计
        _audit_log({
            "ts": time.strftime("%Y-%m-%d %H:%M:%S"),
            "user": username,
            "cmd": command,
            "args": args,
            "returncode": proc.returncode,
            "elapsed": round(elapsed, 2),
        })
        
        return {
            "ok": proc.returncode == 0,
            "stdout": stdout,
            "stderr": stderr,
            "returncode": proc.returncode,
            "elapsed": round(elapsed, 2),
        }
    except subprocess.TimeoutExpired:
        return {"ok": False, "error": f"命令超时（>{timeout}s）", "stdout": "", "stderr": ""}
    except FileNotFoundError:
        return {"ok": False, "error": f"命令 '{command}' 未安装", "stdout": "", "stderr": ""}
    except Exception as e:
        return {"ok": False, "error": str(e), "stdout": "", "stderr": ""}

def _audit_log(entry: dict):
    """写入审计日志（JSONL）"""
    audit_file = PROJECT_ROOT / "data" / "audit" / "commands.jsonl"
    audit_file.parent.mkdir(parents=True, exist_ok=True)
    with open(audit_file, "a", encoding="utf-8") as f:
        f.write(json.dumps(entry, ensure_ascii=False) + "\n")
```

### A.6 Agent 工具层

`tools/shell_executor.py`：

```python
"""Shell 工具层 — Agent 可调用的命令行工具"""
from langchain_core.tools import tool
from tools._runtime.shell_runtime import ALLOWED_COMMANDS, execute

@tool
def run_shell_command(command: str, args: list[str], timeout: int = 30) -> dict:
    """
    在沙箱目录中执行白名单内的本地命令。
    
    **可用命令**：
    - "ffmpeg" + args: 音视频处理（转码/拼接/提取音频等）
    - "git" + args: 版本控制操作（限本仓库内）
    - "curl" + args: HTTP GET 请求（无 body，无 header 注入）
    - "ls/cat/grep/echo/pwd/mkdir" + args: 沙箱内文件操作
    - "python" + args: 执行 Python 脚本/命令
    
    **不可用**：
    - 系统命令：rm/mv/cp/chmod/sudo 等
    - 网络命令：wget/nc/ssh 等
    - 编辑器：vi/nano/emacs
    
    **适用场景**：
    - 用户请求"用 ffmpeg 把 X 转 mp3"
    - 用户请求"列出我的资料目录"
    - 用户请求"用 curl 获取某 URL 内容"
    
    **不适用**：
    - 长时间运行的服务（请用专用工具）
    - 写操作超出沙箱（请先 cp 到沙箱）
    
    Args:
        command: 白名单内的命令名（必须严格匹配，大小写敏感）
        args: 参数列表（每个元素是一段参数，不要拼成字符串）
        timeout: 超时秒数（默认 30，最长按命令配置）
    
    Returns:
        {"ok": bool, "stdout": str, "stderr": str, "returncode": int, "elapsed": float}
        失败时 "ok"=False 且 "stderr"/"error" 含原因
    """
    username, _ = _current_owner()
    return execute(command, args, timeout, username)
```

#### A.9.2 实际白名单与限制（＝用户拍板口径：**只读沙箱**）

| 命令 | 实现方式 | 限制 |
|---|---|---|
| `ls` / `cat` / `grep` / `echo` / `pwd` / `mkdir` | **Python 内建**（不依赖外部 exe） | 路径参数必须落在沙箱内，`..`/绝对路径拒绝 |
| `git` | 外部程序 | 仅安全子命令（init/status/log/diff/add/commit…）；禁 `-c` / `-C` / `--git-dir=` / `--work-tree=` 等改根与注入参数 |
| `curl` | 外部程序 | **只允许 GET**；禁 `-o`/`-X`/`-d`/`-H`/`-T`/`--config` 等；URL 必须 `http(s)://` |
| `ffmpeg` | 外部程序 | 参数不设白名单（滤镜复杂不可枚举），靠沙箱 cwd + 路径校验 + 超时兜底 |
| ~~`python`~~ | — | **剔除**（任意代码执行 = 沙箱形同虚设，且解释器不可控） |

**2026-09-10 用户追加拍板**：沙箱**保持只读**——不加 `curl -o`（写文件）、不加 `write` 内建命令。
理由是 M4b 定位就是「看文件 + 抓网页 + 建目录」；文件下载与转码链路留待 M4c 之后再议。
因此沙箱目录目前只能由用户手动放文件（`data/sandbox/{用户名}/`），`ffmpeg` 需要输入文件时走这条路。

六道闸：① 命令白名单 ② 参数级路径校验 ③ 沙箱 cwd ④ 超时（ffmpeg 300s / curl 30s / git 15s / 文件 5s）
⑤ 输出 1MB 上限 ⑥ 审计日志 `data/audit/commands.jsonl`（含 user / cmd / args / cwd / returncode / elapsed / rejected）。

#### A.9.3 实现要点（踩坑留档）

- **`run_shell_command` 的参数名必须是 `argv`，不能叫 `args`**：`BaseTool.args` 是 langchain 的属性，
  用 `args` 做参数名会与之冲突，真机调用报 `TypeError: run_shell_command() got an unexpected keyword argument 'v__args'`。
- **`--git-dir=C:/Users status` 这类「等号写法」**：只比对裸选项名（`--git-dir`）会漏网，必须同时匹配 `flag + "="` 前缀。
- **`curl` 选项的等号写法**（`--max-time=15`）也要接受，否则模型自然写法会被误拒。
- 子进程环境不能只给 `PATH`（会丢 `SystemRoot` 导致子进程异常），改为继承环境 + 覆盖必需项。
- CLI 面板与 Agent **共用同一执行器**：面板能敲什么，Agent 就能执行什么，规则不漂移。

#### B.11.3 安全边界（自定义 ≠ 放松）

- **可执行名只允许纯名字**（`[A-Za-z0-9][A-Za-z0-9._-]*`）：含 `/` `\` `:` 一律拒绝——否则等于把「执行任意程序」交给表单输入。
- 只读清单：每行一条，逐行 token 解析；含 `; | & > < `` $` 等 shell 元字符拒绝；不得以选项开头；单行 ≤6 段。
- 落盘参数（`-o / --output / --output-dir / --output-qrcode / --download`）即便命中只读清单也拒绝（沙箱只读）。
- 路径参数照旧受沙箱校验；审计日志沿用（第三方/自定义 CLI 的执行记录会带 `third_party` 字段）。
- fail closed：未登记、清单为空、查库失败 → 一律「不在白名单」。

#### B.11.4 表单可用性：只读清单支持「整条粘贴」（2026-09-10 用户实测反馈后修）

用户直接粘官方文档里的整条命令（`weread notes top --limit 20`），旧实现按「每行 token 数 ≤6」直接报错——**设计太严**。
现在改为自动裁剪成子命令路径，用户可整条粘贴：

| 粘贴内容 | 存下的规则 | 说明 |
|---|---|---|
| `weread notes top --limit 20` | `notes top` | 首段是可执行名 → 去掉；`--flag` 及其取值不参与白名单 |
| `weread notes export 3300045871 --format markdown --output notes.md` | `notes export` | 纯数字/含中文/含 `=` 的 token 视为「取值」，连同其后内容一起裁掉 |
| `weread search 三体` | `search` | 关键词不写进规则（否则只能搜同一个词） |
| `weread api call /store/search` | （不建议）| 见下方「逃生口」 |

- 保存后前端回显**裁剪说明**（`parse_notes`）：「`weread notes export 3300045871 --output notes.md` → 已裁成 `notes export`」。
- **可执行名填成 npm 包名的纠错**：用户把「可执行名」填成 `weread-agent-cli`（包名），真实命令名是 `weread`，而粘贴行以 `weread` 开头。
  现在若首段在本机 PATH 里真实存在、且与配置的 bin 有前后缀关系 → 自动去掉并在裁剪说明里提示「建议把可执行名也改成 `weread`」。
  ⚠️ **不能只判「PATH 里有同名文件」**：实测本机 PATH 里真有名为 `search` 的可执行文件，会把正常子命令 `search` 误判成命令名、把规则清空
  （e2e 已加「常见子命令 search/info/list 不被误裁」回归）。所以必须再加「与配置 bin 相关」这一条件。
- `--output / -o / --output-dir` 属于**落盘参数**：即便命中只读清单，运行时仍被拒（沙箱只读）→ 要导出文件请在自己终端跑。

#### B.11.7 CLI 简报注入 Agent 上下文（2026-09-11 补，修「配好了却说没有」）

**现象**：用户配好 `weread`（已接入、15 条只读命令）后，在 AI 助手问「调用 run_shell_command 跑 weread shelf list」，
Agent 回答「`weread` 不在沙箱白名单，需先在第三方 CLI 页登记」——**但审计日志里没有任何对应的拒绝记录**，
说明它根本没调工具，而是把我写在工具说明书里的通用白名单描述（`ffmpeg/git/curl…`）当成了「我刚查过白名单」的事实。

**根因**：`compose_dynamic_prompt` 只注入人格(SOUL) + 记忆(MEMORY)，**Agent 上下文里没有 CLI 清单** → 它自知信息不足时倾向保守乱答。

**修法**（三个层次，都不动 agent 缓存/构建逻辑）：

| 位置 | 改动 |
|---|---|
| `tools/cli_registry.py` | 新增 `agent_brief(account_id)`：只对「已接入且清单非空」的 CLI 生成一行（名称 + 可执行名 + 放行条数 + 采样 6 条子命令），有 `max_clis` / `max_chars` 上限，超出提示「其余 N 个未列出」 |
| `agent/build_context.py` | `compose_dynamic_prompt(..., cli_brief="")` 追加【可用命令行工具（用户自配的 CLI，只读）】区块（含调用方式与「被拒时转述错误原文」）；`build_request_context(..., cli_brief=...)` + `ContextBundle.cli_injected` |
| `api/server.py` | `_run_agent` 里由 server 层取 `cli_reg.agent_brief(account_id)` 传入（装配管线不 import api.*），并 `monitor.report_thinking` 报「已注入可用 CLI 清单 N 条」 |
| `prompt/prompts.yml` | 主 Agent 新增「命令行工具使用纪律（M4c）」：优先调工具取真实数据、禁止凭知识编造、**被拒时如实转述错误原文、不许在没有工具返回的情况下声称「不可用/未登记」**、一次一条、argv 用列表 |

**注**：`prompts.yml` 是 4 空格缩进的 YAML 块标量——插入内容必须同缩进，否则 `yaml.safe_load` 直接解析失败（实测踩坑，已修）。

**验证**：`tests/testclient/m4c_cli_e2e.py` 新增「12.5 CLI 简报注入」组（空账号零开销 / 登记后含名称与条数 /
动态 SystemMessage 含区块 / `cli_injected` 标志 / 超上限截断）+ 真机新增一问
「根据你的系统提示，你能通过 run_shell_command 调用哪些命令行工具？」→ 断言回答里出现该 CLI 名（证明注入真进了模型视野）。

**成本**：1 个 CLI ≈ 30-40 token；没配 CLI 的用户注入空串、零开销。

#### B.11.8 后续：M5 工具智能路由（能力描述 + few-shot，2026-09-13）

B.11.7 解决了「Agent **知不知道**有这些 CLI」；但它注入的是**命令名**（`shelf recent` / `book progress`），
用户说「看看我最近在读什么书」时两者语义空间对不上 → 仍然唤不醒（尤其免费小模型）。这是 LLM Agent 的经典「**工具路由**」问题。
M5a 的续接改动（详见 `docs/v2.0/M5工具智能路由.md`）：

| 位置 | 改动 |
|---|---|
| `tools/schema_personal.py` | `user_clis` 加 `abilities` 列（**幂等 ALTER 迁移**，老库自动补列） |
| `tools/cli_registry.py` | `agent_brief()` **双形态**：有 `abilities` → **能力路由卡**（用户语言 + 关键词 + 能力→命令映射）；无 → 回退 B.11.7 的命令名形态。新增 `ability_examples()` / `ability_examples_block()` 抽 few-shot 示例，**每条 argv 过只读闸**（`readonly_verdict`）后才保留 |
| `api/server.py` | `_run_agent` 把示例区块拼在 CLI 简报之后，一起进同一条动态 SystemMessage |
| `prompt/prompts.yml` | 顶层新增 `ability_writer` 独立段（AI 起草能力描述）+ 纪律补「示例只是格式示范、实际命令以区块为准」「口语需求先对关键词」 |
| `front/index.html` | CLI 表单加「能力描述」textarea + 「✨ 按只读清单生成草稿」按钮；卡片新增能力描述区块（未填时提示「AI 只能看到命令名清单，自然语言容易唤不醒」） |

**关键判据**：能力描述是**路由信号**（错了最多没唤醒），只读清单是**安全边界**（错了就是越权）——所以前者可 AI 起草 + 人确认，后者仍必须人给（M4c 底线不动）。

**★ 实测补丁（同日，核实 CLI 命令后）**：`weread book info` / `reviews list` / `book progress` / `discover similar`
**必须带数字 bookId**（`--help` 实测），而口语提问只有书名 → 能力描述的映射要写成**两步链**
（`书评怎么样→book resolve 再 reviews list`，示例生成器取链上第一步）。
不这么写，模型会拿着书名去调一条必报参数错的命令，**或者干脆绕去网搜/知识库作答**
（实测：用户问「我的书评怎么样」，模型用公开书评回答了——用户私有书评 ≠ 公开信息）。
因此主 Agent 纪律另补一条：**私有数据不能拿网搜/知识库顶替**。

**实测结果**：自然语言探针组 **10/10（复跑 9/10）+ 反例 3/3**；**同题对照组（不填能力描述 = B.11.7 命令名形态）仅 2/10**
（8 条探针连工具都没调）；真实账号 + 真实 weread 端到端 **15/15**（拿到只可能来自 CLI 的真数据）。
探针方法论（真桩夹具、只看首调、真值配对）见 `M5工具智能路由.md` §5/§9.7。

### A.1.1 为什么是 CLI 而不是 MCP？（设计哲学）

> **"CLI is the new API"** —— Shawn Yeager

文章https://b23.tv/kbeIm3R《CLI 是什么？为什么大厂突然集体卷命令行？》揭示了 2026 年大厂（Google、飞书、钉钉、企业微信）集体开源 CLI 的根本原因：**CLI 是 AI 的母语**。

| 维度 | MCP | CLI |
|---|---|---|
| Token 消耗 | 所有工具定义一次性注入上下文，工具一多 Token 爆炸（基准测试：MCP 消耗是 CLI 的几十倍） | 按需 `--help` 查用法，零额外消耗 |
| AI 学习成本 | 需要学习结构化 schema | AI 训练了大量命令行语料，天然会用 |
| 调试体验 | 黑盒，出错难排查 | 命令 + 报错一目了然 |
| 鉴权标准化 | 统一规范，适合企业 | 需要自行实现 |

**本项目选择 CLI 路线的理由**：
1. **省 Token**：技能/工具一多，MCP 的上下文膨胀会让免费模型立刻崩窗
2. **AI 友好**：模型对命令行的理解远强于结构化 API
3. **渐进扩展**：新工具 = 新命令，无需改代码、无需重新发布 schema
4. **人类可用**：CLI 面板同时服务用户和 Agent，一套接口两套前端

> 注：MCP 在企业级统一鉴权场景仍有价值，本项目未来可按需补充；MVP 阶段 CLI 是性价比最高的方案。

### A.5 能力层实现

`tools/_runtime/shell_runtime.py`：

```python
"""Shell 能力层 — 实际执行命令（CLI 面板 + Agent 工具共用）"""
import subprocess
import time
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parents[2]
SANDBOX = PROJECT_ROOT / "data" / "sandbox"

ALLOWED_COMMANDS = {
    "ffmpeg":     {"description": "音视频处理",     "max_runtime": 300},
    "git":        {"description": "版本控制",       "max_runtime": 10},
    "curl":       {"description": "HTTP GET 请求",  "max_runtime": 30},
    "ls":         {"description": "列出文件",       "max_runtime": 5},
    "cat":        {"description": "查看文件内容",   "max_runtime": 5},
    "grep":       {"description": "文件内容搜索",   "max_runtime": 5},
    "echo":       {"description": "输出文本",       "max_runtime": 5},
    "pwd":        {"description": "当前目录",       "max_runtime": 5},
    "mkdir":      {"description": "创建目录",       "max_runtime": 5},
    "python":     {"description": "执行 Python",    "max_runtime": 120},
}

def execute(command: str, args: list[str] = None, timeout: int = 30, username: str = "") -> dict:
    """执行白名单命令，返回结构化结果。"""
    args = args or []
    
    # 1. 白名单校验
    if command not in ALLOWED_COMMANDS:
        return {"ok": False, "error": f"命令 '{command}' 不在白名单", "stdout": "", "stderr": ""}
    
    cmd_meta = ALLOWED_COMMANDS[command]
    user_sandbox = SANDBOX / username
    user_sandbox.mkdir(parents=True, exist_ok=True)
    
    # 2. 执行
    try:
        start = time.time()
        proc = subprocess.run(
            [command, *args],
            cwd=str(user_sandbox),
            capture_output=True,
            timeout=min(timeout, cmd_meta["max_runtime"]),
            env={"PATH": os.environ.get("PATH", "/usr/bin:/usr/local/bin")},
            shell=False,
        )
        elapsed = time.time() - start
        
        # 3. 输出限制
        stdout = proc.stdout[:1_000_000].decode(errors="replace")
        stderr = proc.stderr[:1_000_000].decode(errors="replace")
        
        # 4. 审计
        _audit_log({
            "ts": time.strftime("%Y-%m-%d %H:%M:%S"),
            "user": username,
            "cmd": command,
            "args": args,
            "returncode": proc.returncode,
            "elapsed": round(elapsed, 2),
        })
        
        return {
            "ok": proc.returncode == 0,
            "stdout": stdout,
            "stderr": stderr,
            "returncode": proc.returncode,
            "elapsed": round(elapsed, 2),
        }
    except subprocess.TimeoutExpired:
        return {"ok": False, "error": f"命令超时（>{timeout}s）", "stdout": "", "stderr": ""}
    except FileNotFoundError:
        return {"ok": False, "error": f"命令 '{command}' 未安装", "stdout": "", "stderr": ""}
    except Exception as e:
        return {"ok": False, "error": str(e), "stdout": "", "stderr": ""}

def _audit_log(entry: dict):
    """写入审计日志（JSONL）"""
    audit_file = PROJECT_ROOT / "data" / "audit" / "commands.jsonl"
    audit_file.parent.mkdir(parents=True, exist_ok=True)
    with open(audit_file, "a", encoding="utf-8") as f:
        f.write(json.dumps(entry, ensure_ascii=False) + "\n")
```

### A.6 Agent 工具层

`tools/shell_executor.py`：

```python
"""Shell 工具层 — Agent 可调用的命令行工具"""
from langchain_core.tools import tool
from tools._runtime.shell_runtime import ALLOWED_COMMANDS, execute

@tool
def run_shell_command(command: str, args: list[str], timeout: int = 30) -> dict:
    """
    在沙箱目录中执行白名单内的本地命令。
    
    **可用命令**：
    - "ffmpeg" + args: 音视频处理（转码/拼接/提取音频等）
    - "git" + args: 版本控制操作（限本仓库内）
    - "curl" + args: HTTP GET 请求（无 body，无 header 注入）
    - "ls/cat/grep/echo/pwd/mkdir" + args: 沙箱内文件操作
    - "python" + args: 执行 Python 脚本/命令
    
    **不可用**：
    - 系统命令：rm/mv/cp/chmod/sudo 等
    - 网络命令：wget/nc/ssh 等
    - 编辑器：vi/nano/emacs
    
    **适用场景**：
    - 用户请求"用 ffmpeg 把 X 转 mp3"
    - 用户请求"列出我的资料目录"
    - 用户请求"用 curl 获取某 URL 内容"
    
    **不适用**：
    - 长时间运行的服务（请用专用工具）
    - 写操作超出沙箱（请先 cp 到沙箱）
    
    Args:
        command: 白名单内的命令名（必须严格匹配，大小写敏感）
        args: 参数列表（每个元素是一段参数，不要拼成字符串）
        timeout: 超时秒数（默认 30，最长按命令配置）
    
    Returns:
        {"ok": bool, "stdout": str, "stderr": str, "returncode": int, "elapsed": float}
        失败时 "ok"=False 且 "stderr"/"error" 含原因
    """
    username, _ = _current_owner()
    return execute(command, args, timeout, username)
```

#### A.9.2 实际白名单与限制（＝用户拍板口径：**只读沙箱**）

| ~~`python`~~ | — | **剔除**（任意代码执行 = 沙箱形同虚设，且解释器不可控） |

**2026-09-10 用户追加拍板**：沙箱**保持只读**——不加 `curl -o`（写文件）、不加 `write` 内建命令。
理由是 M4b 定位就是「看文件 + 抓网页 + 建目录」；文件下载与转码链路留待 M4c 之后再议。
因此沙箱目录目前只能由用户手动放文件（`data/sandbox/{用户名}/`），`ffmpeg` 需要输入文件时走这条路。

六道闸：① 命令白名单 ② 参数级路径校验 ③ 沙箱 cwd ④ 超时（ffmpeg 300s / curl 30s / git 15s / 文件 5s）
⑤ 输出 1MB 上限 ⑥ 审计日志 `data/audit/commands.jsonl`（含 user / cmd / args / cwd / returncode / elapsed / rejected）。

#### A.9.3 实现要点（踩坑留档）

- **`run_shell_command` 的参数名必须是 `argv`，不能叫 `args`**：`BaseTool.args` 是 langchain 的属性，
  用 `args` 做参数名会与之冲突，真机调用报 `TypeError: run_shell_command() got an unexpected keyword argument 'v__args'`。
- **`--git-dir=C:/Users status` 这类「等号写法」**：只比对裸选项名（`--git-dir`）会漏网，必须同时匹配 `flag + "="` 前缀。
- **`curl` 选项的等号写法**（`--max-time=15`）也要接受，否则模型自然写法会被误拒。
- 子进程环境不能只给 `PATH`（会丢 `SystemRoot` 导致子进程异常），改为继承环境 + 覆盖必需项。
- CLI 面板与 Agent **共用同一执行器**：面板能敲什么，Agent 就能执行什么，规则不漂移。

```python
async def install_cli(cli_id: str, username: str) -> dict:
```

## 附录 D：工作台「时钟 + 天气卡」（M4 收尾）

工作台欢迎语右侧新增一枚卡片：**收起时是一颗药丸（图标 + 温度 + 城市 + 秒级时钟），悬浮或点击展开成完整天气卡**。

### D.1 设计来源（uiverse **012 号 = cards/weather-gradient**）

| 元素 | 处理 |
|---|---|
| 圆角矩形「上沿右高左低」的渐变底板 | 原样移植（`viewBox="0 0 342 300"` + `linearGradient` `#5936B4 → #362A84`），仅把渐变 id 改成项目内唯一名避免与页面其他 svg 撞车 |
| 右上角探出卡片上沿的太阳/云 SVG | 原样移植（`.cloud { top: -16px }`）——**父容器不能有 `overflow: hidden`**，否则被裁掉 |
| 大号温度读数（48px） | 保留，改为「温度 + 天气文字」一行（`display:flex; align-items:flex-end`） |
| 底部 H/L + 地点信息行 | 保留，右侧换成「体感」 |
| 新增（本项目需求） | **秒级时钟**（34px 等宽数字）、中文日期 + 星期、💧湿度 / 💨风速 / 🌧️降水概率、**3 天预报**（今天/明天/后天）、数据源 + 更新时间、**📍 换城市** |
| 收起/展开 | 参考之前 007/011 的悬停范式：药丸淡出 + 卡片淡入放大，**展开用绝对定位浮层**（不占文档流，避免把欢迎语挤走）；`hover` 与 `open`（点击）双通道，触屏也能用 |

### D.2 数据源选型：Open-Meteo（结论：免 Key 即可满足「城市级」）

| 候选 | 结论 |
|---|---|
| **Open-Meteo**（选用） | ✅ **完全免费、无需 API Key**；自带 **地理编码**接口（`geocoding-api.open-meteo.com`，中文/英文城市名都能查，返回 `latitude/longitude/admin1/country`）→ 真正做到**城市级**（成都 30.667/104.067）而非全国一个点；预报按 WMO code 返回，本地映射成中文 + 图标 |
| wttr.in | 免 Key 但为聚合站点，稳定性与字段规范都差，城市级不够精确 |
| 和风 / 中国天气网 / OpenWeather | 需要 Key（用户曾提出「找不到就给我一个 API 工具」——本次不需要） |
| 浏览器直连 | ❌ 不采用：前端直连会把「外网可达性/代理」问题甩给浏览器，且无法缓存 |

**后端代理 `GET /api/weather?token=&city=&force=`**：`city` 留空取 `.env` 的 `WEATHER_CITY`（默认成都）。

### D.3 后端：三层缓存 + 降级（`api/server.py`）

| 层 | 作用 |
|---|---|
| 城市坐标缓存（`_wx_geo`，进程内永久） | 地理编码只做一次 |
| 天气缓存（`_wx_cache`，**10 分钟**，与 Open-Meteo 自身 15 分钟粒度对齐） | 实测同城二次调用 **0.005s** |
| **磁盘缓存**（`data/weather_cache.json`）+ **启动后台预热** | 首次外网请求实测 **2.7~17s**（视 DNS/代理），落盘 + 预热后**重启首屏也能秒出** |

- `_wx_json()`：先走环境（含系统代理），失败**降级直连重试一次**（`trust_env=False`）——照搬本项目 tavily 工具的降级套路；
- 刷新失败但内存里有旧数据 → 返回旧数据并带 `stale/warning`（前端 toast 提示），**不把 502 甩到工作台**；
- 无外网且无缓存 → 502 + 人话提示；城市查不到 → 404「没找到城市「xxx」，换个写法试试」。

### D.4 前端（`front/index.html`）

- 结构：`.wx-dock`（浮层锚点，`margin-left:auto` 贴右侧）内含 `.wx-mini`（药丸）/ `.wx-card`（012 卡片）/ `.wx-card-load`（加载·失败兜底卡，同样带秒级时钟）/ `.wx-city-form`（换城市内联输入）；
- **秒级时钟** `tickClock()`：`setInterval(tickClock, 1000)`，`_pad2` 补零 → `09:05:07`，附「2026 年 09 月 11 日 · 星期五」；天气 `setInterval(..., 10*60*1000)` 与后端缓存对齐；`wxStart()` **幂等**（重复调用不会起第二套定时器）；
- **换城市**：点「📍 换城市」→ 卡片内**联输入**（不用 `window.prompt`，视觉不跳风格），回车确定 / Esc 取消 / 清空 = 回落 `.env` 默认；记忆存 `localStorage['dw_wx_city_{用户名}']`；
- 窄屏（≤1080px）`display:none`，不跟欢迎语抢位置；
- 加载中/失败显示兜底卡（同样有跳动时钟），不会出现空白洞。

### D.6 配色：默认松绿（对齐项目主色系）+ 4 套可选

012 原片段是**紫罗兰**（`#5936B4 → #362A84`），与本项目「浅绿 70% / 白 20% / 黄 10%」的明亮工作台色系不搭。
做法：**卡片所有颜色抽成 CSS 变量挂在 `.wx-dock` 上**，主题作为 `data-wx` 属性切换，标记不用改：

```css
.wx-dock { --wx-c1:#4fae6b; --wx-c2:#1f5c37; --wx-accent:#ffe27a; --wx-sh:35,104,63; }  /* 默认松绿 */
.wx-dock[data-wx="amber"]  { ... }   /* 暖阳 */
.wx-dock[data-wx="indigo"] { ... }   /* 靛蓝 */
.wx-dock[data-wx="violet"] { ... }   /* 紫罗兰（012 原味，想复刻原图就选它） */
```

- **SVG 渐变也吃变量**：`stop-color` 是 SVG 表现属性（优先级最低），一条 CSS 规则即可覆盖 →
  `.wx-card .background stop:first-of-type { stop-color: var(--wx-c1) }`（末位同理配 `--wx-c2`），**换主题不必碰标记**；
- 投影用 `rgba(var(--wx-sh), .28)`（把三通道拆成变量，才能整主题换色）；
- 卡片右下角 4 个圆点即切即换，按账号记忆 `localStorage['dw_wx_skin_{用户名}']`，非法值忽略。

### D.7 用户实测后发现并修掉的问题（值得记下来）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 悬浮展开后是**一块纯色方块、内容全无** | 「换城市输入面板」被插在 `v-if="wx"` 的数据卡与 `v-else` 的兜底卡**之间** → `v-else` 失去相邻 `v-if`，**Vue 生产版会把它当无条件渲染**，兜底卡（同样的渐变底）盖在数据卡上 | 兜底卡改**独立条件** `v-if="!wx"`，不再依赖 `v-else` 的相邻性 |
| 2 | 卡片被**上下一刀切**（只能看到中间一条） | 012 卡高 300px，而 `.hero` 只有 ~130px 且带着 `overflow: hidden`；展开又用 `translateY(-50%)` 居中 → 大半在 hero 外被裁 | ① 卡片改为**从药丸下方展开**（`top: calc(100% + 10px)`，`transform-origin: right top`）；② `.hero` 放开裁切，原本靠它裁的黄色光晕改由**自带 `overflow:hidden` 的装饰层 `.hero-clip`** 承载（视觉零变化） |
| 3 | 点「换城市」时输入面板与展开卡**叠在一起** | 两者共用同一绝对定位槽位 | 展开卡 `v-if="wx && !wxCityEdit"`、兜底卡同；输入面板独占该槽位 |
| 4 | 卡片里温度/城市文字发**暗绿**、两行信息挤在一起 | 卡片在 `.hero` 内 → `.hero p { color: var(--muted); line-height: 1.7 }` **污染了卡片内的 `<p>`** | 加隔离规则 `.wx-card p { color: inherit; margin: 0 }`（同优先级、靠后生效）+ `.wx-card .info-left p { line-height: 1.35 }` |
| 5 | 预报行与底部页脚**互相压字** | 卡片内容实际高度 > 300px，而页脚是 `position:absolute; bottom:12px` | 卡高 300→336，底部内边距留 46px 给页脚；间距微调 |
| 6 | 页脚**折行/省略号**（数据源 + 4 圆点 + 换城市挤不进 298px） | 文案太长 | 显示名缩短为 `🌐 open-meteo · 19:28`（完整值进 `title`）、`white-space: nowrap`、圆点缩到 10px |

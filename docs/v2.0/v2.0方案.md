## 三、网购商品价格 MCP 工具接入（⏰ 勿忘）

- **来源**：用户将提供两个查询网购软件商品价格的 MCP 工具。
- **现状**：价格字段由用户自填（`products.price` / `company_products.price`）。
- **目标**：接入 MCP 后实现**价格自动抓取与历史追踪**，支撑周报「📉 降价提醒」区块（"你关注的 X 本周降价 12%"）。
- **要点**：
  - MCP 工具接入后，价格写回价格历史表（新表），Agent 可跨期比较；
  - 与 Digest 联动：降价类情报优先推送。

## 四、语音合成常驻服务化（⏰ 换设备后）

- **现状**：v1.0 每次朗读用 subprocess 启动 voice_test 脚本（模型每次冷加载 30-60s；长文本分段合成数分钟）。
- **约束**：RTX 3050 显存 4GB，无法长期占用近 3G 显存 → v1.0 保持"用时启、用完关"。
- **目标**（迁移到显存更大设备后）：voice_test 增加常驻 `tts_server` 微服务（加载一次模型），朗读秒出；主项目 HTTP 调用。
- **附带优化**：音色 pkl 的 ref_text 已做 60 字截断（v1.0 实测合成提速 9 倍），常驻化后可进一步探索更高质量音色克隆参数。

## 五、体验优化（可选）

- Digest 报告 PDF 版导出；
- 邮件送达通道（周报定时发邮箱）；
- 报告在线预览（免下载直接看）；
- **子 Agent 调用治理**（原「调用抑制·省 token」条目已废弃，技术讨论见下）：
  - **结论**：免费模型下「省 token」动机不成立（实测免费 API 限流 429、延迟、重复噪音才是真问题）；「次数硬上限 5 次」对网格/清单类任务有害（会砍掉后半实体导致信息不全）。
  - **方向**：① 结构化分配——清单/对比类任务按条目数分配检索预算（每实体 1-2 次）；② 充分性自检——prompt 要求模型收尾前自检「关键维度是否覆盖齐全，有明显缺口则补查，否则停止」；③ 高上限兜底防失控（单轮 12-15 次，只防无限循环）；④ query 质量优先——检索纪律（原文透传/双语/时效）比次数更影响信息量；⑤ 诚实纪律兜底——信息不足时明说「未检索到/覆盖有限」，幻觉防线在 prompt 不在次数。

## 六、工具智能路由（M5）→ **M5a 已落地，见 `M5工具智能路由.md`**

- **要解决的问题**：M4c 让 Agent「知道有哪些 CLI」，但注入的是 **命令名**（`shelf recent` / `book progress`），
  用户问「看看我最近在读什么书」时两者语义空间对不上 → 模型要么不调工具、要么答「该功能不可用」，这是 LLM Agent 的经典**工具路由**问题。
- **M5a（已完成）**：`user_clis.abilities` 能力描述（用户语言：关键词 + 「用户说法→命令路径」映射）
  → `agent_brief()` 双形态（有描述出**能力路由卡** / 无描述回退命令名形态，存量零影响）
  → 从描述生成 **few-shot 映射示例**一起注入（每条 argv 逐条过只读闸）
  → AI 草稿按钮（`ability_writer` 段 + `POST /api/cli/ability_draft`，只返回草稿、人确认后保存）。
- **实测结果**：自然语言探针组 **10/10（复跑 9/10）+ 反例 3/3**；**同题对照组（M4c 命令名形态）仅 2/10**
  （8 条探针连工具都没调）；真实账号 + 真实 weread 端到端 **15/15**（拿到只可能来自 CLI 的真数据）。
- **★ 踩坑（写进教程与规范）**：第三方 CLI 里**需要 ID 的命令**（`book info` / `reviews list` / `book progress` /
  `discover similar`，`--help` 实测）不能直调，能力描述要写成**两步链**
  （`书评怎么样→book resolve 再 reviews list`，示例取链上第一步）；否则模型要么调报错命令、要么绕去网搜。
- **M5b（第三层：检索式工具路由）暂不实施**：触发条件 = 工具数 > 6 或探针出现回退，当前仅 1 个 CLI。
  届时按 M5b 设计（复用 M3 的 bge + 独立 collection `tool_route_{account_id}`）落地即可，A 层已把「能力描述池」备好。
  附带论据：实测残余误差是「在 9 条命令里挑了更泛的那条」，把「9 选 1」收窄成「1-2 选 1」可能同时提升精度。

# 04 桌宠素材收集清单

> 用途：把悬浮球从「三张静态图」换成会动的桌宠。
> 收集方：用户；消费方：`front/desktop/ball_window.py`（Win32 分层窗口逐帧贴图）。
> 原则：**素材只换皮，不改代码**——所有帧按下面的规格交付，机制的实现与素材无关。

---

## 一、先定一件事：画布与基准线

| 项 | 规格 | 为什么 |
|---|---|---|
| 单帧画布 | **256×256 px**，PNG-24 + 透明通道 | 球逻辑尺寸 32~96（默认 64），200% 缩放下物理 128 px；256 给足 2 倍余量，缩小时仍清晰 |
| 角色占画布比例 | 高约 70~85%（即 180~215 px），四周留透明边 | 留边是为了呼吸/跳跃/尾巴摆动时不裁切 |
| **脚底基准线** | 每帧角色脚底都在 **y = 232 px**（画布底部往上 24 px） | 走路帧若基准线不一致，移动时会上下抖，这是桌宠最常见的翻车点 |
| 水平中心 | 角色重心在 **x = 128 px** | 左右翻转与移动对齐都靠它 |
| 静帧留白 | 任何一帧都不许把角色画到画布边缘 8 px 以内 | 防止缩放后出现硬切边 |

> 如果角色是宽扁型（比如趴着的猫），画布可以改成 320×256，但**同一套素材内必须统一**。

---

## 二、必需的四组动作（没有就不算桌宠）

| 状态 | 帧数 | 帧率 | 循环 | 说明 |
|---|---|---|---|---|
| `idle` 待机 | 4~6 | 8~10 fps | 循环 | 呼吸起伏 / 眨眼 / 轻微摇摆；**首帧与末帧要能无缝接上** |
| `walk` 行走 | 6~8 | 12 fps | 循环 | 左右方向只需一套（代码里镜像翻转），迈步幅度一致 |
| `drag` 被拎起 | 2~3 | 6~8 fps | 循环 | 手脚垂下、身体拉长一点；用户按住拖动时播放 |
| `click` 被点 | 2~4 | 12 fps | **单次**（播完回 idle） | 惊讶/招手/弹一下，给点击一个即时反馈 |

## 三、可选的三组语义动作（有则更完整）

| 状态 | 帧数 | 说明 |
|---|---|---|
| `think` 思考中 | 4~6 | agent 正在回答；转圈、托腮、头顶冒泡 |
| `wait` 等待确认 | 4 | 屏幕控制需要用户确认时；招手或指向某处 |
| `error` 出错 | 3~4 | 耷拉、冒汗、变灰 |

> 只做必需四组也能上线；语义三组是加分项，缺了就用 `idle` 顶替。

---

## 四、文件与命名

```
front/desktop/assets/pet/
├── idle_00.png  idle_01.png  idle_02.png  idle_03.png
├── walk_00.png  walk_01.png  ...  walk_07.png
├── drag_00.png  drag_01.png  drag_02.png
├── click_00.png click_01.png click_02.png click_03.png
├── think_00.png ...            （可选）
├── wait_00.png  ...            （可选）
├── error_00.png ...            （可选）
└── meta.json                   （可选：帧率、锚点、作者与许可）
```

- 命名必须是 `状态_两位序号.png`，从 `00` 连续编号，不能跳号（程序按序号探测，遇到缺号即当作该组结束）；
- 同一组内**尺寸必须完全一致**（程序不逐帧缩放，尺寸不一致会跳）；
- 不要给 GIF / WebM / APNG：程序按帧控速，动图会被当成单帧。

`meta.json` 示例（可选，但强烈建议填作者与许可证）：

```json
{
  "author": "xxx",
  "license": "CC0",
  "source": "https://…",
  "canvas": [256, 256],
  "baseline_y": 232,
  "fps": {"idle": 9, "walk": 12, "drag": 7, "click": 12, "think": 9, "wait": 8, "error": 8}
}
```

## 五、画风与工程约束（这几条最容易返工）

1. **透明背景必须是真透明**：不能用白底/黑底导出后"看起来透明"，也不能带半透明光晕——浅色桌面上会出一圈脏边。
2. **描边统一**：如果要描边，所有帧同一宽度（建议 2~3 px @256 画布），否则翻转/缩放后粗细不匀。
3. **阴影单独或不要**：不要画"贴地投影"进帧里（球是浮在桌面上的，投影会跟着走变成脏块）；如果要投影，由代码画。
4. **颜色不要贴在项目绿上**：桌宠是独立形象，配色自由；但**别用大面积纯白**，浅色壁纸下会看不见。
5. **左右方向只做一套**：代码用镜像翻转，别做两套（两套会出现"转身瞬间跳帧"）。
6. **不要带 UI 元素**：气泡、按钮、文字都不要画进帧里。
7. **单帧体积**：每帧压缩后 ≤ 60 KB，整包（约 20~30 帧）控制在 2 MB 以内。

---

## 六、来源与授权（必须记录）

- 优先 **CC0 / 公共领域 / 明确允许商用** 的素材（Kenney、OpenGameArt 的 CC0 区、itch.io 标注 CC0 的宠物包）；
- **不要**用有 IP 的角色（动漫、游戏、电影形象）做商用展示；
- 记录三件事：**作者 / 原始链接 / 许可证名称**，写进 `meta.json`；
- 如果素材是 sprite sheet（一张图排了多帧），可以只交原图 + 告诉我每帧的格子尺寸与排列顺序，我来切。

---

## 七、交付前自检（10 条）

1. 每组帧数达标，序号连续无缺号；
2. 同组内每帧尺寸完全一致；
3. 脚底基准线 y=232 在 idle / walk 所有帧上一致；
4. 水平重心在 x=128（行走帧左右脚交替时允许 ±6 px 内的自然摆动）；
5. 首末帧能无缝循环（把第 0 帧接在最后一帧后面播放，看不出跳）；
6. 背景是真透明，浅色壁纸下无脏边；
7. 没有把投影/地面画进帧里；
8. 每帧边缘 8 px 内没有角色像素；
9. 单帧 ≤ 60 KB，整包 ≤ 2 MB；
10. `meta.json` 里作者 / 链接 / 许可三项齐全。

## 八、批量抠图与统一尺寸（已落地，2026-11-11）

素材是截图（RGB、带背景），必须先去背景再统一规格。选型与结论：

| 工具 | 许可 | 结论 |
|---|---|---|
| **rembg**（`danielgatis/rembg`） | MIT | 选它：纯本地、离线、批量、Python 库，模型可换 |
| rembg 模型 `isnet-anime` | 动漫专用 | 快（1.3 s/帧）但会把截图边缘的色块/投影留下 |
| rembg 模型 `birefnet-general` | 质量优先 | **最终采用**：边缘干净、角落残留明显更少（16 s/帧，一次性） |
| backgroundremover / transparent-background | MIT | 同类替代，未采用（模型选择不如 rembg 灵活） |
| ToonOut（BiRefNet 动漫微调，HF） | 研究向 | 效果可能更好，但要 torch + 1GB 模型；本轮未上 |
| 在线站（remove.bg 等） | 免费额度/水印 | 不适合批量，也不适合把素材传上去 |

**流水线脚本**：`scripts/pet_assets.py`（独立环境跑，不动项目 venv）

```bash
# 一次性准备（隔离环境，避免污染项目依赖）
uv venv --python 3.11 D:/code/_assetpip/venv
D:/code/_assetpip/venv/Scripts/python.exe -m pip install "rembg[cpu]" onnxruntime pillow

# 跑批（默认源 C:/Users/ZQK/Desktop/subwinpic，输出 front/desktop/assets/pet/）
D:/code/_assetpip/venv/Scripts/python.exe scripts/pet_assets.py
```

脚本做的四件事：

1. **抠图**：`birefnet-general` → RGBA；
2. **清边**：丢小连通块（截图边框、角落色块）→ 只保留「不透明核心 + 2px 软边」，削掉画稿自带的灰色投影；
3. **统一尺寸**：256×256 画布、四周 10px 留白；**同一动作的所有帧用同一套缩放与偏移**（否则呼吸/点头会被抹平），组内按并集包围盒顶部对齐、水平居中；
4. **命名与元数据**：`idle1_00.png … say_00.png …`，写 `meta.json`（画布、模型、锚点、每组帧率、待机切换 2 秒）。

**逐组微调**：`SCALE_OVERRIDE`（如 `idle1: 0.80`）用于校正「取景比别的组更紧」的画面，避免切状态时头忽大忽小。

**已知需要人工处理的一组**：`wait_nothing/5`（角色躺在床上，被子与人物连成一片）——任何通用抠图都会把被褥留下，已用 `SKIP_GROUPS` 跳过；建议用纯色背景重拍这一组，或手工抠。

## 九、如果你只想先给最小可用的一套

**4 个文件就能先跑起来**：

```
idle_00.png  idle_01.png   （两帧呼吸）
walk_00.png  walk_01.png   （两帧迈步，代码会镜像 + 循环）
```

`drag` 缺省用 `idle`、`click` 缺省用 `idle` 播一次——机制仍可完整验收，之后再补帧即可。

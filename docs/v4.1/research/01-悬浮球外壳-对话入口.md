## 一 本地现状（只读取证，2026-10-30）

取证手段：源码阅读 + 装机依赖清单 + 既有文档；**未改任何代码、未写任何数据、未起任何服务**。

### 1.1 外壳是「单窗口 + 托盘」，且窗口是普通大窗

| 事实 | 证据 |
|---|---|
| 全文只有一次窗口创建，尺寸 1280×820 | `front/desktop/app.py:1402-1405`（`webview.create_window(APP_TITLE, html_loading, width=1280, height=820, min_size=(1000, 640), js_api=DesktopApi(), text_select=True)`） |
| 启动方式与 profile | `front/desktop/app.py:1506`（`webview.start(debug=…, private_mode=False, storage_path=…, icon=…)`，阻塞至窗口关闭） |
| 托盘已具备，且是可选依赖（缺 pystray 就退化） | `front/desktop/app.py:752`（注释）、`:844-880`（起托盘）、`:819-836`（运行期改标题与图标、忙碌小点） |
| 通知只有两条路：托盘气泡 + 页面内 WS | `_notify`（托盘）；`api/digest_scheduler.py:22` `_notify_ws`（页面没开就收不到） |

### 1.2 全局热键：没有

`front/desktop/app.py` 全文只有 `:807-808` 用 `ctypes` 调 `SetCurrentProcessExplicitAppUserModelID`，**没有** `RegisterHotKey`、**没有**键盘钩子、**没有** `keyboard` / `mouse` / `pynput` 依赖（`importlib.metadata` 逐个查过）。

### 1.3 登录态：壳不注入令牌，登录发生在 webview 里

- `app.py` 全文**无** `token` 关键字（grep 无命中）→ 壳不做令牌注入；
- 凭据落在 webview profile（`storage_path`），即 `data/desktop_webview/`；`docs/文件存放规则.md` §二末把该目录列为「可删可重建」，并注明删掉会让桌面壳退出登录态；
- 推论（待实测，见 §四 第 5 条）：球若是**同进程的第二个窗口**且共用同一 `storage_path`，同源 localStorage 共享，登录态天然继承，不需要额外做令牌传递。

### 1.4 端口与后端生命周期（球要跟着这套走）

| 项 | 证据 |
|---|---|
| 默认端口 8123，顺延最多 5 个（8123→8127） | `app.py:47` `DEFAULT_PORT = 8123`；`:55` `PORT_ATTEMPTS = 5` |
| 就绪超时 180 秒（后端 import 约 20s、实测就绪 55~85s） | `app.py:48` `READY_TIMEOUT = 180` |
| 后端是 uvicorn 子进程 | `app.py:411-440` `start_backend()` |
| 就绪判定：端口响应 + 子进程存活 + 未监听宽限 90s | `app.py:352-400` |

### 1.5 装机版 pywebview 的能力面（`.venv/Lib/site-packages/webview/window.py`，版本 6.2.1）

`Window.__init__` 的全部参数（逐条抄自源码签名）：

```text
title, url, html, width, height, x, y, resizable, fullscreen, min_size, hidden,
frameless, easy_drag, shadow, focus, minimized, maximized, on_top, confirm_close,
background_color, js_api, text_select, transparent, zoomable, draggable, vibrancy,
menu, localization, http_port, server, server_args, screen
```

结论：悬浮球需要的开关（`frameless` / `on_top` / `transparent` / `easy_drag` / `draggable` / `shadow` / `background_color` / `x`,`y` / `screen` / `focus` / `min_size`）**这套版本已全部具备** —— 外壳这一步不需要为它升级依赖，也不需要换框架。

## 二 意向形态（本步要长成什么样）

1. **常驻球**：默认落在屏幕某个角落，尺寸小（几十像素级），浮在其它窗口之上；
2. **单击展开对话**：球体单击 → 弹出小面板（对话输入 + 流式回答区）；
3. **不抢焦点**：球浮着但不打断用户当前窗口（`focus=False` 方向）；
4. **可拖**：拖到任意角落并记住；拖动不应误触发对话；
5. **托盘联动**：托盘菜单加「显示/隐藏悬浮球」，与现有托盘复用；
6. **对话复用现有链路**：`/api/chat` 与会话历史（SQLite）不变，球只是另一个入口；
7. **外观配置化**：尺寸、透明度、是否置顶、初始角落走设置页（`utils/settings.py` 的开关/参数），不进 `.env`。

## 三 候选路线与代价

| 路线 | 做法 | 代价 | 收益 | 风险 / 未知 |
|---|---|---|---|---|
| A. 同进程第二个 pywebview 窗口 | 在 `front/desktop/app.py` 里再 `create_window` 一个球窗（`frameless + on_top + transparent + easy_drag + focus=False`），共用同一 `storage_path` | 低（装机版参数齐备，无需新依赖） | 登录态天然继承；与托盘、后端生命周期天然同频 | 多窗口事件循环细节；球窗与主窗的关闭语义要理清；透明与阴影互斥（`winforms.py:264`） |
| B. 独立小进程（第二个 pywebview 进程 + 独立托盘） | 单独一个球进程，连同一后端 | 中（要处理端口发现、登录态共享、进程互踢） | 球崩了不带走主壳 | 两个进程抢同一 profile 可能冲突；进程管理复杂度上升 |
| C. 主窗口内的「准悬浮」浮层 | 不新建窗口，只在 `front/index.html` 里做一个可拖动的浮层 | 最低（纯前端改动） | 最快能看见效果 | **做不到浮在其它应用之上** —— 窗口仍是普通窗，只能当过渡形态 |
| D. 纯 Win32 自绘窗体（绕过 webview） | 用 pywin32/qt 自绘球体与面板 | 高（失去 HTML/CSS 与现有前端复用，输入法、字体、富文本都要自己扛） | 极致轻量、可做点击穿透 | 与项目既有前端资产彻底分家，维护双份 UI |

**候选取舍留待定方案期**（本节只列代价，不定结论）。

## 四 未知项与实测清单（只读探测到不了，必须真窗口跑）

1. **透明窗的实际观感**：WebView2 上 `transparent=True` 后，圆角边缘是否有底色残留、球体外的方块区域是否可点击穿透（鼠标点下去会不会挡住底下的窗口）。
2. **拖动与交互是否打架**：`easy_drag` 会吃掉拖动事件，球内的输入框、按钮还能不能正常点；要不要限定拖动区域（`draggable` / 自绘拖动手柄）。
3. **多显示器与缩放**：150% / 200% 缩放下球的初始落点与拖动是否准（`winforms.py:620-643` 已做逻辑→物理换算，但球自身尺寸与落点仍需实测）。
4. **焦点行为**：`focus=False` 时点球体输入框能否自动获焦；不能就要显式 `window.focus()`。
5. **登录态共享**：同进程两个窗口共用 `storage_path` 时，localStorage / 登录态是否共享（推断共享，需实测确认）。
6. **关闭语义**：主窗口现有 `closing` / `closed` 事件链，球窗关闭时是否要连带处理（避免关球把主壳带走）。
7. **托盘与球的状态同步**：托盘的忙碌小点（`app.py:819-836`）与球上的回答状态要不要打通。

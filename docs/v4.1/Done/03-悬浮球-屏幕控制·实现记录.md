## 一、这一大点交付了什么

在 02「能看屏」之上，加一档**「能动手」**：agent 可以点鼠标、打字、按回车、滚滚轮，但每一步都受四道闸门约束。

| 工具 | 签名 | 作用 |
|---|---|---|
| `mouse_click` | `(x, y, capture_id, reason, double=False)` | 左键单击/双击 |
| `type_text` | `(text, capture_id, reason)` | 输入文字（中文走剪贴板粘贴） |
| `press_key` | `key, capture_id, reason, times=1` | 单键（回车/退格/Tab/Esc/方向键等） |
| `mouse_scroll` | `(x, y, notches, capture_id, reason)` | 滚轮，正数向上、负数向下 |
| `screen_capture`（02 已有，本点扩展） | `(reason, monitor=0, region=None)` | 看屏；`region` 走局部放大 |

工具面刻意小：右键、拖选、组合键留到后续版本。

## 二、四道闸门（都在工具函数体里，不靠提示词自觉）

1. **本轮是否允许动手**：`computer_use`（看）与 `allow_control`（动手）两档都要开；只开前者时，中间件把四个控制工具从模型工具表里**摘掉**，模型连卡片都看不到。
2. **次数**：`CU_MAX_ACTIONS_PER_TURN`，默认 20（可配 1~50），超了直接拒绝。
3. **帧是否最新**：每个动作必须带 `capture_id`，与轮内最近一帧不一致就拒绝，杜绝「看着旧帧点新界面」。
4. **白名单**：`CU_WHITELIST`（设置页多行文本，每行一个进程名，默认预填 `python.exe`，清空即全拒）。点击判两层——前台窗口的进程、以及 `WindowFromPoint` 落点那个窗口的**顶层属主**进程；打字与按键只判前台（没有落点）。

## 三、坐标与输入的实现口径

- 模型给的是**截图上**的像素，工具按 `物理 = 图上 ÷ scale + screen_rect 原点` 换算；`scale`/`rect` 来自 02 的帧元数据，存在 `cu_mode` 轮内状态里。
- 鼠标走 `SetCursorPos` + `SendInput(MOUSEEVENTF_LEFTDOWN/UP)`；滚轮走 `SendInput(MOUSEEVENTF_WHEEL)`，一格 120 单位。
- 键盘：`press_key` 走虚拟键码；**文字一律走「写剪贴板 → Ctrl+V」**——键盘扫描码没有汉字，逐键注入会和输入法打架，粘贴不经输入法反而最稳；用完把原剪贴板内容还原。
- 审计：每次成功注入追加一行到 `data/audit/cu_actions.jsonl`（时间/会话/帧号/动作/坐标或文本长度/注入后前台进程），**不含屏幕内容**。

## 四、性能：CU 模式只留屏幕工具

初版把全部业务工具（搜索、写文件、CLI、子 agent、价格/比价能力卡…）都挂在工具表上，每轮还要跑一次工具路由、注入约 1.56 万字的能力卡简报。真机表现为「一步要等十几秒」。

现在：`computer_use` 打开时，中间件只放行屏幕工具（看：1 张；看+动：5 张），**并跳过工具路由**（不再调用决策模型、不再拼简报）。用户反馈「速度得到了极大的提升」。

## 五、小图标：为什么要局部放大

一次真机里，模型连续三次点空：放大镜图标、Edge 侧栏图标、桌面 Edge 图标。原因不是注入不准（`SetCursorPos` 是物理像素级），而是**模型从缩略图里估坐标的误差大于目标本身**：2880×1620 压到 1456×819（scale 0.506）后，一个 24px 图标在图里只有 12px，而模型报点的典型误差是 ±10~20 图像像素。

落地做法（方案 A）：给 `screen_capture` 加 `region`，坐标仍是「当前帧图上的像素」，工具换算成物理像素交给外壳裁剪，**按原生分辨率返回**（长边 <300 放大 3 倍、<900 放大 2 倍），不按长边压缩。放大帧不消耗截图额度，单独计数并封顶（2 × 截图额度，12~60）。

「小」的判定：截图上外接框长边 **< `SCREEN_SMALL_TARGET_PX`（默认 40 图像像素，可调 8~200）**，折合屏幕约 80 物理像素。取这个数的理由：模型误差 ±10~20 图像像素，取两倍余量；典型命中标题栏按钮、工具栏图标、地址栏小图标、下拉小三角、桌面图标、卡片右上角 ×。大按钮、整行卡片、输入框不用放大。

## 六、真机验收（三轮，全部由用户手动发起）

| 轮次 | 题目 | 结果 |
|---|---|---|
| 一 | bilibili：搜索「小约翰可汗」→ 进个人空间 → 打开最新一期 | 通过（7 次动作、6 张截图，最后一条回执因额度用尽没能再确认，画面已到位） |
| 二 | SakuraCat：点「切换」→ 滚轮找新加坡节点 → 切换 | 通过（3 次动作 + 2 张截图，选中最优节点） |
| 三 | Edge → DeepSeek 官网 → 对话 → 问「猪肺吃法」→ 滚动读长回答 → 汇总 | 通过（动作 7/20，第二次续轮 4 次动作读完并汇总；这次暴露了截图额度 6 张太紧，已放宽到 50） |

自动化侧另有两条独立验证：

- 记事本闭环：点击 → Ctrl+A → 粘贴中文 → 回车换行 → Ctrl+S → 读回文件内容逐字一致；
- 滚轮探针：自建 tkinter 窗口记录 `MouseWheel`，向下 3 格收到 3 个 `-120`、向上 2 格收到 2 个 `+120`。

## 七、踩过的坑（都是真机才暴露的）

| 现象 | 根因 | 修法 |
|---|---|---|
| 中文一个字也打不进去 | `GlobalAlloc`/`GlobalLock` 没声明 argtypes，64 位句柄被截成 32 位 | 补 `restype = HGLOBAL`、`GlobalLock.restype = c_void_p` |
| 点搜索框被拒「落点处窗口（未知进程）不在白名单」 | 进程没有 DPI 感知，`WindowFromPoint` 按逻辑坐标解释物理坐标，点落在屏幕外 | 模块**导入时**就声明 per-monitor aware（不能等 `click()` 里再调） |
| 回执显示「落点所在窗口：undefined」 | 运行中的是未提交的中间版本，回退值写成了字面量 | 当前代码回退为「（未知）」；该字段也用来暴露点空 |
| 模型选型页勾了「支持图片」，开屏幕共享却报不支持 | `saveProvider` 的 payload 取的是「新建配置」表单的对象，保存已有配置时把勾选重置成 0 | 改取本行 `p`；保存后回读一次；新增静态守卫测试 |
| 点小图标连续点空 | 缩略图分辨率低于模型定位精度 | 方案 A：region 局部放大 + 提示词里写阈值 |
| 一轮 6 张截图不够读长回答 | 额度按「翻页阅读」估的 | 上限放到 1~50，默认仍 6 |
| CU 轮里模型凭空要「整理 DeepSeek 各模型定价对比报告」 | 每轮 1.56 万字工具简报里堆满比价能力卡，叠加账号记忆里的「关注大模型 API 成本」与官网横幅「更低成本」 | CU 模式跳过工具路由、只发屏幕工具（本条同时是性能改造） |

## 八、明确不做

- 右键菜单、拖选、组合键（`Ctrl+A`/`Ctrl+S` 这类只在执行器内部用，未暴露成工具）；
- 后台静默操作、锁屏运行、无人值守的批量触达；
- 屏幕内容入历史或审计；
- 让模型自己算物理坐标（一律由工具换算）。

## 01 悬浮球外壳（对话入口）

> 状态：方案已定（2026-10-30；裁定见 `Verdict/01-悬浮球外壳-对话入口.md`，调研依据见 `research/01-悬浮球外壳-对话入口.md`）

### ① 应对什么问题

提问入口只有「切窗口」一条路，用户一动手就被打断：

- 桌面壳是**单窗口 + 托盘**，且窗口是 1280×820 的普通大窗 —— `front/desktop/app.py` 全文只有一次窗口创建（`:1402-1405`），托盘只提供菜单与气泡通知（`:752`、`:844-880`）；
- 全局热键**没有**（`app.py` 全文只有 `:807-808` 用 `ctypes` 设 AppUserModelID，无 `RegisterHotKey`、无键盘钩子）；
- 于是用户正在写代码、看文档、翻网页时想问一句，只能切到壳或浏览器，问完再切回来；
- 页面没开时，提醒也收不到：页面内推送走 WS（`api/digest_scheduler.py:22` 的 `_notify_ws`），只有托盘气泡能漏出来一点。

后果是「随手可用」这件事在当前形态下做不到：入口有，但要用户主动去找它。

### ② 功能

做完之后，用户桌面上多一个**常驻小球**：

- 球浮在其它窗口之上、可拖到任意角落、不抢当前窗口焦点；
- 单击球展开一个**对话小面板**，直接提问，答案就在球上滚动显示（复用现有 AI 助手同一套会话与流式事件）；
- 托盘可切换球的显示与隐藏；球的外观（尺寸、透明度、是否置顶、初始角落）在设置页里调，不写进 `.env`；
- 球是**纯入口**：不新增模型能力，提问走的仍是现有主 Agent 链路。

### ③ 实现功能的技术方案

#### 3.1 进程与窗口模型

桌面壳进程内三个实体，职责单一：

| 实体 | 载体 | 生命周期 |
|---|---|---|
| 主窗口 | pywebview（现状：1280×820，URL 带 `?desktop=1`） | 常驻；点 X 收进托盘（`front/desktop/app.py:54`、`:1450-1466`） |
| 悬浮球 | 纯 Win32 分层窗口，独立线程 + 自己的消息循环 | 设置项开启时创建；托盘「退出」时销毁 |
| 对话面板 | pywebview 窗口（无边框、置顶、启动时 `hidden=True`） | 首次点球时 `show()`；面板关闭只是 `hide()`，不 destroy |

三者同进程、同 webview profile（`data/desktop_webview`）→ 登录态共享（2026-10-30 实测：一窗写入 localStorage，另一窗读到同一值），**不需要任何令牌传递**。

#### 3.2 球窗规格（新增 `front/desktop/ball_window.py`）

| 项 | 做法 |
|---|---|
| 窗口样式 | `WS_POPUP` + `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST` |
| 尺寸 | 48 / 64 / 80 三档（设置项），默认 64；**创建后**用 `SetWindowPos` 定尺寸 —— 创建参数在 200% 缩放下不可信（实测传 68×68 实际得到 118×32，创建后改回 68×68 成功） |
| 绘制 | Pillow 读 `front/desktop/assets/ball_{idle,busy,alert}.png`（64×64、带 alpha、阴影烘焙进图），转 `HBITMAP` 后 `UpdateLayeredWindow` 贴图；状态切换 = 换图重贴 |
| 命中 | `WM_NCHITTEST`：落在圆内（半径 = 尺寸/2 − 1）返回 `HTCAPTION`（拖动交给系统）；圆外返回 `HTTRANSPARENT`（点击穿透到下层窗口） |
| 单击 | `WM_LBUTTONUP` 且位移 < 4px → 切换面板显示/隐藏 |
| 右键 | `WM_RBUTTONUP` → 上下文菜单（打开主窗口 / 隐藏悬浮球 / 退出） |
| 拖动 | 由 `HTCAPTION` 交给 DefWindowProc；拖动结束后把**球心逻辑坐标**写回 `data/ball_state.json` |
| 状态 | `idle` / `busy`（回答中，球面进度环）/ `alert`（有未读回答，红点）；由面板经 `pywebview.api.ball_state(state)` 回调，球线程内部用线程安全的 setter 更新 |
| 消息循环 | 线程内 `RegisterClassW` + `CreateWindowExW` + `GetMessageW/DispatchMessageW`；线程退出时 `DestroyWindow` 并注销类 |

#### 3.3 面板窗规格

| 项 | 做法 |
|---|---|
| 创建 | `webview.create_window(title, url, width=380, height=560, min_size=(320, 420), frameless=True, on_top=True, hidden=True, focus=False, easy_drag=True, js_api=DesktopApi())` |
| 加载地址 | `http://127.0.0.1:<port>/?desktop=1&ball=1&embed=1&_=<ts>`（现有 `/[?&]desktop=1/` 正则容忍附加参数，`front/index.html:5040`） |
| 展开落点 | 面板出现在球的**朝向屏幕内侧**一侧（球在左半屏→右侧展开，右半屏→左侧；上下同理），与球留 12px 间距；超出工作区则翻转到另一侧或夹紧；全部按逻辑坐标计算，夹紧算法是纯函数（便于单测） |
| 圆角与阴影 | `frameless` + CSS 圆角；Windows 11 可另用 `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE)` 让系统画圆角与阴影 |
| 关闭 | 面板右上角 × 与 `Esc` 都只 `hide()`，不 destroy（下次展开秒开） |
| 拖拽 | 面板顶部 40px 为拖拽条，元素加 `pywebview-drag-region` 类（pywebview 默认的拖拽选择器就是它，`webview/js/customize.js:92-94`） |

#### 3.4 前端紧凑模式（只改 `front/index.html`，三处）

1. setup 里加 `const IS_BALL = /[?&]ball=1/.test(location.search);`（与 `:5040` 的 `IS_DESKTOP` 同风格）；
2. 根节点挂类：`<div id="app" :class="{ 'ball-mode': IS_BALL }">`；
3. CSS 增 `.ball-mode` 段：隐藏 `.col-left` / `.col-right` / 顶部品牌区 / 页脚；中间列 100%；消息区间距微缩；输入框单行起、最多 4 行；顶部露出 40px 拖拽条（标题 + ×）。

**不改**：会话加载、`/api/chat`、SSE、`/` 选择、图片渲染、workflow 步骤卡 —— 全部原样复用。

#### 3.5 与主壳的集成（`front/desktop/app.py` 改动点）

| 行段 | 改动 |
|---|---|
| `:1384-1390` | 主窗 URL 不变；新增面板窗 URL（附加 `ball=1&embed=1`） |
| `:1402-1405` 之后 | 追加 `panel = webview.create_window(... hidden=True ...)` |
| `webview.start(...)` 之前（`:1506`） | 启动球线程 `BallWindow(on_click=..., on_menu=...)`；单例；起不来只打日志 |
| 托盘菜单 `:855-867` | 追加 `显示/隐藏悬浮球`（带勾选态）；球窗不参与「显示主窗口」 |
| `on_quit` `:1436` | 先 `ball.close()`（投递 `WM_CLOSE` + `Join` 1s），再退出 |
| `on_closing` `:1450-1466` | 不改（现状即收进托盘） |
| `DesktopApi` | 新增 `ball_state(state)`：页面把 idle/busy/alert 回传给球线程；新增 `ball_toggle()` 供页面快捷键调用 |

跨线程依据：pywebview 的 WinForms 后端对窗口操作做了线程编组（`winforms.py:489-500` 的 `load_url` / `hide` / `show` 都先 `self.Invoke(...)`），球线程可直接调用面板的 `show()/hide()/move()`。

#### 3.6 配置与持久化

- `utils/settings.py` 的 `SPECS` 增五项：`BALL_ENABLED`（switch，默认 0）、`BALL_SIZE`（select 48/64/80，默认 64）、`BALL_OPACITY`（number 60-100，默认 100）、`BALL_HOTKEY`（text，默认 `Ctrl+Alt+Space`）、`BALL_ON_TOP`（switch，默认 1）。都是开关/参数 → 落 `app_settings`，不进 `.env`，改完即生效。
- 几何落 `data/ball_state.json`（运行时数据，不入库）：`{"monitor": 0, "x": <逻辑>, "y": <逻辑>, "visible": true}`；只由球线程读写。
- 热键：球线程内 `RegisterHotKey(NULL, 1, MOD_CONTROL|MOD_ALT, VK_SPACE)`，`WM_HOTKEY` → 切换面板；注册失败（组合键被占）只记日志，托盘入口仍可用。

#### 3.7 降级路径

| 情况 | 行为 |
|---|---|
| 托盘不可用（缺 pystray） | 球仍可开；主窗点 X 直接退出（现有逻辑同样放行） |
| 球线程起不来 | 打日志、托盘不出现球项，主窗功能不受影响 |
| 面板页加载失败 | 面板内显示极简错误页 + 重试按钮，不阻塞球 |
| 后端未就绪时点球 | 面板显示既有 loading 页，就绪后再导航（与主窗同一套流程） |

#### 3.8 测试与验收判据

- **单元（`tests/unit/test_ball_geometry.py`）**：圆内/圆外命中判定、面板方位与夹紧算法、倍率换算、`ball_state.json` 读写 —— 纯函数，零窗口。
- **真机（`tests/live/desktop_ball_e2e.py`）**：起壳 → 断言存在对应类名的顶层窗口、`WS_EX_TOPMOST` 置位、尺寸等于设置值、圆外 `WM_NCHITTEST` 返回 `HTTRANSPARENT`、单击后面板可见。
- **客户端实测（人工）**：球浮于所有窗口之上；拖动后落点被记住；点开/收起顺畅；球里完成一轮问答并看到流式；关主窗（收托盘）后球仍在；托盘「退出」后无残留进程。

#### 3.9 明确不做（本期）

- 屏幕共享与屏幕控制（属 02 / 03）；
- 不同缩放比的多显示器落点校正（本期只保证主显示器与同缩放多屏）；
- 球上直接输入（球只是入口，输入在面板）；
- 皮肤/动画系统（只保留 idle / busy / alert 三态位图）；
- 改动「点 X 收进托盘」的现有语义。

## 02 悬浮球（屏幕共享）

> 状态：方案未敲定（调研中，见 `research/02-悬浮球-屏幕共享.md`）

### ① 应对什么问题

Agent 的「看」有边界，看不到用户自己的屏幕：

- 现有三条取信息的路是联网检索、进站抓取（browser-use）、账号资料与知识库，**没有一条能看本机屏幕**；
- 现有图片通路只接受用户手工上传/粘贴的图：`tools/chat_images.py`（magic bytes 校验 → 压缩 → 账号隔离落盘 → 本轮限定），`api/server.py:902-934` 是本轮贴图装配；
- 全仓无屏幕捕获代码：装机依赖里 mss / dxcam / pyautogui / pywinauto / opencv 均未安装（pywin32 312 已在）；
- 于是「屏幕上这个报错是什么意思」「这张表第三列怎么填」这类问题，用户只能打字描述，或手工截图存文件再上传，多步且易失真。

### ② 功能

做完之后，球上多一个**「看屏幕」**开关：

- 按下才截，不按不截，不做后台定时截屏；
- 截图进入现有图片链路（校验、压缩到既有上限、按账号隔离落盘、只喂本轮、历史只留引用），因此模型侧无需新通路；
- 默认截当前前台窗口或由用户框选，不默认整屏；
- 球上能把截图作为本轮提问的附图，与文字问题一起发出去。

## 03 悬浮球（屏幕控制）

> 状态：方案未敲定（调研中，见 `research/03-悬浮球-屏幕控制.md`）

### ① 应对什么问题

Agent 的手只伸到自己的沙箱，碰不到桌面上其它应用：

- 现在能改的只有两处：自己工作目录（内置写工具 create/edit/delete）与自配来源的写能力（CLI/API/MCP，凭「/」授权，`utils/write_auth.py` 的 selected ContextVar）；
- 全仓无输入注入代码：装机依赖里 pyautogui / pydirectinput / pywinauto / comtypes / uiautomation 均未安装；
- 用户的实际诉求（2026-10-30 原话）是「打开QQ,给xx发消息'xxx'」这类**跨应用操作**，以及把它上升为「模拟 window 用户操作电脑」。

### ② 功能

做完之后，球上多一个**「帮我操作」**能力（默认关闭，需显式授权）：

- 动作限于基础鼠标键盘：单击、双击、右键、滚轮、拖选、打字、组合键、粘贴；
- **每一步动作先给预览再确认**：先截一张图、把要点的落点框出来，用户点确认才真的动作；
- 消息类操作走 **draft 模式**：Agent 只负责打开应用、找到会话、把文字写进输入框，**发送由用户自己按**；
- 只允许在用户勾选的窗口范围内动作（白名单），动作全过程留审计记录。

## 二、个人库设计（SQLite 本地文件 · 泛用化 + JSON 扩展）

> 设计原则（采纳 M1 评审《改进建议》）：表结构收敛至绝对共性，业务特性托管至 JSON。
> 库路径：`data/personal.db`（可由 `PERSONAL_DB_PATH` 环境变量覆盖）。

### 2.1 表结构

**`accounts`** — 账号（本地个人使用）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | |
| username | TEXT UNIQUE | |
| password_hash | TEXT | |
| role | TEXT | personal / company |
| display_name | TEXT | |

**`products`** — 个人收藏商品（泛用化核心）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | |
| product_name | TEXT | |
| brand | TEXT | |
| category | TEXT | 品类：耳机/显卡/咖啡机... |
| price | REAL | 参考价 |
| currency | TEXT | 默认 CNY |
| attributes | TEXT | **JSON 结构化规格**，如 `{"battery":"30h","anc":"强"}`（耳机）或 `{"vram":"12GB","tdp":"200W"}`（显卡）|
| status | TEXT | active / discontinued |
| owner_id | INTEGER FK | |

**`interests`** — 兴趣领域（快讯用）| id | owner_id | interest_tag |
**`watchlist`** — 关注清单 | id | owner_id | brand | product | note |

### 2.2 样例数据（实体消费品类，验证泛用性）
- `accounts`：alice（耳机爱好者，personal）
- `products`：Sony WH-1000XM5 / Bose QC45 / AirPods Pro 2（耳机）、RTX 4070 / RTX 4090（显卡）——异质规格全部存入 `attributes` JSON
- `interests`：无线耳机 / 显卡 / 咖啡机
- `watchlist`：Sony/Bose/NVIDIA 各一条

> 验证点：耳机（battery/anc/weight）与显卡（vram/tdp/benchmark）字段完全不同，但共用同一 `products` 表 + JSON 列，证明泛用性成立——这正是 M1 评审中用户建议的核心价值落地。

## 三、个人侧子 Agent 提示词要点（prompts.yml `personal`）

- 任务类型 ①【性价比入手分析】：给定品类/预算 → 个人库 + 网络检索 → 参数对比表 + 最值得入手推荐
- 任务类型 ②【兴趣快讯】：给定兴趣领域 → 联网检索最新动态/评测/降价 → 快讯流
- 来源标注：个人库数据 🗄️个人库（注明表名 products/interests），公开信息 🔍网络
- 读取 JSON 规格指引：`json_extract(attributes,'$.battery')`
- 强制约束：只基于真实查询结果，不编造参数或价格

### 主 Agent 路由原则（新增）
- 公司视角（竞品/B端市场）→ 【数据库查询助手】+【网络搜索助手】
- 个人视角（选购/消费品性价比/兴趣快讯）→ 【个人情报助手】+【网络搜索助手】
- 两类数据互不混淆：公司=MySQL(our_products)，个人=SQLite(products)

## 四、实测验证

**测试问题（个人侧·性价比分析）**：我想买一副降噪耳机，预算2500以内，帮我对比一下我收藏里几款耳机的参数和价格，并结合网上评价给出最值得入手的推荐，标注来源。

**验证结果**：
- ✅ 主 Agent 正确路由到【个人情报助手】（未误调公司侧 MySQL）
- ✅ 个人库读取收藏的 Sony WH-1000XM5 / Bose QC45 / AirPods Pro 2 真实参数（价格/续航/重量/降噪）
- ✅ 联网检索公开评测与口碑（TechTeller/知乎/Reddit/消委会/B站）
- ✅ 交叉给出推荐：综合最优 Sony、iOS 生态 AirPods、降噪纯享 Bose
- ✅ 来源标注 🗄️个人库(products) + 🔍网络 正确
- ✅ 泛用性：JSON attributes 完美承载耳机异质规格

**结论**：M1.5 目标达成，个人侧「选购决策」能力可用，且与公司侧数据隔离、互不干扰。

# 文件存放规则（项目宪法·2026-09-29 立）

> **为什么有这份文件**：这些规则原本只在对话里定过、也进过助手记忆，但**记忆会随工作累积被简化稀释**
> —— 所以规则必须以**仓库内的文档**为准。**新增文件/目录前先读本文件**；本文件与别处冲突时以本文件为准。

## 〇、两条硬规矩

1. **前端代码及相关文件一律放 `front/`**，不得放到其它任何位置（`static` 这名字若将来觉得费解，可整体改名 `front`，但**只允许一个家**）。
2. **新建子文件夹必须先经用户同意**。新增文件放哪，先查本文件的判据（第三节）。

## 一、顶层：项目根只放「入口 + 包装 + 配置 + 声明」

| 该放 | 例子 |
|---|---|
| 程序入口 | `main.py` |
| CLI 包装脚本 | `dspro`、`dspro.cmd`（免激活 venv；PATH 加根目录即可直接调） |
| 依赖/环境/忽略配置 | `pyproject.toml`、`uv.lock`、`.python-version`、`.gitignore`、`.env`（`.env*` 不入库） |
| 声明类文档 | `README.md`（含**阅读指南**章节）、`IDEA.md` |

**不放**：测试脚本、调试脚本、预览/探针产物、临时提取文件（一律各归其位，见下）。

## 二、每个目录的职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `agent/` | **智能体核心**：模型接入、请求装配、上下文预算、会话持久化、思考捕获、周报引擎；`subagents/` 放子 Agent 装配 | 工具封装；**不许 `import api.*`**（依赖倒置） |
| `api/` | **FastAPI 服务层**：路由、鉴权、监控/WS、各业务 API 模块 | 业务算法本体 |
| `cli/` | **CLI 版（dspro）**：argparse 入口、各子命令、终端 UI、登录态 | — |
| `prompt/` | **提示词配置**（`prompts.yml`；主 Agent + 各子 Agent + 各撰写 AI 段） | 机械细节（只写工具文档串与注入块） |
| `tools/` | **agent 的硬编码内置工具开发**（与"用户自配工具"区别）——产出物**用于挂载 agent**：`@tool` 封装、能力池/路由、台账、记忆读写、个人库 Schema | 通用小工具（→ `utils/`） |
| `tools/_runtime/` | **内部实现**（能力执行层）：面板与 Agent 共用的执行器 | ⚠️ **外部不许直接 import** |
| `utils/` | **方便项目开发的小工具**：如文件路径辅助——封装一次，别处引用 + 一句代码即可与其它子文件关联 | 挂载给 agent 的工具 |
| `rag_knowledge/` | M3 RAG：向量库服务/存储/清洗/评估；`db/` 每用户 Chroma 落盘（**不入库**，含路由基准的临时库，**保留**） | 基准 JSON（→ `tests/fixtures/`） |
| `front/` | **前端一切**：`index.html`、`vendor/`、`tutorial/`（教程素材 + `previews/` 生成物）、`desktop/`（桌面壳） | 后端/工具代码 |
| `scripts/` | **开发/运维脚本**（非测试）：预览生成、CDP 探针、数据迁移 | 测试 |
| `tests/` | **测试与调试脚本**（结构见第四节） | 产物（→ `tests/test_out/`） |
| `docs/` | **里程碑文档**：`v1.0/ v2.0/ v2.5/ v3.0/` + `sql/` + `README.md` 索引；**备份**放 `docs/<版本>/backups/` | 代码 |
| `agents_docs/{账号}/` | 用户级智能体资料：`SOUL.md`、`MEMORY.md`、`ACTIVE_SOUL`、`SOUL/*.md` 人格库、`skills/*.md`（**不入库**） | — |
| `pic/{账号}/` | 用户上传的背景图（**不入库**） | 项目自带图（→ `front/`） |
| `output/{账号}/` | **agent（deep_search_pro 本体）的产物**：周报 md/pdf、导出文件、`tts/` 语音（**不入库**） | 测试产物 |
| `data/` | **运行时数据**：个人库 `personal.db`、`sandbox/`、`audit/`、`cli_docs_cache/`、`tts_ref/`、`tutorial_assets/`（教程图片运行时缓存）、`desktop_webview/`（**整体不入库**） | 测试产物 |

**版本目录规则**（既有约定）：整数版本目录 = 大改（调研/方案/计划全进整数目录，收官后补写的也算）；小数版本目录 = bug 与小优化（只放"问题-方案-结果"性质文件）。

## 三、判据速查（新文件放哪）

```text
是前端相关吗？                → front/（唯一家；教程素材 → front/tutorial/，机器生成的预览 → front/tutorial/previews/）
是给 agent 挂载的工具吗？      → tools/
是通用小工具/辅助吗？          → utils/
是智能体核心/装配吗？          → agent/（子 Agent → agent/subagents/）
是服务/API 吗？                → api/
是 CLI 吗？                    → cli/
是开发运维脚本（非测试）吗？    → scripts/
是测试或调试脚本吗？           → tests/<类>/（第四节）
是针对整个系统测试运行的产物吗？→ tests/test_out/（已 gitignore）
是某个 agent 跑出来的交付物吗？ → output/{账号}/
是运行时产生的数据吗？         → data/（已 gitignore）
是用户上传的图吗？             → pic/{账号}/
是文档/方案/记录吗？           → docs/<版本>/
是备份吗？                     → docs/<版本>/backups/
是提示词吗？                   → prompt/prompts.yml
```

## 四、`tests/` 结构（2026-09-29 按类重排）

```text
tests/
├── unit/         # ① pytest 单元 / 静态契约（秒级，无需服务）
├── harness/      # ② 前端抽取式 harness（Node，无需服务）
├── testclient/   # ③ TestClient 端到端（进程内，不占端口）
├── live/         # ④ 真机 / 外壳 / 真窗口（慢，注意额度）
├── debug/        # ⑤ 调试 / 临时（`_` 前缀可删）
├── fixtures/     # 基准与夹具（**不能放 data/**，会被 gitignore 丢掉）
└── test_out/     # 系统级测试产物（已 gitignore）
```

**判据**：
- **离线能跑** → `unit/` 或 `testclient/`；**要起服务/真调模型/真开窗口** → `live/`；
- **测试账号产出的数据按正常账号规则对待**（如 `output/m2tester/` 里的周报就是正常产物）；
- 只有**针对整个系统测试运行**的产物（探针日志、跑批结果、预览截图）才进 `tests/test_out/`。

## 五、不入库清单（`.gitignore` 口径）

`data/` · `agents_docs/` · `output/` · `pic/` · `rag_knowledge/db/` · `tests/test_out/` ·
`front/tutorial/previews/` · `front/desktop/*.log` · `*.db` `*.sqlite*` · `*.log` · `_tmp/` ·
`_chk.js` · `_resp.json` · `nul` · `*.pyc` / `__pycache__/` · `.venv/` · `.env*`

> 生成物（预览页、探针产物）**一律不入库**——要复现就跑生成脚本。

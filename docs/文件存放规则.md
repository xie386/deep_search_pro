# 文件存放规则（项目宪法·2026-09-29 立）

> **为什么有这份文件**：这些规则原本只在对话里定过、也进过助手记忆，但**记忆会随工作累积被简化稀释**
> —— 所以规则必须以**仓库内的文档**为准。**新增文件/目录前先读本文件**；本文件与别处冲突时以本文件为准。

## 〇、两条硬规矩

1. **前端代码及相关文件一律放 `front/`**，不得放到其它任何位置（`static` 这名字若将来觉得费解，可整体改名 `front`，但**只允许一个家**）。
2. **新建子文件夹必须先经用户同意**。新增文件放哪，先查本文件的判据（第三节）。

## 一、顶层：项目根只放「入口 + 包装 + 配置 + 声明」

| 该放 | 例子 |
|---|---|
| 程序入口 | `main.py` |
| CLI 包装脚本 | `dspro`、`dspro.cmd`（免激活 venv；PATH 加根目录即可直接调） |
| 依赖/环境/忽略配置 | `pyproject.toml`、`uv.lock`、`.python-version`、`.gitignore`、`.env`（`.env*` 不入库） |
| 声明类文档 | `README.md`（含**阅读指南**章节）、`IDEA.md` |
| **常青设计图**（★ 2026-10-14 批注） | `设计图-agent工作与工具调用体系.html`——**放项目根、随版本与路由变化持续维护**（单一现行版）；规格 `docs/v4.0/设计图规格-*.json` 与它互引 |

**不放**：测试脚本、调试脚本、预览/探针产物、临时提取文件（一律各归其位，见下）。

**临时提取文件判据**（2026-10-14 新增）：`*.tmp`、`_chk.js`、`_resp.json`、`nul` 一律**不许留在仓库树里**（用完即删；确需留存 → `tests/test_out/`，已 gitignore）。`.env.bak_<时间戳>` 属**改 `.env` 前的备份**，与 `.env*` 同样**不入库**。

> **原则（2026-10-14 批注）**：**`docs/` 是纯文档信息，不应被项目依赖**。项目运行或前端需要的东西（截图、模板、数据）都要在 `front/` 等处另存**副本**；`docs/` 里那份只作文档素材——可以乱、可以旧，删了不影响运行。

## 二、每个目录的职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `agent/` | **智能体核心**：模型接入、请求装配、上下文预算、会话持久化、思考捕获、周报引擎；`subagents/` 放子 Agent 装配 | 工具封装；**不许 `import api.*`**（依赖倒置） |
| `api/` | **FastAPI 服务层**：路由、鉴权、监控/WS、各业务 API 模块 | 业务算法本体 |
| `cli/` | **CLI 版（dspro）**：argparse 入口、各子命令、终端 UI、登录态 | — |
| `prompt/` | **提示词配置**（`prompts.yml`；主 Agent + 各子 Agent + 各撰写 AI 段） | 机械细节（只写工具文档串与注入块） |
| `tools/` | **agent 的硬编码内置工具开发**（与"用户自配工具"区别）——产出物**用于挂载 agent**：`@tool` 封装、能力池/路由、台账、记忆读写、个人库 Schema | 通用小工具（→ `utils/`） |
| `tools/_runtime/` | **内部实现**（能力执行层）：面板与 Agent 共用的执行器 | ⚠️ **除 `api/`（面板层）与 `agent/`（内置 Agent）外，不许直接 import**——2026-10-14 修正：原文写「外部不许」却又说「面板共用」，自相矛盾；现明确 **`api/` 就是面板层、允许 import** |
| `utils/` | **方便项目开发的小工具**：如文件路径辅助——封装一次，别处引用 + 一句代码即可与其它子文件关联。★ `utils/paths.py`（2026-10-13 立）是 **账号级用户数据路径的唯一事实源**，谁要用户数据路径都来问它 | 挂载给 agent 的工具 |
| `rag_knowledge/` | M3 RAG：向量库服务/存储/清洗/评估（★ 2026-10-13 起每用户 Chroma 落盘迁至 `user_data/rag_knowledge/db/`，不入库）；**基准临时库属测试产物，复核后即可清理**（2026-10-14 批注：已清 126 个） | 基准 JSON（→ `tests/fixtures/`） |
| `front/` | **前端一切**：`index.html`、`vendor/`、`tutorial/`（教程素材 + `previews/` 生成物）、`desktop/`（桌面壳） | 后端/工具代码 |
| `scripts/` | **开发/运维脚本**（非测试）：预览生成、CDP 探针、数据迁移 | 测试 |
| `tests/` | **测试与调试脚本**（结构见第四节） | 产物（→ `tests/test_out/`） |
| `docs/` | **里程碑文档**：① **老版本**（`v1.0/ v2.0/ v2.5/ v3.0/ v3.1/`）统一口径＝**存放各种文档、不再逐一维护**（乱属正常）；② **自 v4.0 起**按 [`版本文档规范.md`](版本文档规范.md) 四件套编排；`sql/`；`README.md` = **文档体系索引 + 全树导航** | 代码；被项目运行依赖的内容（见 §一 原则） |
| `docs/<版本>/backups/` | 改用户数据 / 文档前的**只读快照** | ⚠️ **留存期 = 该大版本 git 提交完成后即删除**（2026-10-14 批注）；**整体不入库** |
| `user_data/agents_docs/{账号}/` | 用户级智能体资料：`SOUL.md`、`MEMORY.md`、**`ACTIVE_SOUL`（人格生效源）**、`SOUL/*.md` 人格库、**`ACTIVE_VOICE`（音色生效源；`api/voice_tts.py` 在用）**、`skills/*.md`（**不入库**；2026-10-13 由根目录 `agents_docs/` 归口） | — |
| `user_data/pic/{账号}/` | `*.png` = 用户自设**背景图**；`chat_images/*.png` = **聊天中发出的图**（2026-10-13 由根目录 `pic/` 归口；HTTP 仍挂 `/pic`）。**空目录是合法状态，不得因「空」而删** | 项目自带图（→ `front/`） |
| `user_data/output/{账号}/` | **agent（deep_search_pro 本体）的产物**：周报 md/pdf、导出文件、测评打分表、`tts/` 语音（2026-10-13 由根目录 `output/` 归口） | 测试产物 |
| `data/` | **运行时数据**：个人库 `personal.db`（用户指定暂留此处）、`audit/`、`cli_docs_cache/`、`tutorial_assets/`、`desktop_webview/`（整体不入库） | 测试产物 |
| `user_data/` | **账号级用户数据的唯一归口**（2026-10-13 立，大点 04 · 议题一）：下辖 `agents_docs/` `output/` `pic/` `rag_knowledge/db/` `sandbox/` `probe_sets/` `tts_ref/`；路径一律由 `utils/paths.py` 提供；**整体不入库**（仅留 `.gitkeep`） | — |

> **人格生效源口径**（2026-10-14 新增）：以 **`ACTIVE_SOUL`** 为准，它**可指向两种形态**——`SOUL/<名>.md` 或**顶层 `SOUL.md`**，两者都合法。**没有被 `ACTIVE_SOUL` 指向的顶层 `SOUL.md` = 残留垃圾**（清理前先看 `ACTIVE_SOUL`）。`MEMORY.md` 同理为运行期记忆；漏登的生效源键一律**以代码实际读写为准补登**（本行即按此补 `ACTIVE_VOICE`）。

**版本目录规则**（既有约定）：整数版本目录 = 大改（调研/方案/计划全进整数目录，收官后补写的也算）；小数版本目录 = bug 与小优化（只放"问题-方案-结果"性质文件）。
**整数版目录的内部结构**（`规划文档` / `research/` / `Verdict/` / `Done/` 四件套 + 「裁决只进 Verdict、别的文档不写待裁决」的纪律）见 **`版本文档规范.md`**（2026-10-09 立）——本文件管顶层归属，那份管版本目录内部。

## 二末、目录留存与巡检（2026-10-14 新增：D5 巡检机制 + D9 机器生成目录口径）

**机器生成目录三类口径**：

| 类别 | 目录 | 口径 |
|---|---|---|
| **可删可重建** | `data/desktop_webview/`（浏览器 profile，实测 143.5 MB）· `front/tutorial/previews/` · `data/` 下各缓存 | 随时可删，下次用到自动重建；**巡检时可清**（删 desktop_webview 会让桌面壳退出登录态，动手前知会用户） |
| **必须留** | `user_data/**`（用户数据）· `user_data/rag_knowledge/db/`（向量库）· `tests/fixtures/`（基准与夹具） | 不许当「缓存」清掉；`user_data/` 动手前必须备份 |
| **临时** | `tests/test_out/` · `*.log` · `data/audit/`（按需轮转） | 用完即弃 |

**巡检（存量纠正）**——建议**每个大点收官时跑一遍**：

| # | 检查项 | 查到怎么办 |
|---|---|---|
| 1 | 仓库树里有无 `*.tmp` / `_chk.js` / 裸产物 | 删；需留存 → `tests/test_out/` |
| 2 | 有无遗留临时账号 / 孤儿验证码 | 按 §四 测试账号口径清理 |
| 3 | `docs/<版本>/backups/` 是否「应删未删」 | 该大版本已 git 提交 → 删 |
| 4 | 新增目录有没有登记进 §二 | 未登记 → 补登记（或按 §〇 先问用户） |
| 5 | 有无本机化绝对路径混进代码默认值 | 改成必填提示（口径见 `research/04` §4.2 E4） |
| 6 | 第一类大目录占用是否异常 | 异常 → 清（知会用户） |

发现即纠正，纠正记进 §六 变更记录。

## 四、`tests/` 结构（2026-09-29 按类重排）

```text
tests/
├── unit/         # ① pytest 单元 / 静态契约（秒级，无需服务）
├── harness/      # ② 前端抽取式 harness（Node，无需服务）
├── testclient/   # ③ TestClient 端到端（进程内，不占端口）
├── live/         # ④ 真机 / 外壳 / 真窗口（慢，注意额度）
├── debug/        # ⑤ 调试 / 临时（`_` 前缀可删）
├── fixtures/     # 基准与夹具（**不能放 data/**，会被 gitignore 丢掉）
└── test_out/     # 系统级测试产物（已 gitignore）
```

**判据**：
- **离线能跑** → `unit/` 或 `testclient/`；**要起服务/真调模型/真开窗口** → `live/`；
- 测试账号产出的数据按正常账号规则对待（如 `user_data/output/<测试账号>/` 里的周报就是正常产物）；
- 只有**针对整个系统测试运行**的产物（探针日志、跑批结果、预览截图）才进 `tests/test_out/`。

**测试账号与测试数据口径**（2026-10-14 新增，D6）：

- **命名**：临时账号一律 `t_` + 用途 + 时间戳（如 `t_cli_1014002855`）；**非 `t_` 前缀的账号一律视为真实账号**，只读对待。
- **留存期**：跑完**立即自清**（显式 purge + `atexit` 双保险）；异常退出留下的，靠 §二末 巡检第 2 项扫出来。
- **硬约束（红线）**：**单测 / 探针不得向真实库建号、不得向实时目录写文件**。要账号就跑临时账号；要落盘就落 `tests/test_out/` 或 `tempfile`。**改真实库配置的测试必须「快照 + 只回滚本次改动」**（不许整表删）。
  - 依据：2026-10-13 前置清理实测 5 处脚本向真实库 / 实时目录写入（根因见 `research/04` §3.6）；2026-10-14 收官期又抓到 3 处（单测假设库空、e2e 漏回收临时账号、客户端测试收尾整表删设置）。
- **单测的库隔离**：优先整套指向临时库；做不到时按文件 `monkeypatch`（现状：`test_settings_store.py` 等 4 个文件已按文件隔离）。

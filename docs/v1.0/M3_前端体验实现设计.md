## 二、关键设计

### 2.1 简报卡片分块（前端）
- `splitSections()` 用正则匹配 ①②③④⑤ 序号或 Markdown 标题作为切分点，把 agent 的长回答切成多个 section；无标记则整体一个「内容」块。
- 每块独立渲染：来源标记 🔍网络/🗄️数据库(个人库)/📚知识库 高亮着色；Markdown 表格转 HTML `<table>`（跳过 `|---|` 分隔行）。
- 卡片头部显示从用户问题截取的标题，附导出按钮。

### 2.2 导出链路（后端）
```
前端 POST /api/export {content: markdown}
  → 写 output/{username}/{safe_title}_{ts}.md
  → convert_md_to_pdf_via_word()   # md → html → Word COM → pdf
  → 返回 download_md / download_pdf 链接（token+name）
前端 location.href = download_pdf 触发浏览器下载
```
- 文件按用户目录隔离；`/api/download` 只接受纯文件名（拒绝 `/` `\` `..`）且解析后必须位于本用户 output 目录内。
- 中文文件名：前端/测试脚本对 query 做 URL 编码后请求正常。

## 三、踩坑记录

1. **word_converter 静默吞依赖缺失**：顶部 `try: import markdown ... except ImportError: pass` 导致未装包时直到调用才抛 `NameError: name 'markdown' is not defined`，且错误信息不指向缺依赖。修复=装包；建议后续把 except 分支改成显式日志。
2. **服务进程缓存旧 import 状态**：装完 markdown 后仍报同样错——因为 uvicorn 进程在装包前启动，模块级 try-import 已失败缓存。**重启服务解决**。
3. **URL 中文参数**：测试脚本最初直接拼接中文 title 到 query，urllib 抛 UnicodeEncodeError；统一改用 `urlencode`。
4. （继承自写文件工具的教训）大 HTML 文件整写时曾混入损坏标签，靠逐行 div 配对追踪定位修复——最终校验 `<div>` 40/40 配对、深度归零。

## 二、各里程碑细化

### M1（✅ 已完成）
- **目标**：改造 `prompts.yml`（公司侧人设 + 来源标注规范 + 简报结构）；设计 `our_products` / `our_sales` / `competitors` 三表并造样例；CLI 产出带来源标注的竞品简报。
- **关键修复**：`db_tools.py` 强制 `use_pure=True` 解决 Windows 下 mysql-connector C 扩展连接报错（`Failed raising error`）。
- **验收**：提问「对比我们与飞书/钉钉定价功能差异」→ 调度网搜 + DB，输出 ①摘要 ②动态 ③对比 ④风险机会 ⑤来源清单，每条带来源标记。

### M1.5（✅ 已完成）
- **目标**：个人侧本地库（SQLite）+ 个人子 Agent + 主 Agent 按「公司/个人视角」路由；性价比分析实测。
- **设计原则**：表结构收敛至共性，`attributes` 用 JSON 列承载异质规格（耳机 vs 显卡字段完全不同却共用一表）。
- **验收**：提问「预算 2500 内降噪耳机对比」→ 路由个人库 + 网搜，交叉给出推荐与来源。

### M2（✅ 已完成）
- **目标**：把 CLI 能力搬上 Web。
- **范围**：
  - `api/server.py`：FastAPI 应用 + WebSocket 路由，绑定 `monitor.ConnectionManager`（startup 时 `manager.set_loop`，`set_loop`/`send_to_thread` 已就绪），REST 登录/注册/登出、`/api/chat` 用 `asyncio.to_thread` 跑同步 agent、静态 SPA 托管；
  - `api/account.py`：复用个人库 `accounts` 表（`IF NOT EXISTS`，不破坏 M1.5 样例）做登录鉴权与角色分流（company / personal），token 进程内字典；
  - `front/index.html` + `front/vendor/vue.global.prod.js`：Vue3 免构建 SPA，登录页 + 公司/个人双工作台，右栏 WebSocket 实时滚动工具调用进度。
- **验收**：① 登录/注册/角色分流可用；② `POST /api/chat` 返回带来源标注的竞品简报（200）；③ 前端连 `ws/{thread_id}` 实时收到 `monitor_event`（tool_start 等）工具调用进度；④ 对话能力等价于 CLI 版。
- **踩坑**：Hermes 全局 venv 同名 `agent` 包遮蔽项目包（server.py 顶部加项目根 insert+剔除 hermes 路径）；本地 127.0.0.1 被 HTTP_PROXY 拦截（仅测试脚本需豁免）。
- 详见 `docs/M2_Web服务与鉴权实现设计.md`。

## 三、范围决议（已拍板，2026-08）

> 以下为产品开发中的方向性拍板，后续不反复讨论，除非用户推翻。

1. **网络搜索多轮检索：保持现状，不限制单轮次数。**
   原 system_prompt 写「单轮最多 5 次检索」但代码未兜底，实测一次任务可调 60+ 次。用户判断：多轮检索能获取更详细信息、降低模型幻觉，**暂不修改**；若后续 Tavily 额度吃紧再评估。
2. **MCP 工具：仅作为价格数值参考，不替换 / 大改原有 Tavily 搜索。**
   MCP（如电商价格源）定位为「数值交叉校验」，原有网络搜索子 Agent 的工作流与提示词基本不动；属增强项，优先级低于 M2 / M3。
3. **用户画像：暂缓。**
   原 P5（个人历史分析沉淀 / 用户画像）暂挂起，用户将重新构思方案，确定后再排期（预计归入 M4 或独立里程碑）。

## 四、开发顺序原则

- 严格按 **M1 → M1.5 → M2 → M3 → M4** 推进；M4 为二期，可在 M3 稳定后再启动。
- 每个里程碑结束：补 `docs/M{n}_*实现设计.md`（改动清单 + 数据库设计 + 踩坑 + 实测验证）。
- 改造不回退已验证成果：公司侧表结构与 SQL 习惯不动；泛用化只在个人侧落地（C 折中方案已定）。

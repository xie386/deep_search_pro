## 三、成本最低方案：实测结论（2026-10-18）

> 实验方式：`browser_venv` 里**直接起 `Browser`**（不经过 LLM、零额度），与项目相同的 profile/env（`BROWSER_USE_CONFIG_DIR`、`--no-sandbox`、`--disable-gpu`、`NO_PROXY`）；用一个本地 HTTP 服务返回 `Content-Disposition: attachment; filename="probe.png"` 的图片，导航过去即触发下载。

| 配置 | 结果 |
|---|---|
| `accept_downloads=False` + **显式** `downloads_path` | **落盘** `probe.png`（70 字节） |
| `accept_downloads=True` + 显式 `downloads_path` | 落盘 |
| `accept_downloads=True` + 不显式 | 同样落盘，落在默认 `%TEMP%/browser-use-downloads-<id>` |

**关键源码**：

- 下载行为由 watchdog 用 CDP `Browser.setDownloadBehavior`（含 `downloadPath`）设置 —— `browser_use/browser/watchdogs/downloads_watchdog.py:501-510`；
- 未显式给 `downloads_path` 时，库自动生成 `<系统临时目录>/browser-use-downloads-<唯一 id>` —— `browser_use/browser/profile.py:475-490`；
- `accept_downloads` 在 0.13.11 里只有定义与透传，watchdog 里仅一处 TODO 提到它 —— 它**不是**下载的总开关。

**结论**：用户提出的"显式给 `downloads_path`"成立，成本最低。缺的只是**落点**（要在账号工作目录内）、**回执**（要把下载清单回给模型）、**清理**（空目录不留）。因此 07 降级为三处小改，方案见规划文档 §07 ③。

**顺带发现的两处残留**：`tmp/` 下有 138 个 `browser-use-downloads-*` 空目录（本轮已清）、73 个非空的 `browser-use-user-data-dir-*`（每轮浏览器运行的临时 profile 未清，待确认后再处理）、7 个 `.tmp` 文件。

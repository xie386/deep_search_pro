## 一、身世（为什么提出来）

06 收尾后，用户提出一个具体判据式的追问：**`use_browser` 既然能让 Agent 在网站里点击，那点"下载"按钮是否真的把文件下到了本地？** 若确实能、且落点可用，则"资源嗅探与抓取"没有必要；若不是，才立本大点。

## 二、已知线索（占位期只读取证）

| 事实 | 证据 |
|---|---|
| 浏览器侧**下载被硬关**：`BrowserProfile.accept_downloads=False` | `scripts/browser_runner.py:146`（旁边注释写明：Chrome 因受限令牌必须带 `--no-sandbox`，故关下载） |
| **点击动作是允许的**，被排除的只有 `search / write_file / read_file / replace_file / upload_file` | `scripts/browser_runner.py:48` |
| 即使打开下载，库默认落盘目录是**系统临时目录**下的独立子目录，与账号工作目录无关 | `browser_venv/Lib/site-packages/browser_use/browser/profile.py:475-490` |
| 浏览器临时 profile 在 `finally` 里整体删除 | `scripts/browser_runner.py:139-141` |
| 目前唯一能把远程文件弄到本地的路是 `run_shell_command` 里的 `curl`（AI干货周报用它取 HN 数据），但要求 URL 已知、无站点会话、不执行 JS | `tools/_runtime/shell_runtime.py` 的 `ALLOWED_COMMANDS` |
| 06 已具备的收口：工具返回的图片字节或图片地址 → `<工作目录>/_tool_images/` + 前端渲染 | `tools/capability_invoke.py`、`front/index.html` |

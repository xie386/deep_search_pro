## 二、三类结构性缺陷（本文的核心发现）

### 2.1 目标不可达：`precision@3 ≥ 0.7` 在本题库上恒不成立

指标实现（`tests/live/m5c_router_bench.py`）：每题 `p = |top3 ∩ 可接受| / max(1, min(3, |top3|))`，而 `top3 = decide()["order"][:3]` **恒为 3 条** → 单题上限 = `min(|可接受|, 3) / 3`。

题库事实（`tests/fixtures/router_bench.json`，30 题）——`|可接受|` 分布：

| `|可接受|` | 题数 | 单题 `p` 上限 | 题号 |
|---|---|---|---|
| 1 | 13（改判后 12） | **1/3** | city-basic · city-climate · city-en · train-stations · train-date · douyin-hot · ip-lookup · steam-detail · weread · bili · wechat · pdd-search · trip-route |
| 2 | 8 | 2/3 | train-code · train-city-code · steam-price · bnf-report · pdd-deals · trip-mixed · trip-transfer · compare-price |
| 3 | 1 | 1.0 | trip-tickets |
| 4 | 2 | 1.0 | bnf-subject · trip-main |

⇒ 结构上限 = `(13×1 + 8×2 + 1×3 + 2×3) / (3 × 24) = 38/72 = 0.528`（改判 `city-climate` 后 `37/69 = 0.536`）。
**0.528（0.536）< 0.7** → 这条线**任何路由器都过不了**。它作为立项触发条件是**恒真**的：不是「发现了问题」，而是「只要去看就一定有问题」。

**推广教训**：给任何指标定「绝对值目标」之前，先算它的**可达上限**（= 答案键粒度 × 指标分母口径的函数）。本次的修法就是让脚本**自算并打印**上限（`precision@3_ceiling`），以后改题库它会自动跟着变，不会再漂。

### 2.2 指标把「正确行为」算进坏账：灰区比例

`gray_ratio = 灰区题数 / 30`。噪声题（**本就不该路由**）回退全量是**正确行为**，却被计入灰区——题库 7 道噪声题实测全部正确回退（改判后 7 道），于是灰区**天然 ≥ 7/30 = 0.233**，`≤ 0.3` 这条软判据只剩 0.067 余量给「真正没把握」的题。读数 0.267 看起来像「26.7% 的路由失败」，其实是「6 道噪声正确回退 + 2 道真没把握」。

**修法**：灰区**分两栏** —— `gray_ratio`（全题，含正确回退，保留兼容）+ `gray_ratio_nonnoise`（非噪声题里的灰区，才是真信号）。这也是「每个指标都要问一句：**分母里有没有本来就该这样算的样本**」这条通用检查的来源。

### 2.3 答案键与工具能力不符：唯一未命中题

`city-climate`（「广州夏天热不热，回南天是什么意思」）期望 `mcp:city/search_city`，而该工具的工具级描述写明只返回**标准地名 / 所属国家与一级行政区 / 经纬度 / 人口 / 地点类型** —— 它**答不了气候问题**。

两个后果：
- 把它记成「未命中」，等于**拿一个错的期望去扣路由的分**；
- 它掩盖了真实信息：这道题实际是**被自信路由到了错的工具**（z = 3.22，超过当时候的 `Z_STRONG = 2.4`）——「自信选错」才是可治理的那一类问题。

**口径先例**（同类修订已有两例）：`router_bench_regressions.json` 里 `trip-mixed` / `trip-transfer` 的期望在 2026-10-06 已由用户裁定按「正确期望」修订（`expect_revision` 字段留痕）。

**被否掉的修法**：给 `city/search_city` 的素材补「气候/回南天/热不热」这类关键词，好让它被捞回来 —— 那是**为指标过拟合**，而且会把「池里根本没有这个能力」这个真信息埋掉。按项目判据（「先证明工具本身有没有那个能力，没有就不是 agent 的锅」），正确做法是**改判类别**。

## 三、试过与被否掉的路线（留档，别再走一遍）

| # | 路线 | 结果 |
|---|---|---|
| 1 | 直接把 `precision@3 ≥ 0.7` 下调到 0.55（贴近上限） | ✗ 治标：任何一个「看起来勉强够」的数都会被下一个人再下调一次；正解是把它降级为「仅参考」并补一个可达的主力信号 |
| 2 | 把 precision@3 的定义改成 `|top3 ∩ 可接受| / min(3, |可接受|)`（即现有 recall@3 的口径） | ✗ 那会让「乱塞 2 个无关工具」拿满分，正是 precision 要抓的东西；定义不改，改的是「别拿它当闸门」 |
| 3 | 为 `city-climate` 补素材关键词让它被捞回 | ✗ 为指标过拟合（见 2.3） |
| 4 | 把 Jev 的介入范围从灰区扩到全部题（这样 precision@3 上限 0.528 就够得着 0.503 的验收线） | ✗ 与预研 §3.5「不替换词法/向量两条免费快路」直接冲突；且质量指标已经在 1.0，扩大付费面没有收益 |
| 5 | 只改题库、不动指标（把 13 道单可接受的题补成多可接受） | ✗ 那是在**改答案键去迁就指标**，方向反了；答案键只能按「工具真实能力」改（本次只改了 1 道，且是改判类别不是放宽期望） |
| 6 | 灰区比例直接删掉（既然它含正确回退） | ✗ 它仍有信息（注入量、成本）；正解是分栏，不是删 |

## 六、本批（素材层第三批，同日）的调研发现

### 6.1 「把城市名写进素材」是怎么把 top1 抢走的

`precision@1` 的 6 个失分点里 4 道的 top1 都是 `mcp:12306-mcp/get-station-code-of-citys`，而它的素材当时长这样：

```
name 城市换代表站码
keywords 城市换站码/成都的站码/城市代表车站
ab_user 城市 → 代表站码（如 成都 → CDW、广州 → GZQ）。
```

「成都 / 广州」是出行类问句里的**高频实体**。把具体城市名写进 keywords 与 `abilities_user`，等于把「这枚站码」与「所有提到成都/广州的问句」在向量空间里绑在一起 —— 于是「规划成都→广州的驾车路线」「成都东站的车站代码」「广州有哪些火车站」的第一名都成了它。这与预研 §8.1 根因二（「短而泛的条目吸引向量」）是同一族的另一种表现：**这次不是条目短，而是条目里塞了跨意图的高频实体**。

纪律落点：`../../v3.1/工具接入规范-素材层与工具服务.md` §三 第 1 条（领域锚定）与第 3 条（避开通用词）——「通用」不只指「今天/排序」这类虚词，**具体地名/商品名只要跨意图高频，也一样通用**。修法是**改用中性槽位写法**（「某东站、某南站」）并把**替代路径**写出来（同类工具的互相指向）。

### 6.2 素材改动会推动整池的 z 分布（不是局部效应）

删掉城市名示例后，`city-climate`（噪声题，期望「不路由」）的 z 从 3.22 涨到 3.59（冻结池）/ 3.62（真机池），越过原阈值 3.3 → 噪声假阳性从 0.000 回到 0.143。机制：z 是**相对量**（top1 相对全池均值/标准差），池内任一文本变化都会改变均值与标准差。

**推论（本批最重要的教训）**：素材批与阈值**必须同批验证**。只改素材看素材、只改阈值看阈值，都会得出「另一头坏了」的结论。

### 6.3 两个口径的平台区不一样（冻结池够 ≠ 真机够）

| 池 | 全绿的最小阈值 | 平台区 |
|---|---|---|
| 冻结池 28 条 | 3.4 | 3.4 ~ 4.0（5 个值完全一致） |
| 真机池 29 条 | **3.62** | 3.62 ~ 4.2（6 个值完全一致） |

差 0.22 的来源是**池子多了 1 条**（`agently-cli`）→ 均值/标准差随之变化。取 3.8 = 两池都在平台内、离真机边界留 ~0.18 余量。

### 6.4 本批试过并否掉的路线

| # | 路线 | 结果 |
|---|---|---|
| 1 | 首稿把 `get-tickets` 的城市名示例也一起删（看着「同类」） | ✗ 直接打断 `trip-mixed` 的命中链（`hit@3` 1.000 → 0.957）。**每改一条都要单独看它负责哪些题** |
| 2 | 为 `pdd-search`（「拼多多上磁吸手机壳怎么样」）补一条能字面命中的关键词 | ✗ 属于为测试题堆关键词（过拟合）；本批照纪律改写两条的区分语义后，该题**仍是失分点**，如实保留（不入为凑数） |
| 3 | 把站码三条合并成一条能力卡 | ✗ 工具是 MCP 服务的三个真函数，卡片不能合并；只能靠素材互相区分 |
| 4 | 只改阈值不改素材（p@1 停在 0.739） | ✗ 阈值治不了「top1 排错」——它只决定「路由 or 回退」，排序由文本相似度决定 |

## 五、前置知识：什么叫「决策模型」

### 5.1 一句话
2026 年 9 月下旬集中上线的一类模型：**不生成文本**；你给它 `state`（应用状态/上下文）和**类型化问题**，它**一次前向**返回每个选项的概率；输出 token 免费，代码自己决定拿这些概率干什么。

### 5.2 三种问题原语（本机实测的响应形状，逐字）

| 原语 | 问法 | 返回 |
|---|---|---|
| `noul` | 「是否/要不要」 | `{"type":"noul","noul":0.0203…}` = P(true) |
| `choice` | 「从这些选项里选一个」 | `{"type":"choice","choice":"__none__","probabilities":{选项:概率},"confidence":0.9949}` |
| `score` | 「按有序尺度打分」 | `{"type":"score","score":1.749,"legend":{0:"没把握",…3:"非常有把握"},"probabilities":{等级:概率},"confidence":0}` |

### 5.3 API 契约（实测反推，比文档可靠）
```
POST https://openrouter.ai/api/alpha/decisions
Authorization: Bearer $OPENROUTER_API_KEY
{"model":"<决策模型>",
 "state": <字符串 或 JSON 对象>,                 // 上限约 32k tokens
 "questions": { // 必须是**对象**，不是数组
   "<问题名>": {"type":"noul|choice|score",
                "instructions":"<判据的自然语言>",
                "criteria": {...}}}}              // noul: {"true":..,"false":..}
                                                  // choice: {选项键: "何时选它"}（选项键=模型要回的值）
```
**实测踩坑（记下来省下次时间）**：`questions` 写成数组 → 400；用 `options`/`choices` 代替 `criteria` → 400；选项写成 `{id,label}` 对象 → 400。**API 的 400 会给到字段路径**，照它改最快。

### 5.4 OpenRouter 决策模型全表（2026-10-12 本机拉取 `?output_modalities=decisions`，19 条）
`microsoft/microsoft-decision-1` · `nace-ai/drex-v1.5` · `cloudflare/clef-omni` · `cloudflare/clef` · `cloudflare/clef-flash` · `upstage/solar-decide` · `upstage/solar-decide-flash` · `perplexity/pplx-decider-v1.1-27b` · `openai/gpt-6-luna-decisions` · `liquid/d1` · `togethercomputer/tev1-4b-experimental` · `inception/mercury-decide` · **`inception/mercury-decide:free`（免费；本次调研用它）** · `respan/span-01` · `respan/span-01-lite` · **`respan/span-01-lite:free`（免费）** · `jaredpalmer/kev-4b` · `~typesafe/jev-latest` · **`typesafe/jev-1.13`（与本项目大点同名）**

- 输入价 **$0.02–$0.24 / M tokens**；**输出一律 $0**；ctx 8k–1.05M 不等。
- 外部资料要点（出处见 §十四）：四家厂商 9 月下旬集中上线；**`JevBench v1.4`** 是这类模型的自评榜；Cloudflare 的 Clef 系列 Apache-2.0 开源权重、Amazon Strands Decider 2B 也开源；OpenAI 走 Luna + Decisions API；行业文章的核心告诫是「**要不要用它替代现在被拿来当 judge 的通用 LLM，得先用有标注的留出集自己测**」本轮正是照这条做的。

## 七、方案 A（二值仲裁：路由结果 →「够用 / 打回重选」）

**你的原话**：「1. 根据路由返回选择出来的工具回答是——本轮使用这些工具，还是否——打回重选择；前者的问题是：如果打回重选，要怎么保证重选不会再选错或者甚至重选后与打回前完全相同的选择？」

### 7.1 实测（D2：项目 `router_bench_regressions.json` 的 5 例**已知路由错误**用例 + 2 道跨工具题）

| 用例 | 候选数 | P(够用) | 同 state 重复两次 | 判定 |
|---|---|---|---|---|
| `city-en` | 3 | 0.0124 | 0.01243 / 0.01243 | 一致 |
| `bnf-subject` | 3 | 0.0059 | 0.00591 / 0.00591 | **逐字相同** |
| `bnf-report` | 3 | 0.0159 | 0.0180 / 0.0180 | 一致 |
| `trip-mixed` | 3 | 0.0036 | 0.0032 / 0.0032 | 一致 |
| `trip-main` | 8 | 0.0013 | 0.0013 / 0.0021 | 同向 |
| `trip-tickets` | 8 | 0.0012 | 0.0012 / 0.0009 | 同向 |
| `trip-route` | 8 | 0.0006 | 0.0008 / 0.0007 | 同向 |

- **「该打回」的识别率 = 7/7**（这些用例本来就该打回）→ 「够不够」这一问，模型**非常准**
- **同 state 重复：结论不变**（差 1e-9 ~ 2×，方向一致） → **盲目打回 = 白跑一趟**（疑虑①**实证成立**）

### 7.2 打回时「换喂法」是否改变结果（同一用例）

| 变体 | P(够用) | 解释 |
|---|---|---|
| ① 原样重问 | 0.0124 | **毫无变化**（= 疑虑①） |
| ② 加「上次判你不合格，重新判」 | 0.0097 | 几乎不变（加了情绪、**没加信息**） |
| ③ **换成完整池（28 条）** | **0.9890** | **翻转**（state 里出现了正解） |
| ④ 加「候选里可能没有正确答案」 | 0.0036 | 同向（更保守）不是解 |
| ⑤ 换模型 `typesafe/jev-1.13` | **HTTP 402** | 无 credits |
| ⑥ 换付费路由 | **HTTP 402** | 同上 |

### 7.3 判决与解法
**判决**：方案 A 可行，但**「打回」必须定义成「换状态」而不是「重问」** —— 决策模型对同一 state 是（近似）确定函数。

**解法清单**（按性价比）：
1. **打回 = 升级/降级检索**：候选从「top3」换成「全池」或「放宽阈值后的 top20」（实测 0.012 → 0.989）—— 方案 A 唯一有效的形态；
2. **打回 = 换来源/换路径**：词法 → 向量 → 全量；或换模型（需额度）；
3. **打回 = 带「缺什么」的结构化输入**：把第一次的 `choice` 概率分布当「疑点」喂进第二轮（未验证的新想法 待做）；
4. **别做「情绪式重问」**（②④ 实测无效）。

## 八、方案 B（把工具信息灌给决策模型，让它选本轮用什么）

**你的原话**：「2. 把工具的信息灌输给决策模型，让它来选择 Agent 本轮工作要做什么；后者的问题是：这几乎会占用掉原先工具选择路由的向量模型和重排模型的工作生态位，可能面临大面积工具路由重构？」

### 8.1 实测（D1：30 题 × 28 条池，全池卡片注入，含 `__none__`「不用工具」）

| 指标 | 决策模型直选 | 项目冻结池基线 |
|---|---|---|
| `precision@1` | **0.9333** | 0.478 |
| `precision@1`（非噪声 23 题） | **0.9130** | — |
| `hit@3` | **1.000** | 0.783 |
| `recall@3`（非噪声） | 0.8768 | 0.659 |
| 噪声假阳性（7 题） | 0.000 | 0.000 |
| 注入字符 / 题 | 6730（全池） | 平均 4474（收窄）· 11647（全量） |
| 延迟 / 次 | **1.75 s** | 词法+向量快路 ≈ ms |
| 输入 tokens / 次 | **4507** | 0（本地 embedding） |

### 8.2 它错在哪（比「错多少」更重要）
- **唯一真错**：`compare-price`（「拼多多和 Steam 上**同一款游戏**哪个便宜」）→ 选了 **`__none__`**（判「不用工具」）。
- **另一例**：`trip-tickets`（「成都东到广州南明天还有没有票」）→ 选了 `get-current-date`（**合理的链条第一步**，但不在 `expect` 里）。
- **规律**：需要**组合两个来源 / 多步链条**时，单选 `choice` 会退化成「选中间步骤」或「干脆不选」 → **瓶颈是「单选」，不是「能力」**。

### 8.3 判决与边界
**判决**：在 **≤30 条池子**上方案 B **质量显著更好**（0.478 → 0.933）→ 你的疑虑「会占掉向量+重排生态位」**部分成立**；但**不能据此就替换**，三条硬边界：

1. **池子规模**：全池 28 条 = 6730 字符；若池 200 条 ≈ 45k 字符（ctx/成本线性膨胀）→ **大池必须先召回再决策**（§九·C）；
2. **延迟**：**+1.75 s/次，且每题都付**（快路是本地毫秒级）→ 交互体验的账要单独算；
3. **可用性**：免费路由仅 2 条、付费当前 402 → 现在是「demo 可用、生产不可用」（§十一）。
→ **建议形态：不替换，做「第二意见 / 难例通道」**：免费快路先跑，只在**灰区/低置信**时请决策模型；对小池账号也可直接「全池注入 + 决策」（它比灰区回退**更省**：11647 → 6730 字符，且更准）。

## 九、我方补充的方案（C/D/E/F/G）

### C. 两段式：召回 → 决策精排（最像「正统」用法）
- 实测 D3：把**已知路由错误的 5 例**的 top3（**补进正解**以测「纯精排上限」）交给决策模型 → **3/5 选对**（`city-en` `bnf-subject` `bnf-report`）；失败 2 例**都是多步链题**。
- **洞察（可落地）**：**选项粒度**决定成败 —— 选项写「工具 ref」时链题会选错；选项若写「**这一步该做什么动作**」或改多标签才对得上。
- 附加收益：精排只需 **top-k（k≤8）** 进 state → 注入 ≈1–2k 字符 → 比全池更低、**可扩展到几百条池**（把决策模型用在生产尺度上的正解）。

### D. 多标签/多选（直接回应「决策模型擅长多选」）
- 做法：对池里每个工具各问一个 `noul`「本轮要不要用它？」→ 得到**工具集合**（一次请求多问题 官方支持并行）。
- 为什么：D1 唯一真错 + D3 两例失败 **全部**是「需要组合」的题 → 多标签正对这个失效模式。
- 代价：需要「选几个」的闸门（阈值/预算/上限）。

### E. `needs_tool` 替代/补充阈值（治「噪声被自信路由」与灰区稳定性）

| 阈值 | 噪声被误判「需要工具」 | 非噪声被漏判「不需要」 |
|---|---|---|
| ≥0.1 | 1/7 | 1/23 |
| ≥0.2 ~ 0.5 | **1/7** | **2/23** |
| ≥0.7 | 1/7 | 5/23 |
| ≥0.9 | 1/7 | 9/23 |

- 那 1 例误判 = **`noise-weather`**（「成都今天天气怎么样」P=0.9985）—— **语义上它确实「需要工具」**，只是池里没有天气工具、被题库归为「噪声」→ **题库标签 vs 语义真值的冲突**（§十三·Q4）。
- 漏判 2 例：`bnf-report`（P=0.18，像写作实为工具题）· `city-en`（P=0.03）。
- **判决**：能把「要不要用工具」变成**显式判定**（替代「z 阈值 + 全量回退」这套靠阈值的机制），代价是假阳性 0.000 → ~0.143（但那 1 例本身可疑）；顺带**治住「阈值随素材漂移需重标定」**这个长期痛点。

### F. 级联 + 决策缓存 + 预算闸门（工程化）
- 级联：免费快路 →（灰区/低置信）→ 决策模型 →（仍不决）→ 全量注入（预研「只在灰区付费」的精神）。
- 缓存：决策是 **state → 概率**的（近似）确定函数（实测同 state 同结论）→ 可对「(池版本, 问题)」缓存（复用 `tool_pool_meta.pool_version` 失效）。
- 预算：每日/每会话决策调用上限（与 `usage_events` 同款计数）。

### G. 「当裁判而不是选手」
- 只做方案 A 的那一问（够/不够）、**不做选择** → 用于：① 触发「升级检索」（§7.3）；② 把「P(够用) 低」的路由结果记进 `failure_events`，让漂移可见。
- 与 A 的区别：A 需要**重选机制**（= 第二个选择器 风险）；G 只产出一个**信号** 改动面最小。

1. **方案对比的基线必须"同仪器同期测量"**：不同时间点从文档抄来的基线，会因为素材/词法被改动而失去可比性。故第二期（§二十）的基线用的是**同一次运行**里路由器自己的输出。
2. **"发布口径"是会漂移的量，不是常数**：素材层与账号词法都可由用户持续维护（03 的能力），所以任何对外比较都应**记录当时的素材快照**（池版本 `tool_pool_meta.pool_version` + 草稿文件哈希）随结果一起存，否则事后无法复现。

### 20.5 本期出现的一处负向发现（对生产有价值）

真机池轨道上，决策模型把噪声题 **`noise-who`（「你是谁」）判成要用工具，选了 `agently-cli`（邮件 CLI）**，导致 B 与 D 的噪声假阳性 0.143；而**路由器在两条轨道上都是 0.000**。

### 22.2 决策模型"能不能看到思考"——实测结论

**① 接口不暴露任何思考过程。** 实测一次 `choice` 调用的响应键（逐字）：

```text
顶层键: model / answers / usage / id / provider
answers.tool: type / choice / probabilities / confidence
```

没有任何理由、解释或推理字段。所以"它当时怎么想"只能靠**概率分布 + 受控实验**反推。

**② 那次噪声错题（`noise-who`「你是谁」）的直接证据**：它选 `agently-cli` 的 **P = 0.9553**，`__none__` 仅 0.042；而 `agently-cli` 的卡片正文里写着：

> 用户会说的话：**我是谁→+me**；我有哪些别名→+me；最近有什么邮件→…

**③ 单变量对照实验（决定性）**：同一问题、同一批 29 条候选，只把该卡片里那一段示例删掉：

| 实验 | 选中 | 前三概率 |
|---|---|---|
| ① 原样（含那段示例） | `agently-cli` | agently-cli 0.951 / `__none__` 0.047 |
| ② **只删那一段**（其余一字不改） | **`__none__`** | **`__none__` 1.000** / 其余 0.000 |
| ③ 重复①（稳定性） | `agently-cli` | 与①完全一致（0.951 / 0.047） |

结论：**噪声假阳性 100% 由卡片里那一行示例造成**；决策模型对同一 state 是**确定性**的（③ 与 ① 逐位一致）。

**④ 由此得到的两条纪律**：

1. **素材层面**：卡片里的"用户会说的话 / 示例话术"必须限量或去掉——它会直接制造噪声假阳性。这与 01 大点那次"删掉城市名示例后 `city-climate` 的 z 被顶高"是**同一类问题**（示例文本改变判定），建议在素材规范里单列一条"示例话术不得与噪声题的问法撞车"。
2. **架构层面**：**噪声交给路由器、决策模型只管选**这条分工得到实证支持——路由器两轨噪声假阳性 0.000，而决策模型会被文字陷阱咬住。故首批实现里不把 `needs_tool` 交给决策模型。

### 22.3 进方案期要做的三件事（按用户第 3 条的批次划分）

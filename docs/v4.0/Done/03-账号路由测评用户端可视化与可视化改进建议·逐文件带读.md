**逐行检查要点**
1. `_max_id` 的 `except` 分支**必须**返回 `None`，`cleanup_run` 里**必须**有 `if wm.get(key) is None: continue` —— 这两行是 2026-10-11 那次「历史版本全没了」的防线，删任一处都会重现
2. `cleanup_run` 的清理表里**不许**出现 `memory_snapshots`
3. `restore_profile` 必须在**跑完立刻**执行、且在 `finally` 里（中断也要还原）
4. `ask` 的超时分支要**同时**调 `/api/chat/cancel` 并记账（否则线程悬着）
5. `build_sheet` 的「未测」判定 = 无调用 **且** 有中断/限流标记 —— 别把「模型偷懒没调工具」也算未测

**思考题**
- ① 若把 `_max_id` 改回 `return 0`，哪几张表会被误删？请用 `tests/unit/test_probe_runner.py` 里那条「水位线读不到 → 一行都不删」的用例来证。
- ② 测评跑一半你按了「关服务」，用户的画像还会被还原吗？从 `run_cases` 的 `try/finally` 走一遍答。
- ③ 为什么打分表不参与水位线清理？（提示：判分/建议都发生在**跑完之后**才读它）

| `vague_check` | 529 | ★ 纯正则、不调模型：命中「不定指代 + 类别词」且题面无「具体对象锚点」→ 报 |

| `_health_lines` / `advise` | 983 / 1006 | 建议输入拼装（体检**字典**渲染）+ 建议调用 |

**逐行检查要点**
1. `vague_check` 的**豁免**必须保留：书名号《》、各种引号（含 `‘’`）、`BV号/编号/三位数字`、「叫 X 的」具名短语 —— 少了任一都会误报（实测踩过 `'饥荒:联机版'`、`那个叫阿司匹林的药`）
2. `normalize_expects` 认不出的写法**必须报错**、不许猜（否则等于把坏题静默吞掉）
3. `suit_violations` 必须**同时**查单工具题（不许牵涉两个套装）与多工具题（refs ≥2 且跨套装）
4. `advise` 只喂素材相关字段：**不许**在提示词里要求「改代码/改阈值」（那是用户的活）

**思考题**
- ① 「单工具题可以调多条子命令」和「多工具题必须跨套装」矛盾吗？举一道合法的单工具题与一道非法的「假多工具题」。
- ② 为什么出题材料必须用 `card_block` 而不是自己拼字段？举个「卡片没写、但模型以为有」的能力会出成什么废题。
- ③ 若把 `_ANCHOR_RE` 里的「三位数字」去掉，哪些正常题会被误报为无对象？

## 四、`prompt/prompts.yml`（三段提示词；**数据，不是代码**）

| 段 | 干什么 | 不许做的事 |
|---|---|---|
| `probe_writer` | 出题：题量公式 / 单多工具判据 / **对象必须指名** / 噪声题不许诱发网搜 / 输出 JSON 形状 | 不许出现工具名或参数名（废题）；不许「不定指代 + 类别词」 |
| `probe_judge` | 判分预填：只看给定调用序列 | 不许臆测「本来应该做什么」；不许给改进建议（那是 advisor 的活） |

**检查要点**：`probe_advisor` 里必须有「**改在哪**」段（CLI → 「能力描述」框；api/mcp → 「工具描述」框）与「CLI 诊断口径」（CLI 的能力描述住在 `user_clis.abilities`，**正门** `save_cli()`）。

**思考题**
- ① 把 `probe_writer` 的「对象必须指名」整段删掉，跑一次出题，能复现「一种新药」那类题吗？（改完记得改回来，并跑 `tests/unit/test_probe_agent.py` 的提示词断言）
- ② 为什么这段文件**不用重启**就生效，而 `api/probe.py` 要？（提示：`prompt_of` 每次读文件）

## 七、`api/server.py` / `api/monitor.py`（报错说真话 + 留证）

| 落点 | 要点 |
|---|---|
| `_SHUTTING_DOWN` + 每题前检查 | 服务在关 → 提前中止并**如实记账**，不许把进程故障说成「模型调用失败」✗ |

| `api/monitor.report_tool` | 工具起跑落 `data/audit/tool_calls.jsonl`（写盘失败**绝不影响对话**） |

**思考题**：为什么「缺个包」曾经被报成「模型调用失败」，害用户去查没坏的模型配置？（顺着 `_llm_error_hint` 的入参看它怎么拿到「当前生效配置」）

**逐行检查要点**

1. `maybe_refine` 的前两个 `return None`：`allow=False`（测评）与 `not enabled(account_id)`——**两条都是逐字回退现状**，不写任何东西（除测评那条在开关真开着时记一条 `seen/eval_off`）。
2. 缓存查询在预算闸门**之后**（当前口径），且命中还要过一次 `_fresh(hit)`——长跑进程内存索引会变旧。
3. `_apply` 只改 `order` / `top`，并挂 `decision` 说明；调用方（渲染）原样复用。
4. 所有落盘/审计都是 best-effort（`try/except` 吞掉），**绝不让决策层影响对话**。

**思考题**

- 把 `switch_on` 改成"总是返回 True"，哪些测试会先红？为什么不是全靠真机才能发现？
- 若把 `STATE_TEMPLATE_VERSION` 从 v2 改回 v1 但不改 state 构造，会发生什么？（提示：缓存键与渲染形态的关系）
- 为什么素材指纹必须含 `keywords` 与 `abilities_user`？举一个"只改关键词"的改动，说明不加会复用哪个旧判断。
- 把 TTL 设成 0 再跑一次断服实验，第 5 步应观察到什么不同？

## 四、`api/server.py`（测评隔离的传参链路）

| 关键定义 | 行号 | 说明 |
|---|---|---|
| `_run_agent(..., probe: bool = False)` | 394~398 | 新增形参；CLI `cli/cmd_chat.py` 与调试脚本走默认值 |
| 钩子调用处 | 442~444 | `route_tools(account_id, question, allow_decision=not bool(probe))` |
| `/api/chat` 的 `probe` 查询参数 | 626 | 内部参数，非空即测评请求 |
| `asyncio.to_thread(_run_agent, …, probe=bool(probe))` | 664~669 | 把标记从请求带到工作线程 |

**逐行检查要点**

1. `probe` 是**查询参数**（本项目 `/api/chat` 全用 Query，不是 body）；
2. 传参必须**沿调用链**（`/api/chat` → `to_thread(_run_agent)` → `route_tools`）——第一版漏传 `_run_agent` 的形参，`NameError` 被外层 `except` 吞掉，表现是"工具简报整个不注入"，是最隐蔽的一种坏法；
3. 普通聊天不传 `probe` → `allow_decision=True` → 行为与以前逐字一致。

**思考题**

- 为什么不能用"进程级全局开关"实现测评强制关？（提示：测评跑批与用户聊天在同一进程）
- 若把 `probe` 做成请求头而不是查询参数，这条链路要改哪几处？

| 组件 DOM | 2567~2576 | `input[hidden]`（只作 CSS 钩子）+ `label.jev-tgl`（`@click.prevent`）+ 竖排字母 + 状态徽标 |
| `const decRouter = ref(false)` | 4648 | 状态 |
| 登录/恢复时的加载 | 5182 / 8028 | `loadDecRouter()` 挂在两处初始化链上 |

**状态为何单向驱动（2026-10-13 用户实测后改）**：`label` 上加了 `@click.prevent`，**故意阻止浏览器自己去拨那个 checkbox** —— 于是可视状态只能由 Vue 的 `decRouter` 经 `:checked` 驱动，界面**不可能**与真实状态脱节。原写法（浏览器先拨、再靠 `@change` 回写）在请求失败时会演成"轨道已变绿、徽标还写着已关"（用户实测踩到，且数据库里开关值仍是 0，说明写入根本没落库）。另：`setDecRouter`/`loadDecRouter` 在 `finally` 里还会 `_syncDecTgl()` 把 DOM 兜回去，双保险。

**逐行检查要点**

1. 组件取自技能 `front_from_uiverse` **017 号**：机制是"隐藏 checkbox + label[for] + 紧邻兄弟选择器"，所以 `input` 必须与 `.jev-tgl` **相邻**、圆必须是 label 的子元素；
2. 多实例要改 id（示例里写死 `check`）——本页只有一处，用了 `jev-tgl`；
3. 示例的 6rem 字号与 155px 高度是展示尺度，嵌进侧栏按 20×44 缩放；字母按用户要求从 `N/F` 改成竖排 `J/e/v`；
4. 整行文字用 `<label for="jev-tgl">` 包住（可整行点），**不要再套一层 label**（会点两次）；
5. **模板里用到的每个标识符都必须在 `setup()` 的 return 列表里出现**（本项目在 return 处自带这条注释）。漏了的症状很有欺骗性：`{{ decRouter ? '已开' : '已关' }}` 会安静地只渲染"已关"（undefined 走 falsy 分支）、`:class="{on: …}"` 永远不亮、`@click="setDecRouter(…)"` 变成空操作 —— 看起来像"开关坏了"，其实是名字没暴露。核对方法见实现记录 §六·10。

**思考题**

- 开关状态的"唯一真相"在服务端（`accounts.decision_router`），前端 `decRouter` 只是镜像——为什么不做成 localStorage？
- 若用户开两个浏览器窗口，一边开一边关，界面如何自洽？（提示：`loadDecRouter` 的触发时机）

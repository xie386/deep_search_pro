## 二、关键落点

1. **散落数据 → 一个根**：7 处账号级数据搬进 `user_data/`（168 文件 / 33.72 MB）；知识库保持旧层级 `user_data/rag_knowledge/db/{账号}/`（用户选定）；`/pic` 的 URL 形状不变（前端零改动）；库内相对路径 `digest_reports.md_path` **34 行**同步改写，残留 0。
2. **「配置放哪」三问的答案**：开关/参数落库 `app_settings`（**保存即生效**，读取带 2 秒缓存 + `reload()`）；**一切密钥只在 `.env`**（不进前端、不进库、不回传、不回显）；路径永远问 `utils/paths.py`。判据是「谁能改、改完谁生效、错了会不会外泄」。
3. **邮件通道 = 项目级单发件箱 + 账号级收件箱**（裁定 5）：`.env` 的 `QQMAIL`/`QQMSTP` 是唯一发件箱；每个账号绑自己的收件邮箱（全局唯一）。这与参考项目 `VarifyServer` 的 `from` 固定 / `to` 取请求同源，但补齐了它没有的：6 位数字码、只存哈希、5 分钟时效、60 秒重发冷却、5 次试错、一次性作废、24 小时发信配额、错误归一化。
4. **不可逆操作的安全设计**：注销要三样（密码 + 绑定邮箱验证码 + 原样输入确认词），**先快照再清除**（`backups/account_delete_<账号>_<时间戳>/`），复用 `purge_account` 一次清干净（库行 + 文件侧 + 会话），旧 token 立刻失效。前端那一条深红危险区**放在页面最下方**——位置本身就是警告。
5. **测试纪律的两条硬约束**（本轮补上）：① 真机/端到端脚本**不得在真实账号上写**，一律临时账号 + `atexit` 自清；② **单测不得依赖 `app_settings` 为空**（真机库里可能有用户保存值，而取值顺序是库优先）——本轮给 4 个文件补了「隐藏库值」隔离，并把闭环验法写进测试注释。

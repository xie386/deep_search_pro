## 一、这个模块做了什么

一句话：把「路由变准」从**只对某一个账号的工具池有效**，做成**可迁移、可跨账号复用**的两条腿。

| 两条腿 | 归属 | 谁维护 |
|---|---|---|
| **算法侧** | 项目代码（路由器阈值/度量口径/清理与隔离硬规则/wire 文本渲染） | 我（随版本演进） |
| **词法侧** | **账号数据**（CLI 能力描述 · API/MCP 工具描述 · keywords） | **账号主自维护**（改素材 → 再测 → 看指标） |

落地形态 = 前端第 6 个页签 **🧪 工具池测评** + 后端 `/api/probe/*` **11 个接口** + 三段独立小 Agent
（`probe_writer` 出题 / `probe_judge` 判分预填 / `probe_advisor` 词法建议）+ 执行器 `tools/probe_runner.py`。

闭环（界面顺序即流程）：

```
① 工具池体检（素材缺不缺：关键词/描述/英文名…）
 ↓ ② 生成题单（Agent 出题 → 人过目、可直接改 → 保存）
 ↓ ③ ▶ 开始测评（真机跑，独立进度轮询；单题墙钟上限）
 ↓ ④ 判分（Agent 只**预填** → 人工**终判**，指标只认终判）
 ↓ ⑤ 💡 词法改进建议（只建议改素材，并写明该改哪个框）
 ↓ ⑥ 📥 写入大屏（出打分表 + 覆盖式写指标）→ 改素材 → 回到 ②
```

## 五、踩坑、偏差与事故（如实记）

### 1. e2e 冒烟污染真实账号（裁定 30/31）——我踩的
- **现象**：用户 43 题题集被覆盖成「单元冒烟用的 1 条」；他真机那轮的原始记录被 `_prune_raw(keep=1)` 顶掉（**不可找回**）。
- **根因**：`probe_api_e2e.py` 直接在**真实账号**上做写操作；`_raw()` 用 `startswith("probe_run_")` 匹配，把 `.e2e_hidden`/`.bak` 残留也当本轮记录。
- **修法**：e2e 所有写操作搬到**临时账号**（跑完连账号一起 purge），真实账号**只读 + 结尾零改动指纹复核**；`_raw()` 改严格正则 `RAW_RE`。

### 2. 测评清理把账号的**画像历史版本删光**（裁定 37）——最严重
- **现象**：用户报「每次登录都弹『还没有历史版本』」，查下去是 `memory_snapshots` **整表 0 行**。
- **证据链**：① `sqlite_sequence(memory_snapshots)=1066` 而表空 ⇒ **是被 DELETE、不是表被重建**；② 对比备份：10-10 17:28 有 3 条，今天 19:05 已 0，而同期 `usage_events`/会话/消息/失败事件**都在正常增长** ⇒ 不是删账号，是**只针对这一张表**的清理；③ 全仓只有三处会删行，前两处被排除，只剩 `probe_runner.cleanup_run()` 的水位线清理
- **根因**：`_max_id()` 读失败时**静默返回 0** → `DELETE ... WHERE account_id=3 AND id>0` ⇐ 清空该账号全部画像历史（「读不到」被当成「从 0 开始」）
- **修法**：`_max_id` 读不到返 **`None`** → `cleanup_run` 见到 `None` **跳过该表一行不删**；`memory_snapshots` **彻底移出清理名单**（它是给用户看的数据）；
- **恢复**：从备份把 3 条（09-29 / 09-30 / 10-03）**原位写回**（`docs/v4.0/backups/personal_after_snapshot_restore_*.db` 是恢复后的快照）

### 3. 生成「词法建议」报 `TypeError: sequence item 0: expected str instance, dict found`（裁定 39）
- **根因**：`advise()` 用 `"；".join(h["problems"])`，而体检的 `problems` 是**字典列表** `{code,severity,msg}`；尼古喵喵池子体检**零问题**（走「无」分支）所以一直没暴露，药喵的 arXiv 工具名是英文标识符 → 这条路径第一次被执行就炸
- **修法**：抽出 `_health_lines()`（按 `hard/soft → 硬/软` + `msg` 渲染，容忍老的字符串形状）+ 加了**离线端到端**用例（stub 池子与模型，把 `advise` 的输入拼装整段跑通）

### 4. 提示词文件被 `git checkout` 覆盖后从会话存储还原（同日事故）
- **现象**：改 `prompts.yml` 时手工写 YAML 转义**写成双重反斜杠** → 载入变字面 `\n`；为回退执行 `git checkout -- prompt/prompts.yml`，而该文件的 `probe_*` 三段**只存在于工作区、从未 add/commit** → 被索引旧版覆盖
- **恢复**：从 Hermes 会话存储 `state.db → messages` 逐字取回三段（`probe_writer` 2500 字 / `probe_judge` 947 / `probe_advisor` 1641）+ 逐字校验；快照 `docs/v4.0/backups/prompts_probe3_recovered_20261012_020629.json`
- **损失评估（已核）**：扫本会话对 `prompts.yml` 的全部补丁 diff ⇒ v4.0 期间**只动过 probe_\* 三段**，其余 7 段与提交版逐字相同

### 5. 出题 Agent 爱出「没有明确对象」的题（裁定 38）
- **现象**：「我正要开始吃**一种新药**，但担心它和我正在吃的**降压药**有冲突…」——两个药名一个没给，Agent 无从下手；尼古喵喵那轮同款「我看的那个 bili 视频讲了什么」
- **根因**：旧规定只禁**代词**（它/这个/那本书），模型钻空子用「不定指代 + 类别词」
- **修法**：提示词写死硬规定（含正反例 + 换人可执行自检）+ `vague_check()` 确定性自检 + 题单琥珀条（只提醒不拦保存）

### 6. 与方案的偏差
| 方案里写的 | 实际做的 | 说明 |
|---|---|---|
| 判分「Agent 判」 | Agent **只预填** + 人工**终判** | 方案阶段就已定（避免把模型判断当裁决）✓ 无偏差 |

## 七、这一轮踩出来、已写进纪律的

1. **不对未提交的工作文件用 `git checkout --`**（等于丢弃）；要回退先 `cp` 一份。
2. **YAML 里嵌 JSON 提示词一律用 `json.dumps` 生成**，不手写转义。
3. **高危文件（提示词 / 数据）改动前先落 `docs/v4.0/backups/` 快照**。
4. **测试绝不针对真实账号做写操作**；重活测试用**库副本**（`PERSONAL_DB_PATH`）。
5. **清理类代码的判据必须 fail-closed**：读不到就**不删**（读不到 ≠ 从 0 开始）。
6. **后端改动清单要标「是否需重启」**（提示词类不用、Python 类要）。

# v4.0 · 07 资源嗅探与抓取 · 实现记录

> **性质**：本大点的**实现记录**（问题 → 方案 → 结果）。调研与实测见 `../research/07-资源嗅探与抓取.md`（§二 只读取证 · §三 成本最低方案的三组对照）；方案见 `../v4.0规划文档.md` §07 ③（含「实现期修正」）。

## 二、关键落点

1. **决定下载是否落盘的是 `downloads_path`，不是 `accept_downloads`**。0.13.11 里 `accept_downloads` 只有定义与透传（watchdog 里仅一处 TODO 提到），真正的开关是 watchdog 通过 CDP `Browser.setDownloadBehavior(downloadPath)` 设置的那一处；三组对照实测：`accept=False + 显式路径` 照样落盘。
2. **直落工作目录不落盘，必须「暂存 + 搬移」**。把 `downloads_path` 指到 `<工作目录>/_downloads/browser_<时间戳>/` 时，watchdog 报 `Download did not complete within 20 seconds`、文件始终不落；同一次任务改指项目内 `user_data/_runtime/browser_dl/run_<时间戳>/` 立刻成功。根因未查清（疑与本机受限令牌下该子树的 ACL 有关），按暂存 + 搬移落地并如实注释。
3. **下载流程要 6~10 步**：搜索 → 详情页 → 点 Crop & Scale → 选分辨率 → Done → Continue 确认。模型自己给 5 步时最后一步只剩 `done`，文件眼睁睁没下完 —— 故对下载类任务设**步数下限 12**。
4. **回执是这层的价值所在**：模型原本只知道自己"点了按钮"。现在正文写清「N 个文件、名字、体积、相对路径」，图片再附 `[[img:…]]`（前端渲染沿用 06 的通道）。
5. **空目录不成灾**：没下载到东西时不建目标目录、清掉空暂存；有文件的目录保留给用户。

## 四、本轮修掉的问题（6 个）

| # | 现象 | 根因 | 归属 |
|---|---|---|---|
| 1 | 点「下载」后文件始终不落盘 | `downloads_path` 直接指向工作目录时 Chrome 侧下载不完成（watchdog 20 秒超时） | 本机环境，改「暂存 + 搬移」 |
| 2 | 以为 `accept_downloads=False` 挡住了下载 | 该开关在 0.13.11 里基本未使用，真正起作用的是 `downloads_path` | 认知错误（调研期已纠正） |
| 3 | 模型拿到直链后去 `curl -o` | 说明书与提示词都没提「浏览器能下载」，而 curl 白名单禁止 `-o` | 本点遗漏，补齐三处文案 |
| 4 | 前两次真机失败在第 5 步 | 模型给了 `max_steps=5`，下载流程要 6~10 步 | 本点遗漏，下载任务步数下限 12 |
| 5 | 最终回答里出现 `D:\...\_runtime\browser_dl\run_<ts>\…` | 子 Agent 把内部暂存绝对路径抄进回答 | 本点遗漏，任务里追加【落盘说明】 |
| 6 | 工作目录里留了 6 个空 `_downloads/browser_*` | 没下载到东西也 mkdir 了目标目录 | 本点遗漏，空暂存直接清、不建目录 |

> 另记：browser-use 自带 judge 曾把成功的这轮判成 FAIL（理由说「弹窗里没有 2560×1080」）—— 实际弹窗 Ultrawide 列第一行就是它，日志也有 `Clicked td "2560 × 1080"` 与 `📥 Download started`。该 judge 不参与本项目的成败判定（runner 的 `ok` 恒为 true，成败看有没有文件落盘）。

## 五、遗留与边界（如实记录，不粉饰）

1. **根因未查清**：「`downloads_path` 指向工作目录时 Chrome 不写盘」只做到现象级定位（换到 `_runtime/browser_dl` 即正常），怀疑与本机受限令牌下该子树的 ACL 有关，未做进一步实验。
2. **不做批量嗅探**：一次只下载「任务里点名要点的那几个」，不做「嗅出页面全部资源批量取」。
3. **不做队列/续传/限速**；单文件 100 MB 阈值只做「标记未收」，不拦截下载本身。
4. **judge 与文件展示机制不由本层接管**：`success` 字段照旧回传，但不作为成败依据。
5. **残留未清**：`user_data/_runtime/browseruse/tmp/` 下 73 个非空 `browser-use-user-data-dir-*`（每轮浏览器运行的临时 profile），已报给用户、未动。

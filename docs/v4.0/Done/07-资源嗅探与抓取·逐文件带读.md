# v4.0 · 07 资源嗅探与抓取 · 逐文件带读

> 配套 `07-资源嗅探与抓取·实现记录.md`。本点很小（不新增工具、不新增子 Agent），**两个文件就够了**：
> 读 `browser_tool.py` 看「怎么定落点、怎么搬、怎么回报」，读 `browser_runner.py` 看「browser-use 这一层怎么配」。
> 一句话主线：**下载能力早就有，缺的是"落对地方 + 说清下了什么 + 别让模型用错通道"。**

## 一、阅读顺序总览

```
① scripts/browser_runner.py   ← 先看浏览器侧怎么配（downloads_path 才是开关）
② tools/browser_tool.py       ← 再看调用侧：暂存 / 搬移 / 步数 / 回执
③ tools/web_workflows.py      ← 模型看到的说明书（要下载就把"点下载按钮"写进 task）
④ prompt/prompts.yml          ← 主 Agent 的取法规则（第 ④ 条）
⑤ tests/unit/test_browser_downloads.py
```

## 二、逐文件

### 1. `scripts/browser_runner.py`

- 先看 `prof_kw` 里那两行：`accept_downloads=False` 与 `prof_kw["downloads_path"] = dl_dir`。**思考题**：为什么把 `accept_downloads` 留成 False 也没关系？（答：0.13.11 里它不是总开关，真正生效的是 watchdog 用 CDP `Browser.setDownloadBehavior(downloadPath)` 设置的那一处。）
- 再看 `_list_downloads()` / `_drop_if_empty()`：清单递归扫、超限只标记不删文件、空目录才删。**思考题**：为什么"超限"不删源文件？（用户可能就想要那张大图，删了等于替他做决定。）
- 最后看结果字典里的 `downloads` 与日志「下载落点」。**思考题**：如果这里不给 `downloads_path`，文件会去哪？（库默认 `%TEMP%/browser-use-downloads-<id>`，跑完还在，但没人知道、也没人能用。）

### 2. `tools/browser_tool.py`

- `_download_dir()`：给 Chrome 的是**项目内暂存目录**，返回的是相对工作目录的**最终路径**。**思考题**：为什么不能把 `downloads_path` 直接指到工作目录？（真机：Chrome 那边下载永远完不成；换到 `_runtime/browser_dl` 立刻正常。根因未查清，见实现记录 §五.1。）
- `_move_downloads()`：先扫暂存，没文件就直接清掉、**不建**目标目录；有文件才 mkdir，重名加 `-2` 后缀，搬完删暂存。**思考题**：为什么不直接 `shutil.move(stage, dst)` 一把梭？（目标目录可能已存在、可能重名，且必须保住用户已有文件。）
- `_is_download_task()` + `_step_budget`：下载任务步数下限 12。**思考题**：为什么是 12 而不是"给足 30"？（步数越多，越容易被上游连接时长掐断，也越费额度；12 够走完「搜索→详情页→选尺寸→Done→Continue」。）
- 回执段：`📥 本次下载 N 个文件…` + `[[img:…]]`。**思考题**：图片为什么要单独加标记？（模型只看得懂文本，前端只认 `[[img:…]]` —— 这一行是模型与前端之间唯一的桥。）

### 3. `tools/web_workflows.py`

- `browse_only` 的 docstring 就是**模型看到的说明书**。本点加的那段写清三件事：要下载就把「点击下载按钮」写进 task；文件落到 `_downloads/`；**别用 curl**。
- **思考题**：为什么 curl 不能下载？（白名单只允许 GET 抓文本，`-o` 会被参数级校验拒掉 —— 这是安全设计，不是 bug。）

### 4. `prompt/prompts.yml`

- 找主 Agent「三种取法」那节，看第 ④ 条。**思考题**：为什么这条要写在**取法**里而不是工具 docstring 里？（取法决定"用哪个工具"，docstring 决定"怎么用这个工具"；模型先选工具，再看说明书。）

### 5. `tests/unit/test_browser_downloads.py`

- 12 条，按"配置 → 搬移 → 回执 → 边界"排。**思考题**：哪几条是在钉"不许发生的事"？（空暂存不建目录、超限不删源文件、重名不覆盖、取不到工作目录要静默回退不报错。）

## 三、故障史（读代码时的背景）

| 读到这里时 | 想想当年的故障 |
|---|---|
| `browser_runner.py` 的 `downloads_path` | 以为 `accept_downloads=False` 就够了 → 实际文件早就在悄悄下，只是落在临时目录 |
| `_download_dir()` | 直落工作目录 → 20 秒超时、0 字节，看着像"浏览器坏了" |
| `_step_budget` | 5 步的预算，停在第 4 步「选好分辨率、没点 Continue」 |
| 回执段 | 模型只知道"点了按钮"，回答里给不出一张图的名字和体积 |
| `_move_downloads()` 的空暂存分支 | 工作目录里堆了 6 个空 `_downloads/browser_*` |

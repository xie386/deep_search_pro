## 二、关键落点

1. **结构上限由题库自己决定，不写死**：`m5c_router_bench.py:212-213` 现算 `n_one`（只有 1 个可接受工具的题数）与 `ceiling = Σ min(|可接受|, 3) / 3 / n_conf`，并打印。以后改题库，上限自动跟着变 —— 不会再出现「一条恒真的目标线」。
2. **硬判据的方向显式化**：`METRICS_UP` / `METRICS_DOWN` / `METRICS_REPORT_ONLY`（`:60-62`）三组常量同时供打印与对比使用，避免「哪个键越高越好」靠记忆。
3. **注入形态取真实渲染结果**：`route_once` 回传 `full_refs`（`:137`）—— 它是 `_render_routed` 里**真正给了完整卡**的条目（预算不够会降级成紧凑行，所以这个长度已经反映了降级），因此不需要在测试侧复算渲染逻辑、也就不会与生产逻辑漂移。
4. **阈值改动必须两个口径都重跑**：冻结池（`m5c_router_bench.py`）反映「素材层前」，冻结池＋草稿（`m6b_material_ab.py`）才是「库里入库口径」；只看一个口径改阈值 = 拿半个证据做决定。

## 四、踩坑与偏差

| # | 事项 | 说明 |
|---|---|---|
| 1 | **基线一天被重写两次** | 改判一次（`city-climate`）+ 重标定一次（阈值）。两次都必须**同时**改 `router_bench_baseline.json` 与 `router_bench_regressions.json` 的 `baseline_metrics` —— 只改一处会让两份夹具对不上，而 `verdict_rule` 引用的正是后者 |
| 2 | **改判会「创造」出一个非零指标** | `noise_false_positive` 由 0.000 变 0.143，看着像回归，其实是**信息修正**（那道题一直被自信路由到错工具，只是原先被算在「未命中」栏里）。文档必须写成「口径修正」并把新旧读数并列 |
| 3 | **`m6b_delta_rerun.py --offline-only` 走的是「不加草稿」的冻结池** | 所以它至今仍显示 5 例未命中 —— 别当成回归；要看素材层生效后的落位，用 `m6b_material_ab.py` 或 `m6b_delta_rerun.py --offline-only --live-pool` |
| 4 | 方案偏差：预研写的是「若 precision@3 ≥ 0.7 且噪声假阳性 ≤ 10% 则 Jev 继续搁置」 | 实跑后改为「非噪声灰区 ≥ 5 道 或 噪声假阳性 > 0.1」—— 原条件里的 precision 那条不可达（见规划文档 ①），已作废 |

### 7.6 新增纪律（本次踩出来的）

1. **改阈值必须两个口径都跑**：`Z_STRONG = 3.4` 在**冻结池**全绿，但**真机池**（29 条）下 `city-climate` 的 z = 3.62 仍越线 → 噪声假阳性 0.143。冻结池够 ≠ 真机够。（真机池的最小可行值是 3.62，与那道题的 z 贴边 → 最终取 **3.8**，两池都在平台区内、留 ~0.18 余量。）

## 裁定 1（2026-10-12）：形态定为「两段式决策精排」（方案 C），不做二值仲裁

| 项 | 内容 |
|---|---|
| **分叉点** | 决策模型这一层该做成哪种形态？候选：**A** 二值仲裁（先选→判"够不够"→打回重选）；**B** 决策直选（全池注入，一次选一个）；**C** 两段式（现有路由召回 top-k → 决策模型精排）；**D** 多标签（对每个工具各问一个"要不要用"）；**G** 只当裁判（只产出信号，不改选择） |
| **可选方案** | **A**：改动最大、需要第二个选择器 + 双倍调用（实测净亏）；**B**：质量高但注入 6459~7034 字符、池子一大不可行、真机池出现噪声假阳性 0.143；**C**：注入 421~472 字符（约基线 1/12）、可扩展到几百条池、两轨噪声假阳性 0.000；**D**：裸池口径强，但素材层补齐召回后优势消失；**G**：只漏报不虚报，只能当辅助信号 |
| **裁定结果** | **C（两段式决策精排）作为主路**。A 不做（证伪）；B 备选但必须配噪声闸门与池规模限制；D 不作主路（跨口径不复现）；G 可作辅助信号（首批不做） |
| **依据** | 第二期两轨实测（`research/02-Jev仲裁层.md` §二十）：**冻结池＋素材** 与 **真机池 29＋素材** 两轨上 C 都是 **21/23（0.913）** 对同仪器基线 **19/23（0.826）**，噪声假阳性 0.000，平均注入 462~472 字符；B 在真机池 22/23 但噪声假阳性 0.143；D 两轨都只有 19/23。另：C 的错全部来自「候选里没有正解」或「多步链题单选退化」，精排本身在"候选含正解"时不丢分（§18.3 的 18/18、§20.2 的召回覆盖 23/23） |
| **影响面** | 新增决策客户端与精排逻辑（落点见裁定 5 待定项）；`tools/tool_router.py` 的 `_route_provider()` 缝隙启用；规划文档 §02 ③ 段；不替换词法/向量快路、不改 `card_text`、不动阈值 |

## 裁定 2（2026-10-12）：触发条件用「近并列」（融合分间距），门限起点 0.0005

| 项 | 内容 |
|---|---|
| **分叉点** | 什么时候调决策模型？候选：**只灰区**（预研原意，省调用）／**全跑**（每题都精排）／**近并列**（top1 与 top2 分数接近时才精排） |
| **可选方案** | **只灰区**：触发 2/23，净收益 **0**（因为净收益全在"自信题"里，见下）；**全跑**：净 **+2** 但每题 +1.3 秒、且会把 `trip-transfer` 也交给精排反而弄坏；**近并列**：需要一个门限，实测能"既省又赚" |
| **裁定结果** | **近并列才精排**；判据 = **路由器融合分间距** `fused[top1] − fused[top2]`；**门限起点 0.0005**（触发率约 30%），做成**配置项**，每次触发记录间距以便后续复标 |
| **依据** | 逐题拆解（§22.1、§五之二）：**净收益 100% 来自"自信题"**——自信题里精排救回 3、弄坏 1；灰区题救回 1、弄坏 1 → 只做灰区净收益为 0。门限扫描（`research/02-Jev仲裁层-demo/jev_near_tie_calibration.json`）：融合间距 < 0.0005 时**救回 4/4、弄坏 1/2、净 +3**，优于全跑（+2）；z 间距判别力更弱（最好 +2 且要触发 70~83%）。更细的门限（0.00024~0.00028）能做到净 +4，但两题只差 17%、在 23 道题上属过拟合，不采纳 |
| **影响面** | 新增门限配置项与触发判定；调用量从"每题"降到约 30%；后续需在更大题集上复标（首批实现时把间距写进审计日志） |

## 裁定 3（2026-10-12）：噪声归路由器，决策模型只负责「选」

| 项 | 内容 |
|---|---|
| **分叉点** | 「要不要用工具」这件事归谁判？候选：**交给决策模型**（`needs_tool` 判定，可能替代现有阈值机制）／**仍归路由器**（决策模型不参与，只管从候选里选） |
| **可选方案** | **交给决策模型**：能治"阈值随素材漂移"的长期痛点，但实测噪声假阳性 0.000 → 0.143；**仍归路由器**：保住 0.000，改动面小，但阈值机制照旧 |
| **裁定结果** | **噪声归路由器、决策模型只管选**（首批不做 `needs_tool`） |
| **依据** | 第二期真机池轨道：路由器两轨噪声假阳性 **0.000**，决策模型 **0.143**（把噪声题 `noise-who`「你是谁」判成要用工具，选了 `agently-cli`，P=0.951）。**单变量对照实验**（§22.2）证明原因是素材卡片里写着「用户会说的话：我是谁→+me」：删掉这一段后同一问题同一批候选改为选 `__none__`（P=1.000）；重复原样实验两次结果逐位一致（决策模型对同一 state 是确定性的） |
| **影响面** | 首批不实现 `needs_tool`；另产生一条**素材纪律**：卡片里的「用户会说的话 / 示例话术」不得与噪声题的问法撞车（建议写进素材规范）；噪声题仍由现有"自信才路由"机制兜底 |

## 裁定 4（2026-10-12）：首批范围 = 精排 + 缓存 + 计量 + fail-safe；链题专项为第二批

| 项 | 内容 |
|---|---|
| **分叉点** | 首批做到哪一步？候选：**一次做全**（含多步链题的"选项粒度/动作化"改造）／**先做基础四件**（精排、缓存、计量、fail-safe），链题专项随后 |
| **可选方案** | **一次做全**：链题是当前唯一集中失分点，但选项粒度改造会改变问法，需重新标定门限与重测，周期长；**先做基础四件**：可用新验收口径立刻判定，链题专项作为紧接着的第二批（届时同样要重测） |
| **裁定结果** | **先做基础四件**：决策精排 + 决策缓存 + 计量（`usage_events` / `failure_events` / 缓存命中计数 / 审计日志）+ fail-safe（逐字回退现状）。**链题专项（选项粒度/动作化）作第二批** |
| **依据** | 用户 2026-10-12 夜裁定（原话要点："先只做精排 + 缓存 + 计量 + fail-safe（不含链题选项粒度），链题专项作为紧接着的第二批"）。支持数据：首批即可用"同仪器基线 × 0.9"验收（见裁定 5 的判据口径）；链题的失效模式在两期实验中反复出现且姿势一致（都选链条第一步 `get-current-date`），适合独立成批处理 |
| **影响面** | 实现清单见规划文档 §02 ③ 段；验收判据按新口径（下条）；交付时需给出"脚本自测 + 网页端真机"两步结果（bug 修复阶段两步都不许跳） |

## 裁定 5（2026-10-12）：验收判据改用「同仪器同期基线」口径

| 项 | 内容 |
|---|---|
| **分叉点** | 验收判据怎么写？用户 Q10 原定「灰区 precision 提升 ≥10 个百分点 且 全量 `precision@1` 不低于本轮实测的 90%（≈0.933×0.9 = 0.84）」；但**素材层在 10-09 与 10-11 之间被大改**，0.933 那一期的夹具已不可复现 |
| **可选方案** | **沿用 0.84 硬数字**：可能被素材漂移带偏（判据与实际不同步）；**改为同仪器同期基线**：目标 = **同一次运行里路由器 `precision@1` × 0.9**，并附加条件「噪声假阳性不得高于路由器」 |
| **裁定结果** | **改为同仪器同期基线口径**：① `precision@1` ≥ 该次运行路由器基线的 90%；② **噪声假阳性不得高于路由器**；③ 附报 `hit@3` / 平均注入字符 / 调用次数 / 延迟（不设硬线，只作对比） |
| **依据** | `research/02-Jev仲裁层.md` §十九 / §二十一：今日复现显示 `Done/01` §7.5 记的 0.870 属 10-09 那版素材（草稿夹具 HEAD 版与工作区版有 18 条文本差异、且 `bili` 一条素材在草稿有、库中无），**"发布口径"是会漂移的量**。按新口径：两轨基线 0.826 → 目标 ≥ 0.743；C 实测 0.913 过线；B/D 在真机池的 0.143 噪声假阳性会被第②条卡住 |
| **影响面** | 规划文档 §02 ③ 段的验收段；实现期每次跑基准都要**连素材快照一起记录**（`tool_pool_meta.pool_version` + 草稿文件哈希），否则事后无法复现 |

## 裁定 6（2026-10-13）：**03 路由质量测评期间，决策层强制关闭**（与用户开关无关）

| 项 | 内容 |
|---|---|
| **分叉点** | 决策层上线后，03「账号路由测评」该怎么处理？候选：**按用户开关走**（开着就把决策层算进测评）／**测评期间强制关**（无论开关状态） |
| **可选方案** | **按开关走**：测评数字里混进决策层的功劳，而且会随"用户有没有点按钮"漂移，与 01/03 的历史基线**不可比**（等于自己给自己放水）；**强制关**：测评只量「路由器 + 素材层」，历史可比，代价是要在请求链路上打一个标记 |
| **裁定结果** | **测评期间强制关闭，与开关状态无关**。链路：`probe_runner` 每题下发 `probe=1` → `POST /api/chat?probe=1` → `_run_agent(..., probe=True)` → `route_tools(allow_decision=False)` → 决策层**不参与、不读缓存、不写缓存**；若开关真开着，另落一条 `seen + eval_off` 审计说明"这次是我被测评口挡下的" |
| **依据** | 用户 2026-10-13 裁定（原话要点："决策层及决策缓存会极大提高路由测试的正确性，相当于作弊了，所以用户不管有没有点按钮开启决策模型层，测试期间都必须是关闭状态的"）。同源纪律：01 大点的"同仪器"口径 —— 换仪器就不能沿用旧刻度 |
| **影响面** | ① `tools/probe_runner.py`：每题带 `probe=1`，开跑打一行提示；② `tools/tool_router.py`：`route_tools(allow_decision=...)`；③ `tools/decision_router.py`：`maybe_refine(..., allow=False)` 短路 + `eval_off` 审计；④ `api/server.py`：`/api/chat` 增 `probe` 查询参数并沿调用链传参（CLI `cli/cmd_chat.py` 与调试脚本默认不受影响）。**01 的基准不受影响**：`tests/live/m5c_router_bench.py` 直接调 `router.decide()`，本来就不经过本层 |

## 裁定 8（2026-10-13）：A 案否决 —— 灰区不得裁剪工具池；B 案经核查「已是现状」

| 项 | 内容 |
|---|---|
| **分叉点** | 第二批剩余失分面是**灰区题选错**（样本 `city-basic`）。可选方向：A 让决策层在灰区挑几张完整卡注入（其余只留名称行）；B 把用户侧说明并入向量文本 |
| **A 案裁定** | **不做**。用户原话要点：① 灰区本身就是"路由不确定"的场景，此时**再把全部工具的信息部分裁掉**，一旦决策模型挑偏，Agent 就看不到完整工具池；② 工具池会继续增长、用户需求会继续细分，**后期完全可能出现一次要用 5 个以上工具的问题** —— 灰区若不显示全部信息，Agent 就完不成这类工作。**代价不对称：用一个赌注换掉安全网** |
| **B 案核查** | **不需要做——它已经是现状**。数据库列 `abilities_user` 在**建条目时**就并进 `e.abilities`（`capability_pool.py:358-361`：工具级用户描述顶掉自动摘要、来源级用户描述同时并入），`_entry_text()` 取 `name + keywords + abilities + 参数摘要`，故用户侧说明**本来就进向量**。上一轮"`abilities_user` 不进向量""`keywords` 不进向量"两条结论**均为勘误**：`CapabilityEntry` 上没有 `abilities_user` 字段，且当时的脚本没有"补丁是否命中"的自检，属**静默空跑**被当成了结论 |
| **补测事实** | 带命中自检重测：给 `city` 的 `keywords` / `abilities` 各追加一句后，z 分从 `0.978` 微动到 `0.995` / `0.972`，**名次不变**（±0.02 的位移不足以翻转判定）→ 素材微调对"深度灰区"题天然无效 |
| **灰区排名实测** | **入库口径**下：`city-basic` 的期望工具 `mcp:city/search_city` 排 **第 2**（fused 0.0313 vs 站码工具 0.0315，**仅差 0.0002**）；`trip-transfer` 的两个期望工具排 **1 与 4**。两题都因 z 不达自信线（0.978 / 2.259 < 3.8）落灰区 → 按设计回退全量、由主模型定夺。即 `city-basic` 是「**以 0.0002 之差选了邻位工具**」＋「**分数不达自信线**」的叠合：灰区本就全给工具、精排无增量，所以决策层救不到它；而在灰区裁剪工具池已被本裁定否决 → **唯一被允许的杠杆只剩素材层**（实测能把它翻转，但首版改法带坏了 2 道）。口径提醒：把来源级描述去掉另测时该工具会升到第 1，两个口径不可混用 |
| **影响面** | `Done/02-决策模型仲裁层·实现记录.md` §八（灰区段落改为实测结论 + 勘误说明）；第二批判定为**收口**（挂起项已完成、链题暂不做、A 否决、B 无需做） |

## 裁定 9（2026-10-13）：剩余灰区失分改由素材层收口 —— 措辞迭代选优后直接入库

| 项 | 内容 |
|---|---|
| **分叉点** | 裁定 8 之后，灰区失分只剩**素材层**这一个杠杆；但首版改法把 `city-en`、`trip-main` 带坏。要不要继续迭代措辞？由谁入库？ |
| **裁定结果** | 用户原话：「**迭代几轮选最好的，然后直接入库**」→ 助手迭代措辞，选最优后**直接写库**（授权范围：账号 3 的 `mcp:city/search_city` 一行） |

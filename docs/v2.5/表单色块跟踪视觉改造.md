# 表单视觉改造：把「色块跟踪」铺到三处纯色表单

> 版本：**v2.5**（小数版 = 现有功能的用户观感优化）
> 日期：2026-09-24　范围：`front/index.html`（**纯前端，后端零改动**）

## 问题

项目里的表单分成两种「面无表情」的形态，和已经做过的页面美化（教程 / 天气卡 / 登录卡）不在一个语言体系里：

| 位置 | 现状 | 截图位置 |
|---|---|---|
| **个人信息 / 公司信息** | 白底卡 + 一排灰白圆角输入框 + 深灰按钮，行与行之间没有任何「你在哪一段」的提示 | 导航「👤 个人信息」 |
| **报告（Digest 定期推送）** | 每条订阅一张淡黄卡，但黄只是背景色，不参与任何交互 | 导航「📋 报告」 |
| **定制助手** | 大量纯白表单（模型选型一行 7 个控件、人格区一堆输入框），控件全靠边框区分 | 导航「🐾 定制助手」 |

用户的要求（逐字）：借 014 号组件的**色块跟踪理念**（不是拿它做登录页），把三处表单统一成
**基色 `#FFF81F` + 跟踪色块 `#88F529`**，并且**所有默认输入框组件也要换掉**（可自主选一个 uiverse 组件）。

## 方案

### ① 选型：输入框用 **004（`inputs/neon-shadow`）**，但去掉它的包裹层

004 原组件的标志性动作有两个：**硬偏移投影**（`box-shadow: 8px 8px 0 0 ink`，静态就"立"在纸面上）
和**聚焦时投影收掉 + 上下两条线从两侧展开**。但原实现依赖 `.input-container` 里的
`.topline` / `.underline` 两个 `<span>`——项目里有 **122 处** `.m-input`，不可能逐个加 DOM。

**改造方式**：用 `background-image: linear-gradient(...)` + `background-size` 过渡，把"下划线从左展开"
搬到输入框**自己身上**，于是不需要任何包裹层：

```css
.m-input  { box-shadow: 3px 3px 0 0 var(--form-ink);   /* 静态：硬偏移投影 */
            background-image: linear-gradient(var(--form-track), var(--form-track));
            background-repeat: no-repeat; background-position: left bottom;
            background-size: 0% 3px; }                  /* 聚焦前：下划线长度 0 */
.m-input:focus { box-shadow: none;                      /* 聚焦：投影收掉 */
                 background-size: 100% 4px; }            /* 聚焦：绿下划线展开 */
```

### ② 三条机制（014 的同源改造）

014 是一个"紫色色带跟着鼠标滑落、吞掉你正悬停的那一段"的登录卡。本项目把它**旋转 90°**：
**色块从左侧横向滑过来吞掉「你正在操作的那一行/那一张卡」**。

1. **色块 = 负数 `z-index` 的伪元素**（机制核心）
   CSS 绘制顺序里「负数 z-index 的子元素」排在**元素自身背景之后**——所以绿块盖得住宿主自己的底色。
   这正是 014 能"用**一个**色带吞掉整段"的原理，也是本项目"反相"能成立的前提。
   宿主加 `isolation: isolate` 把色块关进自己的层叠上下文，不会漏到卡片外。
2. **反相是唯一的反馈语言**（014 同款）：被跟踪的那一段，输入框背景转**透明**、硬投影收掉、
   文字与下划线转**墨色**，绿块直接透出来。全场只有两种颜色来回换位，不引入第三种提示色。
3. **表单面 = 纸片**：`-9px 0 0 0 ink` 左侧实心硬边（014 的"错位第二张纸"）+ 墨色 2px 边 +
   **对角切角**（左上/右下小圆角，右上/左下大圆角）+ 极淡斜纹（`rgba(ink,.045)`，135°）+ 顶部高光。

### ③ 落地位置（类名清单）

```css
/* 表单面（黄底 + 斜纹 + 纸片） */
.p-card          /* 个人信息（兴趣 / 关注品牌 / 收藏） */
.cust-card       /* 定制助手（模型选型 / 助手人格） */
.sub-card        /* 报告（Digest 订阅卡） */

/* 跟踪单位（谁被 hover / focus-within，绿块就滑到谁身上） */
.list-edit-row   .list-edit-col      .prov-row      .soul-switch      .add-form .fg
.sub-card        /* 订阅卡整卡作为一个跟踪单位 */

/* 默认输入框组件（全局替换，122 处） */
.m-input   select.m-input   textarea.ta / textarea.m-input
```

### ④ 顺手修掉的老毛病（都在同一段 CSS 里）

- **`.sub-main` / `.sub-row1` / `.sub-row2` / `.sub-lang` 在项目里本来根本没有 CSS**——订阅卡的"两行"
  是靠输入框默认 `inline-block` **偶然对齐**的。既然要在这里给行加跟踪色块，就把它们显式写成
  `display:flex; gap; flex-wrap:wrap`，换行行为从"碰运气"变成"受控"。
- **`select` 加 `background-image` 会吃掉原生箭头** → `appearance: none` + 自带一层 SVG 雪佛龙（墨色 data-URI）。
- **「个人选购 / 公司竞品」**原来是淡灰小字，黄底上发灰看不清 → 改成墨边小胶囊。
- **危险按钮**（删除）的硬投影与文字改红（`#A8220F`），否则黄底上"保存"和"删除"一个样。

## ⚠️ 本次踩的两个坑（工具链，不是设计）

1. **换行口径会弄断 harness 锚点**。仓库 `core.autocrlf=true`，工作区是 CRLF；我用 Python 合并 CSS
   时把 `index.html` 全文转成了 CRLF，而 `tests/m4a_frontend_logic.js` 的锚点字符串里**内嵌了 LF**
   （`SEND_END = "...\n    }\n"`），于是该套件当场失效（报"未能在 index.html 中定位 M4a 代码块"）。
   → **修法**：harness 读入源码后先 `.replace(/\r\n/g, '\n')` 归一化，从此免疫"文件被谁写过"。
   凡是从被抽取文件里**按字面量找代码块**的 harness，都应做这一步。
2. **heredoc / shell 会吃掉 Python 字符串里的 `\n`**：`"\\r\\n"` 写进文件后变成**真实换行**，
   把 `replace(/\r\n/g, '\n')` 劈成了四行。→ **修法**：改这类带转义的代码用 `patch` 工具，
   或退一步用 `chr(92)` 拼反斜杠，绝不把转义交给多层壳。

## 复盘思考题

1. 为什么绿块必须是**负数 z-index 的伪元素**？如果改用 `background` 直接铺在宿主卡片上、
   再让输入框透明化，为什么出不来同样的效果？（提示：CSS 绘制顺序里负 z-index 子元素与元素背景的先后）
2. 014 用「整卡只有一条色带、靠 `~` 兄弟选择器改它的位置」；本项目用「每段自己带一条伪元素色块」。
   在原组件要求"固定尺寸区块"的前提下前者更省，为什么落到可变高度的真实表单上反而是后者更稳？
3. `.sub-main / .sub-row1` 这类"只有 markup 没有 CSS"的结构类为什么危险？它如何让一次纯 CSS 改造
   出现「本地看着没事、换台机器/换个字号就错位」的偶发问题？
4. 输入框换组件时，为什么**不能**照抄 004 的 DOM 结构（`.input-container` + 两个 span）？除了工作量，
   从"这个 class 被谁复用了 122 处"的角度说明改造成本与回归风险的差别。

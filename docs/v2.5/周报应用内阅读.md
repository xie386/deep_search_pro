# 周报新增「应用内阅读」：不再只能下载到本地看

> 版本：**v2.5**（小数版 = 小功能添加）
> 日期：2026-09-24　范围：`front/index.html`（**纯前端，后端零改动**）

## 问题

报告页的表格里，每份周报的操作列只有 **↓MD** / **↓PDF** 两个下载按钮（见报障截图）。可实际上：

- 周报**早就落盘**在 `output/{账号}/快讯周报_<时间戳>.md`（`digest_reports.md_path` 就指着它）；
- 想看内容得先下载到本地、再拿别的编辑器打开；
- 桌面版下载还走原生「另存为」对话框，**连"随便看一眼"都要先选一次路径**。

用户要的：**在前端直接读 `output/` 里的文件**，跳到一个 markdown 渲染的阅读页，**点左上角退出就回到应用**；
设计参考「技能与工具 → CLI 配置的在线教程指南」那一页。

## 方案

### ① 关键判断：不需要新接口，也不需要后端配合

项目里已经有现成的两个东西：

| 已有件 | 位置 | 说明 |
|---|---|---|
| 「教程只读阅读页」 | `front/index.html` 的 `.tutorial-view` / `.tut-head` / `.tut-body.md-doc` | 一个**全屏阅读页壳**：左上角「← 返回」+ 标题 + 元信息 + 正文容器，配套一整套 `.md-doc` 排版样式（标题/表格/代码块/引用/折叠块） |
| 零依赖 md 渲染器 `tutRender(md)` | 同文件，教程页那一段 | 手写渲染（**零外部依赖、离线可用**），且**已经做过注入转义与白名单**（`tests/m4_tutorial_frontend.js` 31 项钉着） |
| `/api/download?token=&name=` | `api/server.py` | 按 token 定位该用户自己的 `output/` 目录、**同目录校验 + 目录穿越拦截**，返回文件 |

而 `GET /api/reports` 返回的每一项里**本来就带着** `download_md` 这个 URL。于是最省的做法是：

> **前端 fetch 与「下载」完全相同的那个 URL，把响应当文本读出来，交给 `tutRender` 渲染。**

好处不只是"省事"：阅读与下载走**同一条数据链路、同一道鉴权与越权闸**，不会出现"能下载却读不到 /
阅读接口忘了校验"的两套逻辑。**后端一行没改。**

### ② 落地（4 处编辑）

```html
<!-- ① 报告表格操作列：新增「阅读」按钮（与 MD↓ 同一存在条件），标签修正见下方踩坑 -->
<button v-if="r.download_md" type="button" class="dl-btn" @click="openReport(r)">…<span class="dl-text">阅读</span></button>

<!-- ② 阅读页：与教程页**同构**，只换数据来源 -->
<div class="view tutorial-view" v-show="view === 'reader'">
  <div class="tut-wrap">
    <div class="tut-head">
      <button class="bubbles tut-back" @click="readerBack()"><span class="text">← 返回</span></button>
      <div class="tut-title"><h2>📖 {{ readerTitle }}</h2><p class="tut-sub"><code>{{ readerMeta }}</code></p></div>
      <button class="bubbles tut-reload" @click="openReport(readerItem, true)"><span class="text">↻ 重新读取</span></button>
    </div>
    <div class="tut-body md-doc" v-if="!readerLoading" v-html="readerHtml"></div>
    <div class="tut-body" v-else><p class="tut-tip">正在读取周报…</p></div>
  </div>
</div>
```

```js
async function openReport(r, force) {      // ③ 阅读器逻辑
  if (!r) return { ok: false, error: 'no-item' };
  readerItem.value = r; go('reader');      // 打开即跳页
  const url = r.download_md;               // ★ 用后端给的 URL，不自己拼
  if (!url) { showToast(READER_NO_MD, true); return { ok: false, error: 'no-md' }; }
  if (readerHtml.value && readerKey.value === url && !force) return { ok: true, cached: true };
  readerLoading.value = true; readerHtml.value = '';
  const resp = await fetch(url);           // ★ 与「下载」同一个 URL
  const md = await resp.text();
  readerHtml.value = tutRender(md);        // ★ 复用教程页真实渲染器
  readerKey.value = url;                   // ★ 缓存键 = URL（不是标题）
  // …异常分支见下
}
function readerBack() { readerItem.value = null; go('report'); }   // ④ 左上角退出
```

### ③ 几个刻意的取舍

- **缓存键用 md URL，不用标题**：报告列表里会出现**多份同名周报**（实测「快讯周报 2026-09-11」有两份），
  用标题当键会让第二份直接命中第一份的正文。
- **失败不留上一份正文**：读失败时先清空 `readerHtml`，否则用户会以为"这一份"长成上一份的样子。
- **`#/reader` 直达守卫**：`readerItem` 只活在内存里，直接刷新/直链进来会停在**空阅读页**且「↻ 重新读取」无从下手
  → 启动时 `view === 'reader'` 一律送回报告页并提示入口。
- **只读**：不提供编辑/保存，与教程阅读页口径一致（要改就下载）。

## 顺手修掉的一个既有 bug

报告表格里 PDF 那个按钮是 **`<button …>` 开、`</a>` 收**（HTML 标签不配）。虽然浏览器会忽略这个悬空
结束标签、**当前没表现出来**，但同一块 markup 里 `</a>` 与 `<button>` 混着写，下次改动很容易被它带偏
（这类"当前无害的不配标签"是 in-DOM 模板的隐患）。本次在改这一列时一并改成 `</button>`，
并在新用例里**钉死**（`…PDF↓</span></button>` 的正则断言），防止回退。

## 复盘思考题

1. 为什么"阅读"要复用**下载**那个 URL，而不是新加一个 `/api/reports/{id}/content`？
   除了省事，从**安全边界**（鉴权、越权校验、同源）和**长期维护**（两条链路会漂移）两个角度各说一条理由。
2. 缓存键为什么必须是 "md 文件的 URL" 而不是"周报标题"或"报告 id"？三者在什么情况下会给出不同结果？
   （提示：看报告列表里那两份同名周报）
3. `readerItem` 只存在于内存，这让"刷新页面"变成一种攻击面（进到空页面）。为什么这类"页面壳复用"
   的功能特别容易出现这种状态残留？守卫应该写在**进入页面时**还是**渲染时**？
4. in-DOM 模板里 `</a>` 收 `</button>` 这样的标签不配，为什么可能"今天不报错、明天出事"？
   和「模板引用未导出标识符」那个老 bug（`/` 唤不出技能菜单）在**失效方式**上有什么共同点？

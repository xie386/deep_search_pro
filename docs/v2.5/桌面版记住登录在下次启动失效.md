# 桌面版「记住登录」在下次启动失效（localStorage 被清空）

> **版本** v2.5（十进制：bug 修补）　**日期** 2026-09-22　**体例** 问题 → 方案 → 结果
> **报障形态** 桌面版里登录一次、关掉再开 → **又要重新登录**（而同一进程内一切正常）
> **触及文件** `front/desktop/app.py`（`webview.start(private_mode=False, storage_path=...)`）· `front/index.html`（桌面模式改走 `localStorage`）
> **守住它的用例** `tests/desktop_window_e2e.py` 第 1/2 轮对比（**单轮测试永远发现不了这个 bug**）

---

## 一、问题

| 现象 | 迷惑点 |
|---|---|
| 桌面版关掉再打开 → 又要登录 | 同一次运行里登录、刷新页面都没问题 |
| 前端已经把 token 从 `sessionStorage` 改成 `localStorage` | 看起来「该做的都做了」 |
| 换回浏览器打开同一个页面 → 能记住 | 让人怀疑是前端存储层写错了 |

---

## 二、排查

| \# | 动作 | 发现 |
|---|---|---|
| 1 | 在桌面壳里读 `localStorage` | **同一进程内读写完全正常**（登录能用） |
| 2 | 关掉进程再开，读同一个键 | **空的** —— 每次进程结束被清 |
| 3 | 查 pywebview 文档与源码 | `webview.start()` 的 `private_mode` **默认 `True`**，文档原话：*"In private mode, cookies and local storage are not preserved"* |
| 4 | 查 `storage_path` | 默认也是 `None` → 数据目录不固定 |

---

## 三、根因

**「记住登录」被前端的存储选择（`localStorage` vs `sessionStorage`）描述得像是前端的事，但它实际上受外壳的 WebView 运行模式控制。**

pywebview 默认跑在**隐私模式**：不持久化 cookie 与 local storage。所以只改前端存储介质是**不够的**——数据根本落不到盘上。

---

## 四、方案

```python
webview.start(debug=args.debug,
              private_mode=False,                                   # ★ 关掉隐私模式
              storage_path=str(ROOT / "data" / "desktop_webview"))  # ★ 固定数据目录
```

两个参数**必须一起给**：只关私有模式而 `storage_path=None` 时，数据目录不固定，同样不可靠。

### 顺带修掉的两个测试陷阱

| 陷阱 | 处置 |
|---|---|
| 自检里的「清本地存储」会**把用户真实的登录态清掉** | 给外壳加 `--storage-path DIR`，测试传 `tempfile.mkdtemp()` 隔离；并加一条断言：跑完前后**用户真实目录内容不变**（实测 `before=['EBWebView'] after=['EBWebView']`） |
| **清完存储必须刷新页面**，否则出现「已登录但存储里没 token」的鬼状态 | SPA 在 `setup()` 阶段就把 token 读进内存了 → 清完 `location.reload()`，轮询等登录表单出现再操作；并把「表单是否真找到并填上 / 按钮是否真点到」作为独立断言暴露（`login_form='filled'` / `login_clicked='clicked'`），否则假失败会伪装成真失败 |

---

## 五、结果

| 用例（`tests/desktop_window_e2e.py`） | 断言 | 实测 |
|---|---|---|
| 第 1 轮 | 真开窗口 → 清空存储（隔离目录）→ 页面上**真登录** → 断言 token 落 `localStorage` | ✅ |
| 第 2 轮（**新进程**，不带任何登录参数） | **不登录也直接进工作台**，且能读到第 1 轮写入的探针值、数据不为 0 | ✅ |
| 隔离 | 测试**没动**用户真实桌面版存储目录 | ✅ `EBWebView` 前后一致 |
| 账号 | 既没新建也没删除 | ✅ 9 → 9 |

窗口套件整体 **46/46**。

> 检验方法必须是**两轮对比**：单轮测试里 `localStorage` 读写永远正常，看起来一切正确 —— 这个 bug 只会在「**下一次启动**」暴露。

## 六、遗留

- 桌面版数据目录 `data/desktop_webview/`（已 gitignore）；换机器/换目录等于换一份登录态，无迁移逻辑（本地个人应用可接受）。
- 与「服务端会话落库」（见《桌面版首次自动登录后数据全是 0》）是**两半**：本节的修复让 token 记得住，那一节让 token 在**新后端进程**里也认得出。**只修一半，症状仍然在。**

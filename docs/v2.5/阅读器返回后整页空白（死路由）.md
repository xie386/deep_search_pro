# 阅读器点「返回」后整页空白（死路由：`go('report')` 少了 s）

> 版本：**v2.5**（小数版 = bug 修补）
> 日期：2026-09-25　范围：`static/index.html` 一行 + 两条静态断言

## 问题

周报阅读页点左上角「← 返回」后，**整页变成一片纯色空白**（导航条还在，内容区全空）；
**点任意一个导航按钮就恢复正常**。用户截图：阅读页正常 → 返回后空白。

## 根因：跳到了一个**不存在的视图名**

项目的视图是 `<div class="view xxx" v-show="view === '<名字>'">` 这套机制，真实视图名一共 9 个：

```
chat  customize  home  kb  profile  reader  reports  skills  tutorial
                                    ↑ 报告页是**复数** reports
```

而我在阅读器里把返回写成了：

```js
function readerBack() { readerItem.value = null; go('report'); }   // ← 少了一个 s
```

`go('report')` 会把 `view` 设成 `'report'` —— **没有任何 `v-show` 匹配这个值** → Vue 把所有
`.view` 都判为隐藏 → 内容区什么都不显示（只剩外层背景色）。点导航按钮时调的是真实视图名
（`go('reports')` 等），于是"一点就恢复"。

> 注意：`go()` 里还有 `location.hash = '#/' + v`，所以现象是"URL 变成 `#/report`（一个不存在的路由）"，
> 刷新一次也还是空白 —— 只有点导航才能出去。

## 方案

1. **改对名字**：`go('reports')`。顺带还有个好处 —— `go()` 会改 hash，而 `hashchange` 里本来就有
   `if (view.value === 'reports') { newReports.value = 0; loadReports(); loadSubs(); }`，
   所以返回时报告列表会顺手刷新一遍（新生成的周报立刻出现在列表里）。
2. **加两条静态不变量防复发**（这类 bug 不报错、不崩溃，只让页面变空，靠肉眼回归很容易漏）：
   - `tests/frontend_setup_exports_check.py` 新增 **不变量 2**：抽出全站所有 `go('x')` 目标与所有
     `v-show="view === 'x'"` 视图名做集合比对，**死路由直接失败**（`'shell'` 是 `go()` 内部会改写成
     `'skills'` 的特例，已在白名单里）。同时带"解析到 ≥5 个目标 / ≥5 个视图名"的自检，防止正则失效后假通过。
   - `tests/m5c_report_reader_frontend.js` 的返回断言从 `'report'` 改成 **`'reports'`**。

**TDD 顺序（先看它红，再改代码）**：改完断言先跑 —— 静态检查报
`go('report') 没有对应的 v-show 视图`、用例报 `goLog=["reader","report"]`（红）；改完 `go('reports')` 后
两边转绿。

## 结果

| 项 | 数字 |
|---|---|
| 静态不变量 | **3 → 5 项全绿**（新增"死路由"与它的解析自检） |
| 阅读器用例 | `m5c_report_reader_frontend` **42/42** |
| 其余前端回归 | `m4a` 56 · `tutorial` 31 · `weather` 51 · `desktop_export` 24 · `setup 导出不变量` 5 · `node --check` OK |
| 死路由审计 | 全站 `go('x')` 目标 6 个，除本次修掉的 `'report'` 外**没有其他死路由** |

## 教训（写下来免得再犯）

**"跳转类"函数的参数是**字符串契约**，拼错了编译器/框架都不会提醒你。**
这类风险的通用解法就是本项目的做法：**把契约变成静态断言**——和之前那条
`tests/frontend_setup_exports_check.py`（模板引用 ⊆ `setup()` 导出，治"漏导出 → 交互静默失效"）
是同一思路：**"静默失效"型 bug 一律用静态检查兜住，别指望人手测出来。**

## 复盘思考题

1. 为什么这个 bug 表现为"空白"而不是"报错"或"停在原页"？`v-show="view === 'x'"` 这套机制在
   跳到一个不存在的名字时发生了什么？
2. 为什么"点任意导航按钮就恢复"能反过来帮助定位根因？（提示：导航用的是哪套名字）
3. 如果项目改用真正的路由库（vue-router），这类 bug 会变成什么表现？**是变好定位了还是更难**？
4. 静态检查里为什么要额外加"解析到 ≥5 个目标 / ≥5 个视图名"这种自检断言？
   举一个"没有它就会假通过"的场景。

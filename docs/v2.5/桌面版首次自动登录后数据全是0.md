# 桌面版首次「记住登录」后账号数据全是 0

> **版本** v2.5（十进制：bug 修补）　**日期** 2026-09-23　**体例** 问题 → 方案 → 结果
> **报障形态** 打开桌面版 → 自动进了工作台、用户名也对（尼古喵喵）→ 但**兴趣/关注/收藏全是 0**；**手动「退出」再登录一次就正常**
> **触及文件** `api/account.py` · `tools/schema_personal.py`（新表 `sessions`）· `front/index.html`（`verifySession`）· `front/desktop/app.py`（失效 token 探针）
> **守住它的用例** `tests/desktop_window_e2e.py`（两轮真数据 + 失效 token）+ `tests/auth_split_e2e.py` [7]（真·新进程校验会话）

---

## 一、问题（用户截图逐条对应）

| 现象 | 成因 |
|---|---|
| 打开就是工作台、用户名显示「尼古喵喵」 | localStorage 里的旧 token **非空** → 前端以为已登录 |
| 工作台「我的兴趣 / 关注品牌商品 / 收藏商品」**全是 0** | 每个接口都吃 **401**，而 `loadMyData()` 里写的是 `if (!r.ok) return;` —— **静默放弃**，页面就留着一堆 0 |
| 天气卡报「未登录或登录已失效」 | 这正是 `get_session()` 抛出的 **401 文案**（铁证） |
| 手动「退出」→ 重新登录 → 一切正常 | 新 token 是**当前进程**签发的 |

---

## 二、排查

| \# | 动作 | 发现 |
|---|---|---|
| 1 | 顺着「未登录或登录已失效」这句文案定位 | 只来自 `get_session()`；说明前端带着 token 请求，但服务端**不认** |
| 2 | 看会话存在哪 | `api/account.py` 的 `_SESSIONS = {}` —— **进程内内存字典**，注释还写着「重启即失效，符合纯个人本地定位」 |
| 3 | 问「那为什么 Web 版没这问题」 | Web 版用户**手动起的服务长期不关**，会话自然一直在；**桌面壳每次重开都会新起一个后端进程** → 旧 token 全失效 |
| 4 | 看前端拿到 401 之后做什么 | `api()` / `loadMyData()` 都是 `if (!r.ok) return;` → 用户看到的是「一堆 0」而不是「登录失效」 |

> 关键洞察：**「记住登录」是两半** —— 前端存住 token（下一节《记住登录在下次启动失效》），**服务端也得认这个 token**。只做前一半，界面看着是登录态，数据却是空的。

---

## 三、根因

**会话的生命周期被绑在了「后端进程」上，而桌面壳每次启动都会换一个后端进程。**

内存字典在「服务长期不关」的场景下工作得很好（所以 Web 版一直没暴露），一旦运行模型变成「每次启动新进程」，它就成了必然失效的设计。

---

## 四、方案（两侧都补，缺一半都不成立）

### 服务端：会话落库

| 改动 | 说明 |
|---|---|
| 新增表 `sessions(token PK, account_id, login_at)` | 90 天有效期；登录时顺手清理过期行 |
| `create_session()` / `get_session()` / `logout()` 改走 SQLite | 登录不再写内存字典 |
| `get_session()` **运行时联查 `accounts`** 取 username/role/display_name | **不存快照**：用户改了昵称/角色要立刻生效，不会读到旧副本 |
| `_ensure_accounts_table()` 统一走 `ensure_tables()` | 建表幂等 |
| `purge_account()` 自省表结构 | 认 `account_id` 列就自动带走 `sessions`（无需改这个函数） |

### 前端：不再「假装已登录」

| 改动 | 说明 |
|---|---|
| 启动先 `verifySession()`（拿 token 调一次 `/api/me/overview`） | **401 就 `forceLogout()` 回登录页** + 提示「登录已失效，请重新登录」 |
| `api()` / `loadMyData()` 的 401 统一走同一处理 | 不再静默 `return` |
| `forceLogout()` **只删 `zx_token/zx_user/zx_role`** | **不能用 `storeClear()`** —— 那会把背景图等用户偏好一起清掉 |

## 五、结果

| 用例 | 断言 | 实测 |
|---|---|---|
| `auth_split_e2e.py` [7] | 会话跨后端重启仍有效 —— 用**真·新进程**（`subprocess` 里 `from api.account import get_session`） | **43/43** ✅ |
| `desktop_window_e2e.py` 第 1 轮 | 用页面存着的 token **真读到账号数据**（不为 0） | ✅ |
| `desktop_window_e2e.py` 第 2 轮（**全新后端进程**） | 拿到的数据与第 1 轮**一致且非 0** | ✅ |
| 失效 token 探针 | 存假 token → 页面自刷 → 必须回登录页 + 提示 + **假 token 被清** | ✅ |
| 会话行回收 | 测试登录产生的会话行在 `finally` 里按「本账号 + 登录时间 ≥ 测试开始」清掉，**绝不碰用户真实登录** | ✅ 回收 1 行 |
| 账号数 | 跑前跑后不变 | ✅ 9 → 9 |

窗口套件整体 **46/46**；`auth_split_e2e` **43/43**；CLI 版 `dspro`（token 同样落库）**45/45**。

> ⚠️ 测试切忌这样写：**「进了工作台」从来不算「记住登录」**，必须「能真读到数据」才算。断言「后端重启后 token 仍有效」也**必须用真·新进程**，**别 reload 模块**（reload 语义不可靠，旧函数对象仍指向旧 module dict，验不出真问题）。
> 另一个坑：桌面壳里做「刷新页面」的探针动作要用**页面自己的 `location.reload()`**（`setTimeout` 包一层），**不要用 `window.load_url()`** —— pywebview 的 `load_url` 走 CoreWebView2，页面已就绪时实测抛 `WebViewException: Main window failed to start`，探针会以「页面没刷新」的假象失败。

---

## 六、遗留

- **升级后第一次打开桌面版需要重新登录一次**：当时 localStorage 里那个 token 是**内存版后端**签发的，已经找不回来了（新表里没有它）。这是一次性的。
- 会话有效期 90 天是拍的；本地单机个人应用没有再引入「滑动续期」的必要。

---

## 七、复盘思考题

1. 为什么「内存字典存会话」在 Web 版一直没暴露问题，到了桌面版就必然失效？（提示：运行模型变了 —— 谁在启动后端进程）
2. 为什么 `get_session()` 要**运行时联查 `accounts`**，而不是把 username/role 一起存进 `sessions` 表？
3. 为什么 401 不该被前端「静默 return」？在这个 bug 里，静默吞掉 401 把什么信号变成了「一堆 0」？

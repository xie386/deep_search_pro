# 桌面版图标显示异常与双击入口的三次报障

> **版本** v2.5（十进制：bug 修补 + 小功能）　**日期** 2026-09-22～23　**体例** 问题 → 方案 → 结果
> **报障形态** ① 任务栏/窗口显示 **Python 图标**；② 换成设计稿后，任务栏/托盘图标变成**彩色噪点**；③（用户提问）**能不能只把 `desktop.cmd` 这个文件的图标换掉**
> **触及文件** `static/desktop/make_icon.py` · `static/desktop/assets/`（`icon-master.svg` / `icon.png` / `icon.ico` / `icon-meta.json`）· `launcher/desktop.cs` · `build_launcher.py` · `desktop.exe` · `app.py`
> **守住它的用例** `tests/desktop_shell_e2e.py`（exe 存在 / PE 子系统=GUI / ico 全 BMP 帧）

---

## 一、问题（三个，各自独立）

| # | 现象 | 用户侧感受 |
|---|---|---|
| 1 | 应用跑起来后任务栏/窗口左上角是 **Python 图标** | 「这不是我的应用」 |
| 2 | 换成设计稿后，大尺寸看着正常，**16/48px 提取出来是雪花噪点** | 任务栏/托盘图标「糊了」 |
| 3 | 问「能把 `desktop.cmd` 的图标换了吗（只换这一个）」 | 想要一个像样儿的双击入口 |
| 附 | 小尺寸可读性差 → 试过裁边放大 → **32/48px 图标变成"削角方块"** | 比糊更糟 |

---

## 二、排查

| \# | 动作 | 发现 |
|---|---|---|
| 1 | 查 pywebview 是否支持 Windows 图标 | 文档写 `icon=` *仅 GTK/QT 支持*，但 **WinForms 后端其实实现了**（包内 `webview/platforms/winforms.py` 有 `self.Icon = ...`）→ 不传它就从 `sys.executable` 抠**解释器自己的图标** |
| 2 | 查任务栏归组 | 不做 `SetCurrentProcessExplicitAppUserModelID` → 壳被当成 `python.exe` 归组，图标与名称都跟着 Python 走 |
| 3 | 用 `.NET System.Drawing.Icon` 读生成的 `.ico` | 读出来是噪点 → **PIL 默认把每帧写成 PNG 压缩帧**，而 `.NET`（pywebview WinForms + PowerShell）**只认 BMP 帧** |
| 4 | `struct` 遍历 ICO 目录逐帧验 | 证实 7 帧全是 `\x89PNG`；大尺寸看着正常，所以肉眼查不出 |
| 5 | 查 `.cmd` 图标机制 | 图标**按文件类型共享**：`.cmd → cmdfile → DefaultIcon = imageres.dll,-68`，改它 = **全系统所有 .cmd 一起变**；Windows **没有「单个 .cmd 自带图标」的机制** |

---

## 三、根因

1. **窗口图标**：pywebview 在 Windows 会回退到解释器图标 → 看起来就是 Python。
2. **噪点**：`.ico` 的帧格式不对（PNG 压缩帧 ≠ BMP 帧），`.NET` 解不出来。
3. **`.cmd` 不能单文件换图标**：Windows 的图标是**按文件类型**（注册表 DefaultIcon）绑定的，没有 per-file icon 存储；而且双击 `.cmd` **必然弹一个控制台黑窗**——这也意味着用户可能「不小心点到黑窗的 X 把整个应用关掉」（真实发生过）。

---

## 四、方案

### 1. 图标三关（去底 → 小尺寸 → 徽标对位）

| 关 | 做法 |
|---|---|
| **去底** | 只把**与外边界相连**的近白区域变透明（四角 flood fill → 哨兵色 → 置 alpha=0），再对二值 alpha 做 ~1px 高斯模糊保住原稿抗锯齿边缘 → 否则贴深色任务栏会露**白方块/浅色光边**，而猫脸那圈白也不会被误伤 |
| **小尺寸** | **默认不补偿**（`SMALL_CROP = 0.0`）：裁边 8% 能把图形占比做大，但**圆角方块一裁就变成"削角方块"**（32/48px 实测），收益远小于损失。开关留着（0.03~0.05 还算安全），必须**肉眼过一遍** |
| **徽标对位** | 把设计稿里橙点的**归一化圆心与半径**测出来写进 `icon-meta.json` → 运行时「忙碌指示灯」**同心叠在同一个点上**（外圈白描边），并**按设计稿点放大 ~1.7 倍**（否则 64→16 缩放后消失） |

### 2. `.ico` 必须写 **BMP 帧**

```python
img.save(ico_path, format="ICO", sizes=[16,24,32,48,64,128,256], bitmap_format="bmp")
```

代价：27KB → **361,102 B**（7 帧全 BMP）。用 `struct` 逐帧断言**不是 PNG** 作为回归守卫。

### 3. 三处图标分别接上（两套独立入口，别只换一个）

| 位置 | 接法 |
|---|---|
| 窗口 / 任务栏 | `webview.start(icon=".../icon.ico")` + **`SetCurrentProcessExplicitAppUserModelID("xieky.zxintel.desktop")`**（创建窗口前设） |
| 托盘（pystray） | 读 `assets/icon.png`（**PNG**，与窗口是两套入口）；运行时 `icon.icon` 与 `icon.title` 都可改 → 忙碌状态叠加琥珀点 + tooltip 写「正在生成…」 |
| `desktop.exe` 文件图标 | 编译时 `/win32icon:assets/icon.ico` **把图标编进 PE 资源** |

### 4. 单文件图标问不出结果 → 编一个属于自己的启动器

```
static/desktop/launcher/desktop.cs   （用系统自带 csc.exe 编译，零额外安装）
static/desktop/build_launcher.py     → 产出 desktop.exe
```

- `/target:winexe` → **PE 子系统 = 2（GUI）**，双击**不弹黑窗**；实测 `desktop.exe` = **367,616 B**（图标在 PE 资源里，所以比纯代码的 ~34KB 大）；
- `/win32icon:assets/icon.ico` → 文件本身就是我们的图标；
- 它只做一件事：定位 `.venv\Scripts\python.exe`，以项目根为 cwd 启动 `static/desktop/app.py`，注入与 `.cmd` 相同的环境（强制 UTF-8、清代理/PYTHONPATH），参数可透传；
- 启动器**自己立刻退出**，app 继续跑；无控制台时 stderr 可能为 `None` → `_install_crash_logger()` 把未捕获异常写 `desktop.log`。
- `desktop.cmd` 保留作后备（排查时能看到完整输出）。

### 5. ★ `.cmd` 必须**纯 ASCII**（连 `rem` 注释也不能有中文）

cmd.exe 按**当前控制台代码页**（中文机 GBK）解析批处理文件，UTF-8 中文字节被误读后会**吃掉后面的字符、并两行**，症状毫不相关：

| 症状 | 实际原因 |
|---|---|
| `'local' 不是内部或外部命令` | `setlocal` 被吃掉 |
| `'p\' 不是内部或外部命令` | 路径行被截断 |
| 报「缺少 pywebview」/ 找不到 `app.py` | `%HERE%` 被清空 → 退化成系统 python；或 `ROOT` 层级退错（`static/desktop/` → 项目根要退**两级**） |

现状校验：`desktop.cmd` **非 ASCII 字节数 = 0** ✅（文件名也保持 ASCII）。

## 五、结果

| 检查 | 结果（本次实测复核） |
|---|---|
| `icon.ico` 尺寸档位 | 16 / 24 / 32 / 48 / 64 / 128 / 256 ✅ |
| `icon.ico` 帧格式 | **7 帧全 BMP** ✅（`struct` 逐帧验签，无一 PNG） |
| `icon.ico` 体积 | 361,102 B |
| `desktop.exe` | 367,616 B，**PE 子系统 = 2（GUI，无黑窗）** ✅，图标已编入 PE 资源 |
| `desktop.cmd` | 1,514 B，**非 ASCII 字节 = 0** ✅ |
| 真窗口启动路径 | 日志出现「应用图标：icon.ico」✅（不设时会静默回退成解释器图标，单测全绿也看不出来） |
| 忙碌/空闲图标 | 两张图**字节不同** ✅ |
| 外壳套件 | **108/108** |

**诚实的观感结论（不拿「测试全绿」暗示小尺寸也可读）**：**64px 以上猫脸很清楚；32px 能认出；24px 是「白脸 + 耳朵」的轮廓；16px 只剩绿方块上一个白点**——任何图标在这个尺寸都保不住细节，作为「一眼认出是我们的图标」够用。

---

## 六、遗留

- **16px 救不回来**：不建议为了让 16px 好看把图形撑到画布顶（会与相邻托盘图标比例失调）。
- **打包分发**仍未做：`.venv` 实测 5.2GB（torch + chromadb + bge + 模型缓存）→ **PyInstaller 不划算**，建议 Inno Setup 安装包/绿色包，或轻量引导式启动器。
- **桌面/开始菜单快捷方式**：`.lnk`（图标 `assets/icon.ico`、起始位置=项目根）属「动用户环境」，做前需确认（用户本轮已手动建好一个）。

## 七、复盘思考题

1. 为什么 `.ico` 的帧格式错了，**大尺寸看着正常、只有小尺寸出问题**？这种「部分可见的故障」为什么必须用**代码断言**（`struct` 逐帧验签）而不是肉眼验收？
2. 为什么「裁边放大让小尺寸更好认」这个看似合理的优化，对**圆角方块类**设计反而更差？什么样的设计稿才适合开这个开关？
3. 为什么 Windows **没有**「单个 `.cmd` 自带图标」的机制？想给双击入口换上自己的图标，为什么「编一个自己的 exe」比「改注册表」更对？（提示：改注册表的影响范围）

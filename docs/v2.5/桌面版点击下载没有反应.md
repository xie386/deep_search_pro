# 桌面版「点下载没反应」：WebView2 不支持浏览器式下载

> **版本** v2.5（十进制：bug 修补）　**日期** 2026-09-22～23　**体例** 问题 → 方案 → 结果
> **报障形态** 周报列表的 `MD↓ / PDF↓`、AI 回答的「导出MD / 导出PDF」——**点了没有任何反应**，文件哪儿都找不到
> **触及文件** `front/index.html`（`saveFromUrl` 收口）· `front/desktop/app.py`（`save_binary_b64` / `--selftest-download` / `--selftest-save-dir`）
> **守住它的用例** `tests/desktop_export_logic.js`（24 项）+ `tests/desktop_window_e2e.py`（真落盘、二进制逐字节比对）

---

## 一、问题

| 现象 | 关键线索 |
|---|---|
| 点「导出MD / 导出PDF」没反应 | **后端日志里能看到 `GET /api/download?... 200 OK`** |
| 周报列表 `MD↓ / PDF↓` 同样没反应 | 同上，请求真的发出去了 |
| 文件在「下载」文件夹、桌面、临时目录里都找不到 | 没有下载 UI、没有落盘 → **被静默丢弃** |

> 排查口诀：**「点了没反应 + 后端日志有 200」= WebView2 把下载吞了**，不是接口问题、不是路径问题、不是权限问题。

---

## 二、排查

| \# | 动作 | 结论 |
|---|---|---|
| 1 | 用浏览器打开同一页面点导出 | **正常下载** → 排除接口/路径/权限 |
| 2 | 看后端访问日志 | `GET /api/download 200 OK` → 请求确实到了、响应也确实回了 |
| 3 | 在桌面壳里用 devtools 看网络与页面状态 | 请求正常、无 JS 报错、**页面也没有任何下载动作** |
| 4 | 结论 | pywebview 的 **WebView2** 不是完整浏览器：**不支持浏览器式下载**（`<a download>` / `location.href` 指向文件都无效），请求发出去后响应被丢弃 |

---

## 三、根因

前端把「取文件」这件事交给了浏览器的下载机制，而**桌面壳里的 WebView2 没有这个机制**。

而前端的下载出口不止一个（AI 回答导出、周报列表两处按钮），**只修一个出口 = 留一半 bug**。

---

## 四、方案

### 1. 所有取文件出口收口到一个前端助手 `saveFromUrl(url, filename)`

```
桌面分支：fetch 回字节 → 分块 base64 → 调 pywebview.api.save_binary_b64()
          → 外壳弹「原生另存为」（默认目录 = 用户「下载」）
网页分支：退回 <a download>（比 location.href 好：不会整页跳转）
```

- **分块 base64**：`String.fromCharCode.apply` 每次 0x8000 字节（否则大文件爆栈）。
- **边界**：**「取网络」留在前端**、只有「写文件」交给外壳 —— 这样既不多出一条绕过鉴权的请求通道，也不用把 token 搬出页面。
- 逐一 grep 前端所有出口：`:href` / `location.href=` / `window.open` / `.download`，**一个都不能漏**。

### 2. 让「点下载 → 真落盘」可以被自动化断言（两个测试缝隙）

| CLI 参数 | 作用 |
|---|---|
| `--selftest-save-dir DIR` | 让原生「另存为」**不弹窗**、直接写该目录（否则自动化会卡在无人点击的对话框上） |
| `--selftest-download NAME` | 登录后调用页面**真实的** `saveFromUrl()` 下载 `output/<账号>/<NAME>`，外壳回写文件字节数 |

## 五、结果

| 用例 | 覆盖 | 结果 |
|---|---|---|
| `tests/desktop_export_logic.js` | `saveFromUrl` 两条分支（网页下载 / 桌面另存为）+ base64 字节一致（**含 200KB 分块**）+ 取消/失败/404 异常路径 | **24/24** |
| `tests/desktop_window_e2e.py` | 拿账号里**已有的真实周报**做探针：点下载 → 原生另存为 → 检查落盘文件与源文件**二进制逐字节比对** | ✅ |

---

## 六、遗留

- **拖文件进窗口入库**（待办）：WebView2 默认「拖文件 = 导航到该文件」会把页面顶掉，必须在壳里拦掉这个导航 —— 属另一件事，未做。
- 剪贴板/图片类导出（如导出 PNG）目前没有需求；`save_binary_b64` 已是通用通道，加导出类型不用改外壳。

---

## 七、复盘思考题

1. 为什么「请求 200 OK」**不能**证明「下载成功」？这两件事分别由谁负责？
2. 为什么要把「取网络」留在前端、只把「写文件」交给外壳？如果反过来（外壳代发请求）会破坏什么？
3. 为什么这类 bug 必须靠**自动化断言真落盘**来守？（提示：`.venv` 里没有的东西，肉眼看不见）

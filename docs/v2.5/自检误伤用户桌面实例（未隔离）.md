# 自检误伤用户正在运行的桌面实例（进程与数据目录都没隔离）

> 版本：**v2.5**（小数版 = bug 修补）
> 日期：2026-09-25　范围：`tests/desktop_shell_e2e.py` + `static/desktop/app.py`（日志目录可覆盖）

## 问题

用户报告：**修复期间他的桌面版连带后端（PID 8884）自己不见了**，而且不是他手动退出的。

排查日志（`static/desktop/desktop.log`，**自检与用户实例共用这一份**）看到：

```
13:16:02 [窗口] 点 X → 收进托盘（托盘菜单「退出」才真正退出）
13:16:06 [后端] 关闭本次启动的 uvicorn (pid=8884)…
13:16:06 已退出。
```

即：**用户实例收到了一个"窗口关闭"事件** → 走了"托盘不可用则放行关闭"的兜底（外壳设计里
为了避免"关不掉"特意保留）→ 于是**连自己起的后端一起关掉并退出**。没有 `taskkill` 的痕迹，
所以不是测试直接杀它 —— 但触发几乎可以肯定来自与此同时在跑的自检。

## 根因：自检与用户实例**没有隔离**（三处）

| # | 没隔离的东西 | 后果 |
|---|---|---|
| 1 | **WebView2 用户目录**：自检起的临时外壳实例用的是**默认 `storage_path`**（`data/desktop_webview`），而用户实例正开着它 | 两个 pywebview/WebView2 抢同一个 user-data-dir —— 实测就是这一刻用户窗口收到了异常关闭事件（`desktop_window_e2e.py` 早就带 `--storage-path` 临时目录，`desktop_shell_e2e.py` 漏了） |
| 2 | **日志文件**：`desktop.log` / `backend.log` 都是 `static/desktop/` 下的**固定路径**，双方都往里写 | ① 日志交错，用户实例的记录里混进测试的记录（这次就是靠这份交错日志才还原出时间线）；② 更危险的是自检要**按日志解析"本次实例的后端 pid"**（`_backend_pid()`），一旦读到用户的 pid，后面的 `taskkill /F /T` 就可能真去杀用户的进程 |
| 3 | **没有"用户实例在跑吗"的判断**：`[16] 真机：杀掉后端 → 断言自动拉回` 会**开一个真窗口**并杀掉端口持有者 | 在用户正用着应用时跑它，纯属添乱 |

## 方案（三处一起补）

1. `static/desktop/app.py`：日志目录**可被环境变量覆盖** ——
   ```python
   LOG_DIR = Path(os.environ["ZX_DESKTOP_LOGDIR"]) if os.environ.get("ZX_DESKTOP_LOGDIR") else HERE
   BACKEND_LOG = LOG_DIR / "backend.log"        # log() / 异常钩子 / 托盘"打开日志" 全走 LOG_DIR
   ```
2. `tests/desktop_shell_e2e.py` 新增 `[0] 测试隔离` 段：`tempfile.mkdtemp()` 出一个临时目录 →
   设 `ZX_DESKTOP_LOGDIR` → 再 `load_shell()`（这样**在进程内**跑的那些段落也写临时日志）；
   临时外壳实例同时带上 `--storage-path <临时>/webview`。
3. 新增 `_user_instance_running()`（判据 = 默认后端端口 **8123** 或锁端口 **9123** 已被占用）：
   检测到用户在跑就**跳过 `[16]` 真机重启段**并打印醒目提示（"要跑完整自检请先把桌面版从托盘退出"）。

## 结果（实测）

| 项 | 结果 |
|---|---|
| 自检总体 | **107 通过 / 0 失败**（跳过了 [16] 那 7 项；无用户实例时完整为 **114 项**） |
| **[0] 段自己断言隔离** | ✅ 日志目录已改到 `C:\Users\ZQK\AppData\Local\Temp\zx_shell_e2e_*`；✅ `sh.LOG_DIR` 确实指向临时目录 |
| **用户实例是否被碰** | ✅ 自检开始前 `8123=PID 20256 / 9123=PID 30192`，**结束后一模一样** |
| 日志是否还交错 | ✅ 用户的 `desktop.log` 最后一行仍是自己的记录（`13:43:45 [窗口] 加载 …/&_=1790315015`），测试的日志全部落在临时目录 |
| 顺带确认 | 用户日志里那条 URL **带 nonce** → 前一篇（WebView2 缓存）的修复在他的实例上确实生效 |

## 教训

- **"测试不许动用户的进程与数据"要落到机制上，不能靠自觉**：进程类测试的三个必查项 =
  ① 用户可见的资源目录（这里 = WebView2 storage）② 共享的日志/状态文件 ③ "用户正在使用中"的探测。
  项目里原有"测试不许动用户数据"的纪律，这次把它扩展到了**进程与运行环境**。
- **共享日志既是排查工具也是隐患**：它能还原事故时间线，但也是"按日志猜 pid → 误杀"的入口。
  两边都想要时，正确做法是**内容隔离**（各自一份），而不是"反正都写同一条"。

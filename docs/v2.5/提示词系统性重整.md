# 提示词系统性重整（追加式迭代 → 8 段结构）

> **版本** v2.5（十进制：现有功能优化 + bug 修补）　**日期** 2026-09-23～24　**体例** 问题 → 方案 → 结果
> **触发** 用户提问：「主 agent 的提示词迭代都是在原来的提示词后面追加内容，可能导致提示词过于繁琐或者上下矛盾影响 agent 判断，是否需要做系统性编写整改」
> **触及文件** `prompt/prompts.yml`（**重写**）· `agent/build_context.py` · `agent/digest_engine.py` · `tests/test_prompt_contracts.py`(新) · `tests/test_assembly.py`
> **配套清理** `agents_docs/agents_docs/尼古喵喵/`（写歪目录）· 测试残留账号与目录
> **守住它的用例** `tests/test_prompt_contracts.py`（11 项）· `tests/m4c_cli_e2e.py`(109) · `tests/m5_abilities_e2e.py`(43)

## 一、问题（不是「太长」，是**同一事实有多份、且互相矛盾**）

| # | 问题 | 具体表现 |
|---|---|---|
| 1 | **一个事实散在 4 处** | 「CLI 怎么调」在 ① `prompts.yml`（513 字）② `build_context.py` 注入块（187 字）③ `tools/shell_executor.py` 的 `@tool` 文档串（1349 字，**每次请求都发给模型**）④ 每轮能力卡（1644~2499 字）四处各写一份 → 改一处忘三处 |
| 2 | **与 v2.0 路由设计脱节** | M5b 路由会把未命中工具的说明压成「**仅名称**」，而静态提示词却写「以【可用命令行工具】区块**列出的**为准」→ 模型倾向「没详细说明 = 不能用」，**该调的不调** |
| 3 | **陈旧/矛盾文本仍在生效** | `our_products`（公司侧早已迁 SQLite `company_products`）、`MySQL`、`ragflow` 占位段、文件头写着「M1 公司侧」、配置里还留着 changelog、`memory_initializer` 注释错位 |
| 4 | **★ YAML 块标量里 `#` 是正文，不是注释** | 老版有 **5 个 `#` 开头的块**（`# 路由原则（关键）：` 及 3 条规则、`# 两类数据互不混淆：…`）——它们**全部作为正文发给模型**，等于「废案规则」一直在生效 |

### 证据：追加式迭代已经**写坏过真实数据**

审计时发现磁盘上有 `agents_docs/agents_docs/尼古喵喵/MEMORY.md`（1270 字节）+ `SKILLS.md`（254 字节，**模型编造**的技能清单）——**嵌套了一层目录**的歪路径。根因链：

```
提示词写：更新 agents_docs/{username}/MEMORY.md      ← 带前缀的写法
而 write_agent_doc(filename) 的基准目录**就是** agents_docs
→ 路径被拼成 agents_docs/agents_docs/{username}/MEMORY.md
→ 越权校验通过、返回「写入成功」（假成功）
→ _get_memory_text() 读 agents_docs/{username}/MEMORY.md **永远读不到**（记忆白写）
```

同一类问题的「静默」特征：**写入自报成功、读取永远为空**，不报错、不告警。

## 三、根因

**「每个里程碑往后追加一段」这个迭代方式本身**：

1. 追加的每段都要把上下文再讲一遍 → **副本越攒越多**（问题 1）；
2. 追加者只看「我要加什么」，不看「这句话与既有段落是否冲突」→ **矛盾与陈旧文本沉淀**（问题 3）；
3. YAML 块标量里 `#` 不构成注释 → 追加者以为自己在「写注释/留废案」，实际**都在生效**（问题 4）；
4. 章节顺序按「写入时间」而非「模型读的顺序」排列 → **工具调用纪律被排到第 28 块**，前面全是角色与话术（问题 2 的土壤）。

## 四、方案（方案 A：系统性重排）

### 1. 主 Agent 改成 **「角色 + 8 段」**，按「模型读的顺序」重排

| 段 | 作用 | 字数 |
|---|---|---|
| 角色 | 一句话定位 | 47 |
| **① 指令优先级（冲突时从高到低）** | 事实与安全 ＞ 用户选中技能 ＞ 本轮注入块 ＞ 本文其余风格约定 | 102 |
| ② 你的职责 | 需求理解 + 调度专家助手（含「先澄清公司/个人视角」） | 209 |
| ③ 来源可追溯（硬要求） | 🔍网络 / 🗄️公司库 / **🗄️个人库** / 📚知识库 四类标记 | 305 |
| **④ 工具使用总则（新增）** | 含**先后顺序**：问题指向用户自己账号里的对象 → **先用账号内工具取真实数据**，不足再联网 | 284 |
| **⑤ 你手上的三类工具（新增）** | 明确「**只列名称不等于不可用**」 | 475 |
| ⑥ 记忆维护 | 必须调用写文档工具，禁止只口头确认 | 307 |
| ⑦ 技能纪律 | 用户 `/` 选中的说明书，本轮一次性 | 274 |
| ⑧ 输出结构 | 默认简报体 | 198 |

> **工具相关的两段从第 26/28 位提到第 4/5 位**，并把「怎么调」的机械细节**全部移出**（见维护纪律②）。

### 2. 子 Agent：删掉与工具文档串重复的机械细节

表名 / 列名 / 行数上限 / JSON 列 / `json_extract` / 检索参数语义 → 一律改为「以工具说明为准」。

### 3. 措辞可执行化（批次 1）

| 位置 | 改前 | 改后 |
|---|---|---|
| `db` 子 Agent | 「引导用户在前端**左栏**维护」（v2.0 前端已是顶部导航、入口叫「🏢 公司信息」） | 「以工具说明为准」+ 指到「**公司信息**」页 |
| `personal` 子 Agent | 「**请求主 Agent 调度**【网络搜索助手】」（子 Agent 无 `task` 工具 → 不可执行） | 「在结论里写明「需要联网补充：<要查什么>」，由主 Agent 据此调度」 |
| `tavily` 子 Agent | 「**至少从 3 个不同角度检索**」（硬下限，直接烧额度） | 「**先精后宽**：先 1~2 条精准检索，覆盖面不足才补查，整轮 ≤5 次」 |
| `tavily` 回传格式 | 「标注出自哪类来源网址」（类别 ≠ 出处） | 「**逐条标注「来源名称 + 日期 + URL」**」（与主 Agent 的来源清单要求对齐） |

### 4. 契约单一来源 + 契约测试（批次 3）

- **周报头部格式契约**抽成常量：`agent/digest_engine.py` 的 `SCAN_LINE_CONTRACT` / `SCAN_LINE_RE` 相邻定义 + **import 期自检**；生成侧（`prompts.yml` digest 段 + task_prompt）与解析侧共用同一措辞 → 专治 M4 期「周报内容齐全、统计却记 0 条」那类**静默解析失败**。
- **新增 `tests/test_prompt_contracts.py`（11 项，纯静态 0.2s）**：① 周报契约三处一致；② 能力描述三种写法（单命令箭头 / 两步链取第一步 / 关键词行）都能被解析；③ 记忆与技能路径必须是「相对 agents_docs」；④ **防腐断言**（`our_products`/`MySQL`/`ragflow` 不得回流；`--output`/`argv=[` 等机械细节不得回流进常驻提示词；优先级声明 / 先后顺序 / 三类工具 /「只列名称不等于不可用」不得被后续追加冲掉）。

### 5. 文件头写进 **3 条维护纪律**（防回潮）

```
① 本文件是**静态**提示词：只放「角色 / 原则 / 纪律」；本轮相关内容（人格、记忆画像、
   可用 CLI 清单、映射示例、技能说明书）一律由 agent/build_context.py 在 invoke 期注入
② CLI 调用的机械细节只写两处：tools/shell_executor.py 的 @tool 文档串 + build_context.py
   的【可用命令行工具】注入块。**此处不重复**
③ 改完任何一段：跑 tests/m4c_cli_e2e.py + tests/m5_abilities_e2e.py；动了工具/路由措辞再跑
   真机 tests/m5_probe_e2e.py
```

## 六、遗留（诚实说明）

1. **子 Agent 没有减到 30%**：去重本身减了约 700 字，但同批新增的纪律（引用格式、检索预算、顺序约束）又加了约 700 字，**净减 175 字**。达成的是「**不再随 schema 漂移**」，没达成「字数控减」——真要再减就得删纪律。
2. **信念锚必须留在注入块**（`build_context.py`）：① 本区块出现 = 本机确实装了并已放行 ②**优先调用** `run_shell_command` 取真实数据 ③ 不要在没有任何工具返回时声称该命令不可用。它们是**条件性强度要求**，放进静态提示词会变成无害的常驻文本。
3. **真机探针本身是随机的**（同日两轮失败集合都不同），它只适合做「A/B 对照」，不适合做「单次达标判定」。

## 七、复盘思考题

1. 为什么「同一事实写 4 处」比「写得长」更致命？（提示：改一处忘三处之后，哪一处才是真的在生效）
2. YAML 块标量（`key: |`）里 `#` 开头的行是什么？为什么「留一段废案当注释」会变成「一直生效的规则」？
3. 提示词里写路径时，为什么要先确认**工具的实现基准目录**？这套「写入自报成功、读取永远为空」的故障是怎么骗过所有测试的？
4. 「探针命中从 9/10 掉到 5/10」为什么**不能**直接归因于提示词改动？要做出可信归因，最小的实验设计是什么（同日？同模型？同桩？阈值多少）？

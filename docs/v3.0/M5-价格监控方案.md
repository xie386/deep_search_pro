# M5 · 价格监控 方案

> **状态**：✅ **定稿**（2026-09-25 用户裁决 D1~D6，见 §零；§九 无待定项）
> **对应规划书**：§2 P5 / §3 A6 / §5 M5｜**依赖**：M1（阶段 2 复用 API 适配器）、M4（写价工具走计数器与审计）、M3（画像里的价格敏感度已影响周报权重）
> **一句话**：把"收藏的商品 / 公司的产品"从**一个静态参考价**，变成**有历史、有阈值、会提醒、能写进周报**的价格闭环 —— 且**第一阶段零外部依赖就能用**。
> **范围（用户定）**：**三样都做** —— ① 个人收藏商品目标价提醒 ② 公司产品与竞品价格对比 ③ **把周报里的价格情报结构化成价格条目**
> **采集（用户定）**：**阶段 1 = 手动 + 对话记价（零依赖）**；**阶段 2 = 用户自配价格 API**（等你手上有可用源再接）
> **提醒（用户定）**：**桌面通知 + 周报附录**

### 0.2 助手已定（依据 §二 取证 + §四 选型）

| # | 结论 |
|---|---|
| C1 | **价格必须带来源类型**：`source_type ∈ manual \| api \| news`。资讯里的价格 **≠ 当前售价**，UI 与周报都必须标注来源，**禁止把 news 价当现价**（这是最容易误导用户的地方） |

## 一、目标与验收判据

| # | 目标 | 验收判据（可测） |
|---|---|---|
| G1 | **台账**：价格有历史，能看涨跌 | 收藏页"更新价格"→ `price_history` 新增一条；页面显示"较上次 ↓12%"（两条记录即可算出） |
| G2 | **对话记价** | 对 Agent 说"米诺地尔跌到 89 了"→ 调 `record_price` 落库（关联到收藏 #N）→ 回答里确认；**同一价格重复上报不新增重复行**（同值同天去重） |
| G3 | **阈值提醒 + 去重** | 设 `target_price=100`、记 `89` → 产生**一次**提醒（桌面通知 + 周报附录各一处）；再记 `89.5`（未创新低）→ **不再提醒**；记 `85`（创新低）→ 再提醒一次 |
| G4 | **来源可区分** | 每条价格带 `source_type`；UI 上 `news` 价显示为"资讯价（来源：周报 #12）"，**不显示成"当前价"**；静态断言：没有任何读取路径把 `news` 当 `manual/api` |
| G5 | **竞品对比** | 记自家产品 100、竞品 85（经 `mapped_product_ids` 关联）→ 页面/工作台显示"竞品低 15%"；竞品低于我方超过阈值 → 触发提醒 |
| G6 | **周报价格情报结构化** | 一次真实周报生成 → `price_mentions` 里出现结构化条目（实体 / 价格 / 来源 URL / 日期），且 `source_type='news'`；**不额外增加模型调用**（断言调用次数不增） |
| G7 | **配置导向（阶段 2 预留）** | 价格源配置表里**不出现厂商名**；新增源=填 URL 模板与字段映射（静态断言 + 一条 mock 用例） |
| G8 | **失败不静默（阶段 2 预留）** | 源超时/限流/字段缺失 → 明确提示并落 `price_alerts` 的 `check_error`，**不静默跳过** |
| G9 | **隔离与清理** | 全部按 `account_id`；`purge_account()` 连带清理新表（自省表结构） |

### 2.2 缺口（M5 要补的正是这些）

| 缺口 | 证据 | 影响 |
|---|---|---|
| **没有"能定位外部商品"的字段** | `products`/`watchlist`/`company_products` 里**无** `url`/`sku`/商品 ID（全表 grep 无命中） | 阶段 2 无法知道"去哪儿查这个商品的价" |
| **没有目标价/阈值** | 备注栏写的是"为什么收藏？关注点？预算？"——自由文本，不可判定 | 无法触发提醒 |
| **没有价格历史** | `price` 是单值，改一次覆盖一次 | 无法判断"是不是真跌了"、无法看趋势 |
| **没有任何价格源与检查任务** | 全项目无抓价/查价代码（grep 价格/price 仅命中 schema、画像读取、周报权重） | 只能手动 |
| **Agent 不能写个人库** | `tools/personal_tools.py` 三个工具**全是只读**（`list_personal_tables`/`get_personal_data`/`query_personal_db`） | "对话记价"需要新工具（C4） |
| **周报里的价格是纯文本** | 周报按权重收录降价类动态，但价格散在正文里 | 无法按商品聚合、无法回溯（C5 要补） |
| **没有提醒去重机制** | 无 `price_alerts` 类表 | 会重复打扰 |

### 2.3 外部现实（决定了 C2/C3）

- 主流电商（淘宝/京东/拼多多）**不开放**个人可用的价格 API；
- 有历史价的第三方（Keepa / 慢慢买 / 什么值得买等）**多为付费或灰色**；
- **Tavily 是搜索不是价格源**：返回网页文本，不保证含当前价，且**烧额度**（M4 正在为这件事补计数器）；
- 爬虫 = 反爬 + 字段漂移 + 法律灰色 + 长期维护 → 规划书 §6 已标"外部依赖最重"，**不做**（C2）。

## 三、设计（三块 + 一个共同底座）

### 3.1 共同底座：台账（价格历史 + 来源）

```
                    ┌──────────────── 统一台账 ────────────────┐
 ① 手动更新（前端按钮）                     price_history
 ② 对话记价（record_price 工具）  ─────▶   (item_type, item_id, price,
 ③ 周报价格情报（digest 结构化块）            source_type, source_ref, observed_at)
 ④ 阶段 2：自配 API 检查           ─────▶   price_alerts（触发历史 + 去重 + 错误）
                    └──────────────────────────────────────────┘
                                  │
        ② 提醒：桌面通知 + 周报附录 ─┘
```

**item_type**：`product`（个人收藏）/ `company_product`（自家产品）/ `competitor_product`（竞品）
**source_type**：`manual`（人填/对话说）/ `api`（阶段 2 自配源）/ `news`（周报资讯价）

### 3.2 ① 个人收藏目标价提醒

- 加列：`products.url`、`products.target_price`、`products.alert_drop_pct`、`products.monitor_enabled`
- 记价 → 与**上一次**比较 → 若"首次跌破 `target_price`"或"创历史新低"→ 触发提醒（§3.5 去重）
- 前端：收藏卡片显示"当前记价 / 较上次 ±X% / 目标价"，并提供**「更新价格」**（就地输入，一次写入一条历史）

### 3.3 ② 公司产品与竞品价格对比

- 加列：`company_products.url`、`company_products.target_price`、`company_products.monitor_enabled`
- 竞品价格也走同一台账：`item_type='competitor_product'`，通过 `mapped_product_ids` 与自家产品关联
- 展示：工作台/公司页显示"竞品 X 比我方低 N%"；规则：竞品低于我方超过阈值（默认 10%，可配）→ 触发提醒

### 3.4 ③ 周报价格情报结构化（C5：不额外调模型）

- 在 digest 的**同一轮**输出末尾追加一个结构化块（行契约，示例）：

```
【价格情报】
- 米诺地尔 | 89.00 | CNY | 京东自营 | https://example.com/x | 2026-09-24
```

- 契约三处定义（沿用项目既有手法）：`PRICE_LINE_CONTRACT` + `PRICE_LINE_RE` + import 期自检（与 `SCAN_LINE_CONTRACT`/`SCAN_LINE_RE` 同风格）
- 代码层解析 → 写 `price_mentions`（**与 `price_history` 分表**！资讯价不进"当前价"序列，只在 UI 上以"资讯价"分组展示）
- 关联：按**实体名模糊匹配** `products.product_name`/`company_products.product_name` → 命中则在商品卡片下显示"相关资讯价"（带来源链接）

### 3.5 提醒与去重（G3）

```
触发条件（任一）：首次跌破 target_price ／ 创历史新低 ／ 竞品价差超阈值
去重规则（D5 定稿）：个人 → 仅"首次跌破 target_price"与"创历史新低"两种触发，
                    未创新低不重复提醒；竞品 → 价差提醒每 7 天最多一次
落地：price_alerts(id, account_id, item_type, item_id, rule, value, price, fired_at, acked_at, check_error)
通知：后端只落库 + 标记"待通知" → 桌面壳取走并弹系统通知 → 回写 acked_at（**避免重复弹**）
周报：digest 生成时把本周期内未写进周报的提醒收进"价格监控"附录
```

### 3.6 阶段 2（今天不做，接口先留好）

- 复用 M1 的 API 适配器：用户填"价格源的 URL 模板 + 参数位置 + 取值映射（JSONPath）+ 只读闸"；
- 检查方式：**手动"立即检查"** + 可选定时（沿用既有调度能力，不新增依赖）；
- 失败/限流：写 `price_alerts.check_error` 并在 UI 明示（G8），**不静默**。

## 四、设计选型与取舍

| 议题 | 备选 | 结论 |
|---|---|---|
| 价格从哪来 | A 自建爬虫 / B Tavily 当价格源 / C 付费比价 API / **D 手动+对话（阶段1）→ 自配 API（阶段2）** | ✅ **D**（C2/C3）：成本、稳定性、法律风险三项都最优 |
| 历史与资讯价 | A 全部混进一张表 / **B 分表（`price_history` vs `price_mentions`）** | ✅ **B**（C1）：一旦混表，早晚有人把资讯价当现价 |
| 记价入口 | A 只做前端按钮 / B 只做对话 / **C 两者都做（同一写入函数）** | ✅ **C**：前端按钮=确定性，对话=顺手（用户明确要"对话记价"） |
| 周报价格抽取 | A 另起一个抽取 AI（多一次模型调用）/ **B 让 digest 顺带输出结构化块** | ✅ **B**（**D6**）：省一次调用与 token，且行契约有先例 |
| 提醒去重 | A 每次触发都提醒 / **B "更极端"才重复触发** / C 固定静默期 | ✅ **B**（**D5**）：个人用"首次跌破 + 创历史新低"，竞品用 7 天静默 |
| 阶段 2 的源 | A 内置某厂商 / **B 配置导向（复用 M1 适配器）** | ✅ **B**：符合你"不写死厂商、让用户填字段"的既有偏好 |

## 五、契约与数据模型（照抄可开工）

### 5.1 加列（`tools/schema_personal.py`，迁移沿用既有 `_ensure_*` 风格）

```sql
-- products（个人收藏）
ALTER TABLE products ADD COLUMN url            TEXT;
ALTER TABLE products ADD COLUMN target_price   REAL;
ALTER TABLE products ADD COLUMN alert_drop_pct REAL;      -- 可选：较上次跌幅超过 N% 也提醒
ALTER TABLE products ADD COLUMN monitor_enabled INTEGER DEFAULT 0;
ALTER TABLE products ADD COLUMN last_price     REAL;      -- 冗余缓存"最新记价"，便于列表展示
-- company_products（自家产品）：url / target_price / monitor_enabled / last_price 同上
```

### 5.2 新表

```sql
-- 价格台账（人填 / 对话 / 阶段2 API）
CREATE TABLE IF NOT EXISTS price_history (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id  INTEGER NOT NULL,
  item_type   TEXT NOT NULL,     -- product | company_product | competitor_product
  item_id     INTEGER,           -- 对应表主键（competitor 时可为 NULL）
  item_name   TEXT,              -- 冗余名称（防止源行被删后无据可查）
  price       REAL NOT NULL,
  currency    TEXT DEFAULT 'CNY',
  source_type TEXT NOT NULL,     -- manual | api
  source_ref  TEXT,              -- 谁记的：username / 'agent' / 源配置名
  observed_at TEXT NOT NULL,     -- 观测时间（价格属于那一刻）
  note        TEXT
);
CREATE INDEX IF NOT EXISTS idx_ph_item ON price_history(account_id, item_type, item_id, observed_at DESC);

-- 资讯价（周报抽取，绝不进 price_history）
CREATE TABLE IF NOT EXISTS price_mentions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id  INTEGER NOT NULL,
  report_id   INTEGER,           -- digest_reports.id
  entity      TEXT NOT NULL,     -- 抽取出的商品/实体名
  price       REAL,
  price_text  TEXT,              -- 原文价格串（如 "89元起"）
  currency    TEXT DEFAULT 'CNY',
  shop        TEXT,              -- 京东自营 / 天猫旗舰店…
  source_url  TEXT,
  seen_at     TEXT NOT NULL,
  linked_item_type TEXT,         -- 匹配到的商品：product | company_product | NULL
  linked_item_id   INTEGER,
  match_score REAL
);
CREATE INDEX IF NOT EXISTS idx_pm_entity ON price_mentions(account_id, entity);

-- 提醒（触发历史 + 去重 + 错误）
CREATE TABLE IF NOT EXISTS price_alerts (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id  INTEGER NOT NULL,
  item_type   TEXT NOT NULL,
  item_id     INTEGER,
  rule        TEXT NOT NULL,     -- below_target | new_low | competitor_gap | check_error
  price       REAL,
  detail      TEXT,              -- 如 "竞品低 15%" / 错误摘要
  fired_at    TEXT NOT NULL,
  acked_at    TEXT,              -- 桌面壳弹过通知后回写（防重复弹）
  in_digest   INTEGER DEFAULT 0  -- 是否已收进周报附录
);
```

### 5.3 写入与触发函数（唯一事实源，放 `tools/` 或 `agent/`）

```
record_price(account_id, item_type, item_id, price, source_type, source_ref, note) -> dict
    ① 去重：同 (item, 同日, 同价) 不新增
    ② 写 price_history + 更新 products.last_price
    ③ 读上一条 → 判 new_low / below_target / competitor_gap → 写 price_alerts
    ④ 返回 {"ok":True,"row_id":…,"delta_pct":-12.0,"alert":"new_low"}

pending_alerts(account_id) / ack_alert(alert_id)      # 桌面通知取用 + 回执
collect_price_mentions(account_id, report_id, text)   # 周报结构化块 → price_mentions（含实体匹配）
```

### 5.4 工具（模型可见）

| 工具 | 参数 | 说明 |
|---|---|---|
| `record_price`（新增） | `item_type, item_name 或 item_id, price, note?` | 按名称**模糊匹配**到收藏/公司产品；匹配到多条则返回候选让模型问用户；**只读之外唯一的写个人库工具**（与 M3 的 `update_user_profile` 同取向） |

### 5.5 接口（`api/`）

| 端点 | 用途 |
|---|---|
| `POST /api/price/record` | 前端"更新价格"按钮（与 `record_price` 共用同一函数） |
| `GET /api/price/history?item_type=&item_id=` | 历史点 + 涨跌幅（给图表用） |
| `GET /api/price/alerts?pending=1` | 待通知提醒（桌面壳轮询/拉取） |

## 八、风险、回退与遗留

| 风险 | 缓解 |
|---|---|
| **把资讯价当现价**（最大的误导风险） | C1：分表 + `source_type` + UI 明确标注"资讯价（来源链接）"；G4 静态断言无路径混用 |
| 对话记价记错商品（名称模糊） | 工具按名称匹配 → **多候选时返回候选让模型向用户确认**，不擅自写入；用例覆盖 |
| 提醒重复打扰 | §3.5 去重（"更极端"才再触发）+ 竞品类 N 天静默 + `acked_at`/`in_digest` 双标记 |
| 周报输出变长/被契约破坏 | 结构化块放**末尾**且允许空块；契约 import 期自检 + 脏输出容错（解析失败只丢该块，不影响周报正文） |
| 新工具影响工具路由/注入量 | 新工具是**内部工具**（不进 CLI/API 能力池）；`m5b_*` 回归必跑；必要时给路由加"快路径"白名单 |
| 阶段 2 变成空壳 | 阶段 2 **只留接口与桩**（M5-8），不宣称"已支持自动查价"；README/文档同步口径 |

**回退**：全部是**加列 + 加表 + 加工具 + 加端点**，不做破坏性改动；关掉前端入口与工具即回到现状（`price` 仍是参考价）；周报价格块可一键关（`ZX_PRICE_MENTIONS=0`）。

**遗留（本版不做）**：自动抓取/爬虫（C2）；Tavily 当价格源（C2）；CLISHOP 或任何下单链路（D4）；真实第三方价格源的接入与选型（阶段 2，等可用源）；价格预测/趋势建模；把资讯价合并进"当前价"（明确禁止）。

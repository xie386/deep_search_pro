## 二、与方案的偏差（4 处，均已在对话中报告）

① **提醒只在"记价那一刻"产生**，不是后台自动盯价 —— 方案 §3.5 的表述容易读成"后台轮询"，实现是记价副作用。UI/周报文案已按此写（"已记价并生成提醒"），**后台自动抓价是阶段 2（M5-8）**。

② **桌面壳系统通知未接**：前端已写成"`window.__zxDesktop.notify` 存在就用它，否则应用内 toast 兜底"，而 `window.__zxDesktop` 由**页面**定义，外壳没往里挂 notify → 桌面壳里目前走兜底。补完需外壳侧加约 5 行桥接；外壳有独立 e2e 且助手无法在 Hermes 中真跑桌面窗口，**按要求暂停等用户点头**。

③ **价差提醒忽略 `alert_drop_pct`**：竞品行没有该列，阈值取模块常量 `COMPETITOR_THRESHOLD_PCT = 10.0`（方案 §3.3 的默认值）。

④ **前端 harness 的行为段（③）没跑起来**：静态契约 16 项全绿 + `node --check` 0 + 前端不变量全过，但 harness 里"真跑 `savePrice` 三个非法输入不发请求"的 3 项因**子进程段自身报错**（错误头被截，未定位）而未通过 —— 属**测试基建 bug，不是产品代码问题**。产品侧同一逻辑由 `test_price_tool.py` 的"价格 ≤0 友好失败"与"多候选不记账"用例覆盖。**留待下一轮修 harness**。

## 三、关键设计落点

- **G4（最易出事的一条）三道闸**：① `price_history.source_type` 的 `CHECK (source_type IN ('manual','api'))` —— 数据库层硬闸，插 `news` 直接 `IntegrityError`；② 资讯价走**另一张表** `price_mentions`；③ 前端 `<details>` 标题与周报块都写明"**不等于当前售价**"，harness 把这句话做成断言。实体匹配只写"疑似关联"（`linked_item_*` + `match_score`，0/0.5/0.7/1.0 四档），**绝不参与提醒判定**。
- **提醒去重（D5/G3）**：只两种触发 —— 创历史新低、首次跌破目标价；**首条记录不算创新低**（否则一记价就报警）；竞品价差**每 7 天最多一次**。
- **一次记价可同时触发多条规则**：返回里的 `alert` 只报**第一条**（个人价规则优先），其余照样落 `price_alerts` —— 别以为漏了。
- **C5（不额外调模型）**：周报在**同一轮**里多写一个结构化块，代码只解析。`test_price_mentions.py` 用静态断言钉死"解析路径里不得出现 `create_deep_agent`/`invoke`/`llm`/`requests.`"。
- **周报附录顺序**：先 `mark=False` 取正文 → **报告写盘之后**才 `mark=True`（否则"标了却没出报告"这条提醒永久丢）。
- **`collect_price_mentions` 去重**：(report_id, entity, price) 已存在不再插 —— 同一份周报重试解析不该翻倍。

## 四、踩坑记录（本轮 5 条）

1. **`'' AS brand LIKE ?` 是非法 SQL** —— 把字面量别名塞进 `WHERE`，SQLite 直接报 `near "AS": syntax error`。列不存在时的兜底要用 `COALESCE(brand,'')` 这种**表达式**，不是别名。
2. **取行值别依赖键名** —— 改成按 SELECT 顺序取下标；列名/别名一变就 `KeyError`。
3. **同一个字典两套主键名**（候选里叫 `item_id`、打印函数里取 `id`）→ 两处 `KeyError`。命名口径要**一处定义**。
4. **`price_ack.Req` 写错类名** → 注解在 **import 期**求值 → `import api.server` 直接炸 ✗，而 `py_compile` **查不出来**（它不求值注解）。是 M4-7 那条"起子进程验回退开关"的用例把它挡下来的。
5. **中文串里嵌 ASCII 双引号**（惯犯，Python 侧又中一次）→ 用全角／「」；**这条坑在 JS 不成立**（单引号串里带 `"` 合法），别把 Python 的规矩生搬到前端 harness。

## 六、M5-8（阶段 2 预留）落点

- **表 `price_sources`**：只有"怎么查"的字段（`url_template` / `param_map` / `value_path` / `timeout_s` / `readonly` / `enabled` / `secret_env`），**没有任何厂商名** —— 新增一个源 = 用户填字段，不改代码（G7，用例里用**厂商名黑名单**静态断言钉死）。
- **只读闸（C3）**：`upsert_source` 直接拒 `readonly=0`；`check_price` 里再拒一次（防库里历史脏数据）。
- **失败不静默（G8）**：超时 / 非 2xx / 非 JSON / 取值取不到 —— 四类都给**可读原因**并落 `price_alerts.check_error`；**"还没配源"不落错误**（那不是源坏了）。
- **凭证**：只存环境变量的**名字**（`secret_env`），值只在请求时从环境读；接口回参里永不出现值。
- **阶段边界**：`enabled` 默认 0，本版**不内置任何源**；没有启用的源时 `check_price` 明确回"阶段 2 未接源"，不假装查过。机制本身是通用的（配置驱动 HTTP GET + JSON 取值路径），用例用注入式 `fetch` 覆盖成功/超时/字段缺失/非 JSON/503 五种情形。

## 四、本轮踩坑（4 条，都值得记）

1. **"替换到下一个 `def`"的整段手术会把文件尾部的代码一起吞掉** —— 我替换 `digest_appendix` 时，把早先追加在文件末尾的 M5-7 竞品函数区间覆盖了。虽然函数最终都在（只有两个常量被吃），但**这是危险操作**：整段替换前应先 `grep '^def '` 记录函数清单，替换后再对一遍。
2. **缩进：`if` 体内的行必须是 `if` 缩进 + 4** —— 我批量替换时把注释与代码放成了与 `if` 同级，`IndentationError`。
3. **中文串里嵌 ASCII 双引号**（惯犯，本轮在**用例文件**里又中一次）→ 全角引号/「」。
4. **断言"数量必须为 1"救了一次** —— `price_tool` 里有**两处** `return "记录失败：%s" % e`，我差点改错那一处；`assert count == 1` 当场拦下。

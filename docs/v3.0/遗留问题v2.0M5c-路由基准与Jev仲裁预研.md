# v2.0遗留问题 M5c · 路由基准与 Jev 仲裁 预研（v3.0）

> **状态**：🔍 **预研**（结论已实测、方案待你拍板后再开工）
> **依赖**：M5b（已收官）· **M1/M2 已落地（池子因此从 8 条涨到 28 条 —— 本文全部问题的起点）**
> **对应规划书**：§2 P3/P4（路由质量）· §3 B1/B2（测试基线）
> **与 M6b 的关系**：M6b 的「路由质量基准」就是本文步骤三；M6b 里依赖 Tavily 的探针漂移部分**仍等 10/1**，但**本文的基准完全离线**（本地 embedding + 无 LLM），所以**不必等**。
> **一句话**：池子 8 → 28 之后，"路由全对"这个结论**不再成立** —— 实测出现**自信选错**（连"你是谁"都被路由）。根因分三层：**权限元数据把 19/28 个纯查询工具标成了写操作**、**来源级描述被粘进同源每个工具的向量文本**、**缺少带标签的基准**。本文给出证据、根因、三步走方案与 Jev 的立项条件。

### 2.3 用户那次"多工具综合运用测试"的解剖

问题：*「我现在的位置是四川成都，可能要去广州实习，帮我把广州这个城市的信息、出行路线和火车票价都查一下」*

| 项 | 实测 |
|---|---|
| 路由模式 | `routed`（z=2.175，自信） |
| 注入文本 | **2474 字符**（全量约 17360 字符 → 省 7 倍 ✓ 路由本身是对的） |
| top3 命中（拿**完整卡**的） | `api:xxapi#ipQuery` · `mcp:12306-mcp/get-station-code-of-citys` · `mcp:12306-mcp/get-station-code-by-names` ❌ |
| 该用的工具是否在注入文本里 | `mcp:city/search_city` ✅ · `mcp:route/plan_route` ✅ · `mcp:12306-mcp/get-tickets` ✅ · `get-current-date` ✅ · `get-stations-code-in-city` ✅（**都在**，但除命中的外只有一行"紧凑名"） |
| 模型实际做的 | 用了 `city/search_city` ✅ + 12306 车站码工具 ✅ → **卡在 `get-tickets`**（自述："这个会改外部状态，我需要先确认用户是否明确要求"）→ **退回网络搜索**（携程 / ip138 / 好查列车时刻表）→ 答案只能挂 ⚠️ 免责声明 |

**结论：路由把该用的工具都摆到它面前了；真正拦停它的是权限元数据（2.4）**，其次是"命中工具拿完整卡、其他只给一行"的降权效应（2.5 相关）。

### 2.4 根因一：权限元数据 —— 19/28 个**纯查询**工具被标成"写操作"

代码落点：`api/tools_sources.py:122 def _is_write_row(src, spec)` —— mcp 的口径是
**`spec["read_only_hint"] is not True` → 按"写"处理**（保守设计：规范说 annotations 只是提示、客户端不得据此做安全决策）。

后果（实测）：**12306 的 8 个 + BNF 的 8 个 + 拼多多 3 个 = 19 条全部非只读**，因为这三只服务的工具**一个 `readOnlyHint` 都没声明**。
而恰好声明了只读的 9 条里，就包含 `mcp:city/search_city` 与 `mcp:route/plan_route` —— 与"模型用了 city 却被 get-tickets 卡住"的现象**完全吻合**。

> 这不是模型能力问题：**它按我们的安全指令做了正确的事**（去确认写操作是否被授权），代价是整条工具链断掉、退化成二手网搜。

### 2.5 根因二：向量文本粘连 —— 来源级描述被粘进同源**每个**工具

代码落点：
- 合并逻辑 `tools/capability_pool.py:241`：`abilities = 工具级 + "；" + 来源级`（这是 **M1 为修"来源级描述被埋没"而加的**，方向对，但**同时污染了向量文本**）；
- 向量文本 `tools/capability_pool.py:438 _entry_text(e)` = `name + keywords + abilities + param_summary`。

实测出来的三张卡片（这才是 top3 选错的直接原因）：

| ref | 向量文本长度 | 能力描述（节选） |
|---|---|---|
| `api:xxapi#ipQuery` | 61 字 | 查询IP归属地**；抖音热榜、抖音热搜、实时热点榜单、抖音热门视频/话题排名** |
| `api:xxapi#douyinHot` | 46 字 | 获取抖音实时热榜**；抖音热榜、抖音热搜、实时热点榜单、抖音热门视频/话题排名** |
| `mcp:12306-mcp/get-current-date` | 150 字 | 获取当前日期…**；查看车票信息,查看当天从出发点到目的地的车票剩余,路程需要中转车票购买规划** |

→ **同源工具共享同一段最强文本**，向量分不开（"查广州这个城市"的 top3 = `ipQuery` / `douyinHot` / `station-code`，而 `city/search_city` **连 top3 都没进**）；
→ 另：**`keywords` 是设计上最强的路由信号，但 28 条里只有 3 条 CLI 填了、25 条 api/mcp 全空**
（`_KEYWORDS_PREFIX` 只认「能力描述」里的 `关键词：…` 前缀，`tools/capability_pool.py:34`）。
更糟的是 CLI 那 3 条里含**泛化模板词**（`今天` / `XX` / `我` / `有没有`）—— 实测「今天几号」能让 `cli:bili` 拿到 **1.0 词法分**
（它的关键词里有「**今天**B站在火什么」）；而 `lexical_scores` 的短语命中权重是 **3.0**、`LEX_MIN=2`（`tools/tool_router.py:33/86`）
→ **一次泛化词命中就足以判"自信"**，把向量里正确的 top1 在 RRF 里顶掉（`_rrf` 注释里记过同类事故）。

### 2.6 根因三：没有带标签的基准 —— "全对"这个结论本身不可复现

- M5b 的"标定 10/10"是在 **8 工具池**下、用 **10 条题**得出的；
- 池子变成 28 条后，同一套阈值下已出现 2.2/2.3 里的两类错误（自信选错 / 噪声路由）；
- 而且**没有"期望工具集"标签**，所以既无法算 precision，也无法回归（每次只能目测"看着对"）。

## 三、设计选型与取舍

### 3.1 步骤一（G1）：来源级「我确认这个服务全是只读」声明

**存哪**：`tool_sources.config_json.assume_read_only: true`（**免建表/免迁移**；随来源一起被 `sources_list` 投影出来给前端回显）。

**安全口径（必须写死，这是本步骤的边界）**：
- 只允许覆盖**服务端"没声明"**（`read_only_hint is None`）的情况；
- **服务端明确 `read_only_hint=false` 的工具，绝不允许被这个开关覆盖**（明确说"我会改状态"就按写处理，用户不能一键绕过）；
- 开关是**显式的用户动作**（前端一个勾选框 + 后果说明），变更进审计（`data/audit/commands.jsonl` 的 `read_only` 字段照旧 + 建议加 `read_only_declared: true` 以便追溯"当时是用户声明的只读"）。

**改动面（很小）**：只需让**写库时的 `read_only` 派生**吃这个开关（`_discover_mcp()` 与 `confirm()` 两处的 `_is_write_row`），**网关侧零改动**（`readonly_verdict` 读的是库里已存的 `cap.read_only`，`tools/capability_invoke.py:171`）。
**回退**：把开关取消 + 重跑一次「发现工具」即可让 `read_only` 回到保守值。

### 3.2 步骤二（G2）：向量文本卫生

**改法**：给条目多带一个**工具级原文**字段，并新增 `route_text`：
```
route_text = name + keywords + (工具级 abilities 原文 or 回退到合并后的 abilities) + param_summary
_entry_text(e)  →  改用 route_text     # 只影响"送去 embed 的文本"
card_text       →  完全不动            # 模型看到的卡片照旧保留「工具级 + 来源级」两层
```
- 工具级描述**为空**时仍回退到合并文本（否则该条目几乎没信号，例如某些只给了工具名的 MCP 工具）；
- **CLI 条目逐字不变**（现有回归断言钉着 `content_hash`，不得触碰）；
- **影响面**：api/mcp 条目的向量文本变化 → `content_hash` 变化 → `sync_vectors` 自动**一次性重算**（28 条，秒级）。
- 附带指引：在来源的「能力描述」里用 `关键词：xxx, yyy` 开头（`capability_pool.py:34` 认这个前缀）→ 前端教程补一句，把这 28 条的空 keywords 填起来。

### 3.3 步骤三（G3）：离线路由基准（可不等 10/1）

- **题库** `tests/data/router_bench.json`：每条 = `{问, 类别, 期望工具集(refs), 备注}`，类别覆盖：**明确命中 / 灰区 / 噪声（本不该路由）/ 跨工具多步**；
- **冻结池**：另存 `tests/data/router_pool_snapshot.json`（从某次真实池子里导出的卡片），基准**默认跑快照**（可复现、不受账号增删工具影响）；`--live` 才打真实账号；
- **指标**：`precision@3` · `recall@3`（该进 top3 的进了没）· 灰区比例 · 噪声假阳性率 · 平均注入字符数；
- **纪律**：纯本地（embedding 本地 + 无 LLM + 无网络）→ **不烧 Tavily、不必等额度重置**；临时账号用完 `purge_account`。

### 3.4 步骤四（G4）：Jev 仲裁层（**默认关**，配置导向）

沿用 09-19 的结论与架构，**本次实测补充了一个新岗位**：

```
问句
 ├─ ① 词法命中 ≥ LEX_MIN(2) ──→ 路由（现状，零成本零延迟）
 ├─ ② 向量 z ≥ Z_STRONG(2.0) ─→ 路由（现状，零成本）
 └─ ③ 灰色区间（其余）──→ 【Jev 仲裁】（新增，仅此处付费）
        state = 问句 + 池内工具 name/keywords
        questions = {
            "tool":        choice("该用哪个工具回答？", {全池})
            "needs_tool":  noul("这个问题需要调用工具吗？")     ← ★ 新岗位：治"你是谁"被自信路由
        }
        ├─ confidence ≥ 0.6 且 needs_tool 高 → 按 Jev 排序路由
        └─ 否则 → 回退全量（现状行为）
```

- **立项触发条件（修订版，三条任一）**：灰区 >30% **或** `precision@3 < 0.7` **或** 噪声假阳性 >10%；
- **前置条件（硬性）**：步骤一、二**必须先落地** —— 否则是"把糊在一起的文本喂给更聪明的判断器"，脏进脏出；
- **配置口径**：`tool_route_provider = local(默认) | jev`，jev 的 endpoint / model / 阈值 / 超时全部可配（**不许硬编码厂商**，与 `llm_providers` 同款）；
- **fail-safe**：Jev 不可用 → 回退 bge+词法路由 → 再回退全量简报（链路天然兼容）；
- **铁律**：Jev 只影响"工具怎么被想起"，**绝不参与"能不能跑"**（六道闸 / 只读闸 / 审计一律不动）；
- **成本**（按 09-19 估算口径，灰色区间按实测 25% 计）：每次约 800 input tokens ≈ $0.000034；日均 1000 问 → **≈$0.0085/天**，可忽略；延迟 +70~500ms，只付在灰区。

### 3.5 明确不做

- ❌ 不替换词法/向量两条免费快路（它们现在依然零成本正确）；
- ❌ 不做"关键词黑名单 / 停用词表"这种打补丁（先把 3.2 的文本卫生做对）；
- ❌ **不在没有基准的情况下调阈值**（2.0 / 2 都是 8 工具时代标定的，拍脑袋改等于换一种方式不可复现）；
- ❌ 不改 `card_text`（模型看到的卡片已经是对的，问题只在"送去 embed 的文本"）。

## 七、风险、回退与遗留

| 风险 | 缓解 |
|---|---|
| 来源级只读被**误勾** → 真写操作被自动放行 | 只允许覆盖"未声明"（明确 false 不可覆盖）+ UI 写清后果 + 审计留痕 + 取消开关即回保守 |
| 向量文本变更导致重算（28 条，秒级） | 一次性；`content_hash` 机制自动处理；CLI 条目不受影响 |

### 8.1 基准跑出来的三条**新的**根因（M5c-2 之后才看清）

   25 条 api/mcp 的 keywords 为空 → 该路对它们**完全无信号**；而 CLI 那 3 条的泛化模板词（`今天`/`XX`/`我`/`有没有`）

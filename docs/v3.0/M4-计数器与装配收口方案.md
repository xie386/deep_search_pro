# M4 · 检索计数器 + 装配入口收口 方案

> **状态**：✅ **定稿**（2026-09-25 用户裁决 O1/O2/O3，见 §零；§九 无待定项）
> **对应规划书**：§2 P3 / §2 P4 / §3 A4 / §3 A5 / §4 S4｜**依赖**：与 M1M2（`api:`/`mcp:` 来源分类）、M3（记忆读取统一）相接

## 二、现状与证据

### 2.1 装配：函数唯一， **取材不唯一**

```
api/server.py _run_agent()（169-247）—— 现在它既是"取材员"又是"调用方"
 192: cust.get_soul_content(account_id) ← 取材① SOUL
 195: _get_memory_text(account_id) ← 取材② MEMORY（内部 131-135 再开一次 DB 连接查 username）
 203: cust.get_skills_text(account_id, ...) ← 取材③ 技能说明书
 215: tool_router.route_tools(account_id, q) ← 取材④ CLI 简报 + few-shot 示例
 224: build_request_context(...) ← 装配（唯一调用点）
 229-239: 只用 monitor.report_thinking 推 WS 提示 ← **结果不落库**
```

| 事实 | 证据 |
| --- | --- |
| `build_request_context` 存在且 **唯一被调** | `agent/build_context.py:115`，调用点仅 `api/server.py:224` |
| 装配内部顺序：动态 SystemMessage → 历史 → 技能前缀 → 预算截断 | `build_context.py:143-153`（`_apply_persona/_apply_memory` 注释见 `build_context.py:7`） |

| 历史坑 1：记忆相对路径 bug | `build_context.py:71-73` 注释记录："模型照抄传参 → 落到 `agents_docs/agents_docs/{user}/`…实测踩过" |

## 三、设计

### 3.1 M4-A 检索计数器

```
[挂点] AgentMiddleware.wrap_tool_call / awrap_tool_call（langchain 1.3.14 提供；
 ToolCallRequest{tool_call, tool, state, runtime}；handler 负责真正执行）
 ├─ 主 Agent：create_deep_agent(middleware=[_ToolExclusionMiddleware(), UsageCounter()])
 ├─ 3 个子 Agent 的 spec：{"name":…, "tools":[…], "middleware":[UsageCounter()]} ← C2 必须
 └─ 周报自建 Agent（digest_engine.py:223）同样带 UsageCounter ← C3 必须

[分类] kind 由工具名映射（一张表，可扩展；与 M1M2 的 ref 前缀自动衔接）
 retrieval_external : internet_search（Tavily） ← 唯一花额度的类
 tool_internal : query_kb / db / personal / company / 读写文档
 shell : run_shell_command（沙箱）
 api / mcp : 以后按 ref 前缀 `api:` / `mcp:` 自动归类（M1M2）

[落库] usage_events(id, account_id, thread_id, turn_index, kind, name, ok, ms, result_chars, created_at)

[出口] GET /api/usage?thread_id= → {this_turn:{…}, this_session:{…}, kinds:{…}}
 前端：① 聊天页显示"本会话外部检索 N 次"（复用 WS 的 tool_start 事件做实时 + 拉一次接口做总数）
 ② 工作台 `.stat-card` 加一张"本月成本/检索"卡（复用现成格位）
 ③ 单轮外部检索 > 阈值（默认 3）→ monitor 提示（**只提示不阻断**，见 D1）

[并存] monitor.report_tool 保留不动（负责"实时播报"），中间件负责"记"——两件事不要混
```

**为什么必须挂中间件、而不是继续用 `report_tool`**： `report_tool` 是**工具函数自己 **写的（工具不写就漏），而中间件在**框架执行工具的唯一咽喉 **上——两者证据强度不同；且中间件能拿到**调用前后的耗时/异常 **， `report_tool` 只有调用前。

### 3.2 M4-B 装配入口收口（依赖倒置）

```
agent/context_sources.py（新增；不 import api.*）
 register(name: str, provider: Callable[[int, str], SourceResult]) -> None
 collect(account_id: int, question: str) -> dict[str, str] # 顺序确定、异常降级为空串
 SourceResult = (text: str, injected: bool) # 供装配侧判断是否推"已注入 N 条"提示

api/context_providers.py（新增；启动时 import 一次即完成注册）
 register("soul", lambda aid, q: SourceResult(cust.get_soul_content(aid), bool(...)))
 register("memory", lambda aid, q: read_memory_for_agent(aid)) # ← 与周报共用（C6）
 register("skills", …) register("cli_brief", …)

agent/build_context.py
 build_request_context(thread_id, account_id, new_user_msg, *,
 sources: dict[str, str] | None = None, # 显式传入（测试/兼容）
 config=None, manager=None) -> ContextBundle
 sources = sources if sources is not None else context_sources.collect(account_id, new_user_msg)
```

- **新增注入源 = 写一个 provider + 注册一行**（不再翻三处）；
- **记忆读取唯一化**：把路径规则下沉为唯一事实源（见 §5.4），对话与周报都调 `read_memory_for_agent(account_id)`；
- **回退开关**： `ZX_ASSEMBLY_SOURCES=legacy` 时 `_run_agent` 走旧的"server 取材 + 传参"分支（保留一段时间）；
- **明确不做**：不把周报改造成走 `build_request_context`（C6）——那是"任务型 prompt + 自建 agent"，强改风险大于收益；本轮只统一记忆读取。

## 四、设计选型与取舍

### 4.1 计数挂钩点

| 备选 | 结论 |
| --- | --- |
| **A. 中间件 `wrap_tool_call`**（框架咽喉） | ✅**选它 **：不靠工具自觉；能拿到耗时/异常；一处覆盖所有工具（含以后 API/MCP 适配器） |
| B. 继续用 `monitor.report_tool`（工具自觉上报） | ❌ 主因：漏计不可知（新工具忘了写就漏）；且无耗时/异常 |
| C. 事后从 `messages`（tool role）回算 | ❌ 只能事后；无法区分 kind、拿不到耗时；压缩/裁剪场景下语义不清 |
| D. 在 `_run_agent` 里包一层工具列表 | ❌ 只在主图生效（子 Agent 有独立工具列表），比 A 更脆 |

**降级预案**：若 deepagents/langchain 升级导致中间件签名变动 → 回退到"工具自觉上报 + 静态断言 `tools/*.py` 覆盖率"（双保险），并在 `tests/test_usage_counter.py` 里钉住版本号断言（当前 deepagents **0.7.4** / langchain**1.3.14** / langchain-core**1.5.3** / langgraph**1.2.10**）。

### 4.2 取材收口的做法

| 备选 | 结论 |
| --- | --- |
| **A. 来源注册表 + 依赖倒置**（api 层注册 provider） | ✅ **选它**：既守住"`agent/` 不 import `api.*`"铁律，又让装配内聚；新增源=加一行注册 |
| B. 保持现状（server 取材后传字符串） | ❌ 就是"改一处忘一处"的来源 |
| C. 让 `build_context` 直接 import `api.customize` | ❌ 违反架构铁律（历史上正是为解反向依赖才拆出 `agent/answer_text.py`） |
| D. 把用户文档路径规则整体下沉到 `agent/` | 部分采纳： **只下沉"路径解析"**（§5.4），不动 api 层的写入/校验逻辑 |

### 4.3 计数的粒度（本版做到哪）

| 项 | 本版 | 理由 |
| --- | --- | --- |
| 工具/检索次数 + kind + 成功失败 + 耗时 + 结果字数 | ✅ 做 | 一次 INSERT 的成本，排障价值高 |
| 会话级聚合 + 阈值提示 | ✅ 做 | 直接对应"额度可见可控" |
| **模型调用级 token** | ❌ 不做（**D2**） | 轮级 token 已有（`conversations.token_usage`）；模型级属于"账单"范畴 → 与 M6c 成本表一起做 |
| **Tavily 余额查询** | ❌ 遗留/调研 | 需确认 Tavily 是否提供余额端点； **不承诺**（避免又变成"看起来有其实没有"的功能） |

## 五、契约与数据模型（照抄可开工）

### 5.1 新表 `usage_events`（`tools/schema_personal.py`）

```sql
CREATE TABLE IF NOT EXISTS usage_events (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 account_id INTEGER NOT NULL,
 thread_id TEXT, -- 周报/后台任务可为 NULL
 turn_index INTEGER, -- 该会话内第几轮（能取到就填）
 kind TEXT NOT NULL, -- retrieval_external | tool_internal | shell | api | mcp | model
 name TEXT NOT NULL, -- 工具名（如 internet_search / run_shell_command）
 ok INTEGER NOT NULL DEFAULT 1,
 ms INTEGER, -- 耗时（毫秒）
 result_chars INTEGER, -- 结果字数（便于估"注入了多少"）
 created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_usage_acct_time ON usage_events(account_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_usage_thread ON usage_events(thread_id, id);
```

- **账号隔离**：全部带 `account_id`； `purge_account()` 连带清理（沿用"自省表结构"的既有做法）；
- **保留策略**： **永不清理**（D3：单轮个位数行；删了就无法回溯"那次为什么烧额度"）；
- **失败也记**（`ok=0`）——额度已经花了。

### 5.2 中间件契约（`agent/usage_counter.py`，新增）

```python
class UsageCounter(AgentMiddleware):
 """按工具调用计数落库（不 import api.*；上下文取自 set_thread_context/set_owner_context）。"""
 def wrap_tool_call(self, request, handler): ... # 同步路径
 async def awrap_tool_call(self, request, handler): ... # 异步路径（两条都实现，防漏）
```

写入时机： **调用返回后**写一条（含 `ok/ms/result_chars`）；异常路径在 `except` 里以 `ok=0` 写一条后原样抛出（不改行为、不吞异常）。

### 5.3 接口

| 端点 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/usage?thread_id=&token=` | 本轮 + 本会话分类计数 | `{this_turn:{retrieval_external:2, tool_internal:3,…}, this_session:{…}, tokens:{this_turn, this_session}}`； **越权校验**（thread 不属于该账号 → 403） |
| （复用） `/api/me/overview` | 工作台"成本卡"的汇总位 | 新增字段，不破坏既有返回（含"本月外部检索次数"） |
| （不改） `GET /api/me/overview` 之外的既有端点 | — | 本版 **不删不改**任何既有端点 |

### 5.4 记忆读取唯一化（C6）

```
现在：api/server.py:_get_memory_text() ← 对话路径（自己开 DB 连接查 username）
 agent/digest_engine.py:158 ← 周报路径（自己拼路径）

改为：tools/user_doc_paths.py（新增，路径规则的唯一事实源）
 user_doc_dir(username) / user_memory_path(username) / user_soul_path(username)
```

## 八、风险、回退与遗留

| 风险 | 缓解 |
| --- | --- |
| 装配重构触及所有请求路径 | **先写等价性回归再切**（G2）； `ZX_ASSEMBLY_SOURCES=legacy` 一键回退；先做计数后做重构（可分两次上线） |
| 中间件是 deepagents/langchain 内部 API，升级会变 | 钉版本断言（0.7.4 / 1.3.14 / 1.5.3 / 1.2.10）+ 降级预案（回退 `report_tool` + 覆盖率静态断言） |
| **子 Agent 漏计** | C2 明确注册位置 + **反证用例**（委派 2 次必须 2 条）；这条不达标就不算完成 |
| 计数写库影响性能 | 单轮工具调用数是个位数；同库短事务；必要时改批量写（预留 `ZX_USAGE_COUNTER=0` 关掉） |
| provider 抛异常导致请求失败 | `collect()` 内 **逐源 try/except → 降级空串 + 日志**（与现在 server 层 `except: soul_text=""` 的行为 **逐字一致**，这是等价性回归的一部分） |
| 周报路径被顺手改坏 | C6 明确"只统一记忆读取"，不做 prompt 改造；周报有独立回归用例 |
| 度量本身被误解（"计数=成本"） | 表里只放 **次数/耗时/字数**；token 与钱的关系留给 M6c 成本表，口径写清 |

**回退**：三个开关（§5.5）；计数是 **旁路写**（关掉即回到"只 WS 播报"）；装配收口有 legacy 分支；全流程不需要数据迁移（新表 + 新增字段）。

**遗留（本版不做）**：模型调用级 token 计数（**D2** → M6c）；Tavily 余额查询（需先确认其 API 能力）；**"需确认续跑 / 直接拒绝"式闸门 **（**D1** 定为开关预留、本版不实装）；跨会话成本报表（→ M6c）；把周报改造成走统一装配入口（C6）； `usage_events` 的清理策略（**D3** 定为不删）。

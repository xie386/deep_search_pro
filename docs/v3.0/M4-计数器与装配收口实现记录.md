## 二、与方案的偏差（逐条给理由，均已写进代码注释）

① **`usage_events` 列做方案 §3.1 列草图的超集**（用户拍板「按建议补齐」）
   方案草图：`(…, turn_index, name, ok, ms, result_chars, created_at)`；实际：
   `(…, turn_index, tool_name, source, ok, latency_ms, result_chars, created_at, created_ts)`。
   - **补**了 `turn_index`（M4-4「本轮」的唯一依据 —— 缺了它这一维算不出来）与 `result_chars`；
   - **多了** `source`（界面要显示"具体是哪个 API/MCP 工具"，kind 只是粗分类）与 `created_ts`（聚合排序用，避免字符串比较）；
   - `name/ms` 改名为 `tool_name/latency_ms`（与代码里其它字段口径一致）。

② **`context_providers` 只注册 `soul` / `memory`**（方案 §3.2 列了 4 个）
   `skills` / `cli_brief` 需要**本轮特有**的入参（选中的技能名、路由结果），而 provider 签名只有
   `(account_id, question)` → 宁可少注册，也不注册空 provider 让装配侧误以为"已经收集过"。
   这两个源仍由 server 显式传入（M4-7 的等价性用例覆盖了它们的存在）。

③ **kind 常量名取 `internal`**（方案 §3.1 行文写 `tool_internal`、§5.1 写 `internal`）→ 取 §5.1。

④ **「来源可点开」不在 M4**（属 M3-7 遗留，见 M3 实现记录 §二④）。

## 三、M4-9 真机抽样（数字为实跑）

**方法**：起后端（8123）→ 用真实账号「尼古喵喵」新建会话 → 提一句**需要联网检索**的问题
（"用网络搜索查一下法国国家图书馆(BnF)今天的开放时间"）→ 查 `usage_events` 与 `GET /api/usage` 对账。

| 指标 | 实测 |
|---|---|
| 该次问答产生的 `retrieval_external` 事件 | **2 条**（`internet_search`，耗时 4354ms / 2204ms，返回 6441 / 7536 字符） |
| `GET /api/usage.this_session` | `{total: 2, cost_calls: 2, by_kind: {"外部检索": 2}}` |
| 对账结论 | **接口与库完全一致**（2 = 2）；事件带真实耗时与返回字符数 → 确实是当次 Tavily 调用 |
| `turn_index` | 0（该会话第一轮；轮号按 `conversations.message_count // 2` 折算，首轮即 0） |
| 该账号累计 | `internal 23 / retrieval_external 2 / shell 7` |

> ★ 抽样**当场暴露两个缺口并已修**（这类问题只有真机数据能发现）：
> ① `classify()` 缺 `internet_search` → 真实检索工具名不在映射表里 → **唯一花额度的那一类一条都没记上**
>    （首轮抽样时 `retrieval_external` 为 0）；② 上下文读取器只给 2 元组 → `turn_index` 恒 0、
>    「本轮」在真机上等于废的。两处修完均已补用例钉死（`test_usage_counter.py`）。

## 四、落地过程中踩的坑（都值得记）

1. **`ensure_tables()` 里的迁移必须放在真的会执行到的路径上**：我第一版把补列 `ALTER` 塞进了
   「`tool_sources.intro` 列缺失才执行」的条件分支 → 本机永远不跑。改到函数最开头并用
   `PRAGMA` 查缺 + try 兜底后才生效。**证明方式**：把一份库副本造成"没有这两列"，用
   `PERSONAL_DB_PATH` 指过去再跑 `ensure_tables()` → 列被补上（注意该环境变量是 **import 期**读的，
   必须在 import 之前设）。**别用 `DROP COLUMN` 验证** —— 本机 SQLite 构建不支持。
2. **`hasattr(obj, "_private")` 防御式取值是坏味道**：`context_providers._memory` 写成这样 →
   方法根本不存在 → **记忆被静默注成空串** → `m2_assembly_e2e_test`「问答引用画像事实」失败。
   该问的路径要自己查（本例：从 `accounts` 表取用户名），不要用 hasattr 掩盖缺失。
3. **模板块别插进 `v-for` 里**：计数条一开始被插到 `session-item` 的 v-for 内 → 每个会话渲染一条；
   而且 `session-item` 的开标签与它的 `v-for` 属性是**分两行**的，插在中间会把属性挤到后面、破坏结构。
   `node --check` 与前端不变量**都查不到模板结构** —— 模板改动必须自己看渲染位置。
4. **`execute_code` 有 300s 硬上限**：真机问答（免费模型 + 联网）实测 >200s，脚本超时设 560s 反而
   连结果都拿不到。真机抽样要拆成"起服务 / 等就绪 / 短请求 / 查库"多步，别塞一个 cell。

## 二、问题与方案

### 问题 1：原设计**无法直接取用** 
- 原站标注 **「Exact source is protected」**—— 只发编译产物、不发源码；
- 原组件是 **React** 组件（`<TypographyVortexCanvas />` + `npm i @designcodeio/threeui`），而本项目前端是 **Vue3 单页内联 JS**。

**方案**：**按效果契约复刻**（不动项目依赖、不引 React 运行时）
- 契约抄准：`renderer=Canvas 2D（2 passes）` · `ringGrowth=1.21` · `suctionDuration=920ms` · `pixelRatio adaptive ≤ 2` · `mode dark|light`；
- 纯手写 `front/login_vortex.js`（约 15KB **零依赖**），全局只暴露 `window.LoginVortex`。

### 问题 2：**浅底上几乎看不见**（用户实测截图）
页面本身是浅色底，而第一版**按深色底配色**（淡蓝白墨迹叠浅底 → 化掉）；
且模式判断靠 `documentElement.classList` → 页面上没那个类 → **一律走了深色档**。

**方案**：浅底专用档 = **深琥珀线条（#a9760c / #c9971c）+ 亮白高光**；粒子在浅底改用深色；
不透明度整体上调（环 0.28→0.46 ✓、字形 0.62→0.86 ✓）；`autoMount` **默认浅色档**，另留 `data-mode="dark"` 覆盖。
→ 用户确认「**改了色以后清楚多了**」

### 问题 3：三处**设计理解偏差**（用户贴参考图 1/图 2 纠正）
| 我原来的实现 | 参考图实际 | 改法 |
|---|---|---|
| 鼠标处画一层**暖色光晕** | 鼠标处**粒子散落**（细小方点向外飘散渐隐，环线被"擦断"） | 去掉光晕；每帧 spawn `scatterRate=5` 个散落方点（`fillRect`，`moteLife≈900ms`），保留 `destination-out` 擦断 |
| 点击时**整个环圈收紧** | 点击处**粒子汇聚**（四周飞向落点聚成一团 + 落点小目标环 10→34px） | 改为 spawn `convergeCount=190` 个粒子飞向落点（easeOutCubic 920ms）+ 落点小环 |
| （被否掉的"缩放"） | — | **挪用到登录卡片**：悬停卡片 → 背景环**同步放大 1.18×**（0.16s 平滑），移开复原 |
| 环上是随机字母 `ABCD…` | 环上是**重复文字串** | 改为 `智选情报官 / INTELLIGENCE IN MOTION /`（`DEFAULTS.text` 一处可改） |

## 四、踩坑记录（都是真踩过的）
1. **新增 `<script src>` 会挪动 harness 的脚本索引**—— harness 取"第 2 段 `<script>`"当主脚本，我在头部插标签 → 两个老 harness 立刻红 
 → 修：把模块标签**移到页面尾部**（主脚本仍是第 2 段 ✓）→ 恢复 11/11 ✓。
 **教训**：往 `index.html` 加脚本，别插在主内联脚本**之前**。
2. **shell 的 `&&` 链会搞坏 node 的 stdin**—— `node f.js < /dev/null && …` 报 `stdin is not a tty`，导致**全量 harness 假 FAIL**（11 个全红）
 → 改用 `;` 分隔 + `if node f; then` ✓ → 真结果 11/11 ✓。**教训**：满屏 FAIL 先怀疑跑法，别急着改代码 ✓。
3. **配色必须按页面实际底色定**（见问题 2）——"深色页的浅色墨迹"搬到浅底 = 看不见。
4. **skill 的 `types/` 与 `snippets/` 是两套独立 id**—— 我一度把页面级设计编号成 `002` 撞上了既有的 `002-login-register` 
 → 改 `006-login-page`，并把这条规则写进 skill。

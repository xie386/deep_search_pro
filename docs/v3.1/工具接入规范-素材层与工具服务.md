# 工具接入规范：素材层与工具服务（v3.1 立）

> 目的：让「以后接入别的工具」不再重演 bnf 那一轮问题。
> 适用：接入新 CLI / API / MCP 来源的人（含 AI 助手）。
> 配套：`tests/live/m6b_material_lint.py`（静态闸门）· `tests/live/m6b_material_ab.py`（动态闸门）。

## 一、为什么有这份规范

bnf 接入后暴露的问题，**在真机上全都以"agent 犯错"的面貌出现**，逐个排查才发现责任在三层里各有归属：

| 现象（真机看到的） | 证据 | 定性（谁的责任） |
|---|---|---|
| 「模型不知道有这个工具 / 用错同源函数」 | 离线 5 例里期望工具进不了 top3（0/5） | **素材层**：缺面向路由的文本 |
| 「检索结果被截断，模型看不到全部」 | 28 次 bnf 调用里 12 次顶到 6000 字符截断线 | **工具服务**：载荷过大 |
| 「同一个查询连着发两次」 | `search_by_date` 同参数连发（第 6/7 步） | **工具服务**：返回不带页码、参数叫 `start_record` |
| 「中文主题查不出东西」 | `natural_language_search("雨果")` 静默 0 条 | **工具服务**：语言约束没写进描述、空结果没有 hint |
| 「报告写着写着跑偏」 | 报告工具只用于初始化，随后自己另搜 7 次 | **工具服务**：初始化 `nextStep` 把模型推给了别的工具 |
| 「报告进度不动」 | `progress` 恒 10.0%（每次调用是新进程） | **工具服务**：状态只存内存、没落盘 |

**结论**：接入 = **三件事**，缺一件就会在真机上以 agent 犯错的面貌出现 ——
① 工具服务侧的返回契约 · ② 账号素材层的文本 · ③ 入库前的两道离线闸门。

**责任判据（先于一切修复）**：先证明**工具本身有没有那个能力**。工具没有 → 只改工具，不算 agent 的锅；
工具确实有（如翻页可用）而 agent 不用 → 才进入"调用纪律"，那是另一层的事。

## 二、素材层三件套（每条能力都要齐）

路由器与模型用到的文本只有三处，**逐条都要写**：

| 字段 | 谁在用 | 写什么 | 反面例子 |
|---|---|---|---|
| `keywords` | **词法路唯一信号**（短语命中权重最高） | 用户真实会说的中文短语，竖线或顿号分隔 | 留空（词法路对这条完全没信号） |
| `abilities_user` | 卡片文本 + 向量文本（**写了它，自动摘要就不再进向量文本**） | 工具级**中文**描述：做什么、什么时候用、关键约束 | 只有 1000 字英文自动摘要（既稀释又无中文信号） |
| `name` | 卡片标题 + 词法/向量两条路 | **人话名字** | `get-station-code-of-citys` 这种英文标识符（会与中文问句在向量空间撞车） |

来源级 `abilities`（你按自己的话写的来源说明）**保留**：它会被合并进条目文本，是 M5c-2 实测有用的那部分中文信号。
（历史结论：M5c-2 曾试"只取工具级描述"，实测是负收益，已回退。向量收益应来自**补关键词/补工具级描述**，不是砍来源级描述。）

## 三、四条被实测逼出来的写作纪律

1. **领域锚定**：描述要绑回它服务的领域，不能只写"功能"。
   反例：`get-current-date` 写成「取当前日期（查票前先取一次）」→ 它成了向量路离群点，
   「今天心情有点好」「…今天天气不错」两道噪声题被**自信路由**（噪声假阳性 0 → 0.333）。
   改成「铁路余票查询的第一步：取当前日期，供查火车票时填 date 参数」后归零。
2. **不要写否定式措辞**：写「与 X 无关」**会把 X 本身拉进向量空间**。
   反例：拼多多商品搜索写「与编程/算法里的『排序』无关」→ 「用 python 写个快速排序」直接命中它并获得自信判定。
   一律改成**领域正面措辞**。
3. **避开通用词与情绪化词**：`今天` / `排序` / `随便逛逛` / `不知道买什么` 这类词跨领域零区分度。
   反例：「按价格排序」被「写个快速**排序**」命中（M5c 期就已踩过同一坑）。
4. **近名工具必须各有区分性短语**：同一来源的多条工具（12306 三个站码工具、bnf 八个检索函数）
   要能各自命中不同问句，并在描述里写清"什么时候**不**用它"的替代路径。
   反例：`city/search_city` 原先只有 1.0 词法分，`get-station-code-of-citys` 反而在"这个城市在哪个省"里排前。

## 四、工具服务侧六条契约（bnf 教训的直接产物）

| # | 契约 | 为什么 |
|---|---|---|
| 1 | 检索结果**自带分页可见性**：`page` / `page_size` / `total_pages` / `has_more` / `next_page` | 返回不带页码，模型就不知道还能翻页，于是重发同一查询 |
| 2 | 空结果给**可行动 hint** | 中文查询静默回空，模型只会换词乱试；hint 直接说"译成法/英，例：巴黎公社 → Commune de Paris 1871" |
| 3 | **参数约束写进描述**：语言（拉丁字母）、上限（max_results ≤ 50）、"一页 10 条刚好看清，要更多请翻页" | 约束不写，模型就会用自创参数名（`limitedNum` / `limit` 都出现过） |
| 4 | **载荷默认瘦身 + 显式取全量** | 一页 16KB 必被 6000 字符截断；核心 7 字段后 5.5KB，看得全 |
| 5 | **跨调用状态落盘** | 本项目"每次调用一条新连接"→ 工具进程每次全新，内存状态就是零 |
| 6 | **`nextStep` 必须自洽**，不得把模型推给别的工具 | 初始化让模型"去用别的函数搜来源"，它就会绕开本工具自己干 |

## 五、这些规则落在产品代码的哪儿（"固化"对照表）

**原则**：规范写在文档里只是"讲清楚"；**能自动兜的必须做进代码**——用户不会去读文档、更不会去跑测试脚本。

| # | 规则（来自哪次教训） | 落点（产品代码） | 对新接入的工具自动生效吗 |
|---|---|---|---|
| 1 | **参数类型宽容**：模型把标量写成字符串（`"15"` / `"true"`），旧实现直接拒 → 模型三连发 | `tools/capability_invoke.py` → `coerce_args()`（2026-10-06 新增；转不了的原样报错） | **是**（所有 API/MCP 工具） |
| 2 | **截断不切断 JSON**：旧实现硬切字符，模型看到半个对象 | 同文件 → `clip_payload()`（数组/记录列表按**完整条目**裁） | **是** |
| 3 | **截断要告诉模型怎么取更多**：否则它会把同一查询原样重发 | 同文件 → `_paging_hint()`（从 schema **自动认出**分页/数量参数并写进告知） | **是** |
| 4 | **素材齐备判定**（关键词可用性 / 工具级描述 / 英文名 / 否定式措辞 / 同源近名重叠） | `tools/capability_lint.py`（**产品模块**，不再是测试脚本里的私有逻辑） | **是**（接口自动调用） |
| 5 | **让用户知道该补素材**（不跑脚本也能看见） | `api/tools_sources.py` → `sources_list()` 回传每个来源的 `material` 体检 + 顶层 `material_summary.hint` | **是** |
| 6 | **描述/关键词怎么写**（领域锚定、不写否定式、避开通用词、同源工具必须能区分） | `prompt/prompts.yml` → `capability_writer`（"✨ AI 预写"就按这套纪律产出） | **是**（凡走 AI 预写的） |
| 7 | **模型侧纪律**：截断→用分页参数取更多；空结果→按提示改；参数用 schema 里的名字与原生类型 | `prompt/prompts.yml` → `main_agent`「工具使用总则」 | **是** |
| 8 | **服务侧契约**（分页可见性 / 空结果 hint / 载荷上限 / 状态落盘 / `nextStep` 自洽） | 由**服务作者**遵守（bnf 已逐条做）；调用层只能兜住"载荷超窗"与"参数类型" | 部分（第三方服务改不动，但危害已被调用层削掉大半） |
| 9 | **发现/导入工具后自动跑 AI 预写**，草稿随响应回给前端，**用户确认后才落库** | `api/tools_sources.py` → `discover()` 挂 `_auto_draft()`（非致命：缺依据/模型失败只回 `why`）；前端 `capDraftCache` + `capApplyDraft`（打开弹窗即预填） | **是** |
| 10 | **人话名字**：AI 预写同时产出显示名（`get-station-by-telecode` → 「站码反查车站」） | 提示词 `capability_writer` 的「名称：」行 → 解析器 `tools/capability_draft.py::parse_draft` 产出 `suggest_name`（**只作建议**）→ 用户在前端确认 → `cap_abilities_save` 写 `name` 列 | **是** |
| 11 | **素材问题一眼可见**：来源卡片上直接标「⚠️ N 条素材待补」，点击直达工具描述弹窗 | `front/index.html` 的来源卡片（API / MCP 两个页签）+ `sources_list()` 回传的 `material` | **是** |
| 12 | **"这批素材到底有没有让路由变好"** | `tests/live/m6b_material_ab.py`（冻结池/真实池）、`tests/live/m6b_delta_rerun.py --live-pool` | 否 —— 这是**验证**，不是接入的前提 |
| 13 | **CLI 能力描述的依据三选一**（网址 / 本机文件 / 跑 `--help`）—— 自研（未开源）与闭源公测的 CLI 没有可读文档页，`--help` 是唯一方法信息源 | `tools/cli_registry.py` → `DOCS_MODES` + `_validate_payload`（按模式各自校验）；`api/customize.py::cli_ability_generate`（三选一取证据；`help` 模式调 `collect_help_digest`）+ 前端 `front/index.html` 的单选 | **是**（用户在前端单选，不问"该填什么"） |
| 14 | **裸 `<bin> --help` 必须放行**（第 13 条 `help` 模式的前提）—— 它无副作用，且比放行任一子命令**更窄**：仍需清单非空、参数只能是无副作用开关，落盘参数照旧先拒 | `tools/cli_registry.py::readonly_verdict` + `HARMLESS_FLAGS` | **是** |
| 15 | **Windows `.cmd`/`.bat` 垫片经 `cmd.exe` 启动** —— npm / pipx 装的 CLI 在 PATH 上就是垫片，旧实现直接 `subprocess.run` 报 `WinError 193`，**工具根本跑不起来**（不只是取证，Agent 侧调用同样死） | `tools/_runtime/shell_runtime.py::execute`（仍传参数列表、`shell=False`；只挡 `%`/双引号/换行这三处 cmd 二次解析点） | **是** |

**一句话**：能自动兜的都做进调用层与接入接口（1~7、13~15）；只有第 9 条仍需跑闸门，
而它只在**你改了素材或改了路由**时才需要——日常接入新工具不必。

## 六、两道闸门

**静态闸门** `tests/live/m6b_material_lint.py`（只读，秒级；**规则同源于产品模块 `tools/capability_lint.py`**）
：逐条检查素材齐不齐 —— 关键词是否可用（去掉泛化词后还剩什么）、工具级描述是否到位、
名字是否英文标识符、是否含否定式措辞、同源条目关键词是否高度重叠。
★ 它的规则**对齐 `capability_pool` 的真实语义**（例如：写了 `abilities_user` 后自动摘要不进向量文本，
所以"自动摘要过长/是英文"只在**没写**工具级描述时才算问题）。

**动态闸门** `tests/live/m6b_material_ab.py`（只读，约 20 秒，零额度）
：三模式 —— 默认「冻结池＋草稿」测素材本身有没有效；`--live-pool` 测库里现状；
`--live-pool --draft` 测"在现状之上再补这批素材会怎样"。输出 5 例回归落位 + 30 题五指标 + 噪声题逐题 **z 值**。

**闸门三条纪律**（都是踩出来的）：

1. **必须在「你要发布的那份池子」上量**。混合池会给假信号 ——
   本轮就出现过两次"噪声 0.333"的假警报（冻结池 + 含暂缓条目的草稿），
   而真实池上六个噪声题的 z 只有 1.31~1.92，离阈值 2.4 有明显余量。
2. **噪声是硬判据，但不能只看布尔值**：池内余弦标准差极小（实测 ≈0.01），
   所以要同时看逐题 z 的余量，才能区分"踩线"与"安全"。
3. **阈值（`Z_STRONG=2.4`、`LEX_MIN=2`）不在素材改动里顺手调**。
   改阈值必须重跑基准并另行裁决（既有裁定：阈值调整不在本任务范围内）。

## 七、接入流程（六步）

| 步 | 动作 | 命令 / 产物 |
|---|---|---|
| 1 | 接入来源并验证连通 | 来源配置（`tool_sources.config_json`）+ 能力卡刷新 |
| 2 | 跑静态闸门 | `tests/live/m6b_material_lint.py <账号>` |
| 3 | 按三件套补素材（先起草，冻结池试跑） | 起草落在 `tests/fixtures/material_layer_draft.json` |
| 4 | 跑动态闸门（`--live-pool --draft`，**不入库**） | `tests/live/m6b_material_ab.py --live-pool --draft` |
| 5 | 备份入库 | 整库快照 + 行级回滚 → `docs/v3.1/backups/` |
| 6 | 复跑 + 真机 | `tests/live/m6b_delta_rerun.py --offline-only --live-pool`，再跑真机由人工打分 |

★ 工具服务侧的改动（第四节六条）走同样的路线：先备份服务目录 → 改 → 用**服务自己的 venv** 直连调用验证
（例：`D:\LLM\mcp_servers\bnf\env\Scripts\python.exe`）→ 记录到服务 `README.md` 的"本地改动记录"。

## 八、边界

- **不做**（既有裁定，不要顺手加）：重复调用护栏、阈值调整、Jev 仲裁层。
- 本规范只覆盖两件事：让工具**被正确想起**（素材层）与工具**自己把话说清楚**（服务侧契约）。
  **模型侧的调用纪律**是第三层，不在本规范内。
- 素材是**账号数据**：入库属"改用户数据"操作，必须先备份、必须只有明确授权才做。

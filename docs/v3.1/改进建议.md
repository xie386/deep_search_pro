## 一、几处"自洽性"问题

### 1. subagents 的颜色破了你自己的规则

你定的规则是"**绿=编排层 · 橙=工具族**"，但：

- `builtin` → 橙（工具族）✓
- `subagents` → **绿**（编排层？）
- `cli` → 橙（工具族）✓
- `apimcp` → 橙（工具族）✓

图上 subagents 和 builtin/cli/apimcp 是**并列的四条工具入口**，都从 main 出发。视觉上它是一种"工具"，但颜色上它被归入编排层。

如果你的本意是"子 Agent 是 Agent，不是工具，所以归编排层"，那**图面上需要有个视觉提示**（比如给 subagents 加一个双层边框，或把它的 sigil 换成和 main 一样的），否则读者只会看到"三橙一绿并列"，感觉是失误。

**建议二选一：**
- A. 把 subagents 改成橙，和其余三族工具一致（"工具族"= 主 Agent 可 dispatch 的一切）
- B. 保留绿色，但给 subagents 加一个**区别于 backend 的标记**（比如和 main 一样用实心 sigil，而 builtin/cli/apimcp 用空心），并在一处文案里点明"子 Agent 属于编排层，不是工具"

### 2. emphasis 不一致

```html
gateway → cli     class="a-default"   stroke-width="1.5"
gateway → apimcp  class="a-emphasis"  stroke-width="1.8"
```

`ref 分派` 是 emphasis，但同样语义的 `cli: ref` 是 default。**同层的两条分派路径不该一强一弱**。

**建议：**
- 如果两条都是"网关按 ref 分派到不同工具族"，**都 emphasis**
- 如果你是想强调"分派"这个动作本身，**都 default**，让 `main → gateway` 单独 emphasis
- 如果确实想表达"apimcp 是主通道、cli 是辅通道"，那在图例或 sublabel 里说清楚

原版 `main → subagents` 有 `data-edge-label="task 调度"`，新版移除了。虽然卡片①写了"主 Agent 逐个 task 调用"，但：

- **图面上没有表达"子 Agent 是通过 task 机制被调度的"**

## 三、视觉/布局上的小事

### 5. `external` 节点触底

```html
<rect x="780" y="430" width="200" height="58"/>
```

y + height = 488，距 viewBox `height=500` 只剩 **12px**。加上 audit 已经从右下移到右上，右下这块空了，external 完全贴底。如果视觉上不需要这么靠下，可以整体上移 10–20px。

### 6. `audit` 和 `apimcp` 的垂直间距偏紧

```
audit:   y = 190 … 248
apimcp:  y = 310 … 368
gap = 62px
```

中间只隔了 62px，且两条都靠右侧（x=910）。如果以后 audit 加更多字段（比如"P95 耗时 / 拒单率"），容易撞车。可以让 audit 再往上走一点（y=170），或让 apimcp 往下走（y=330）。

### 7. `font-size="7.6"` 是个不常见值

内置工具的 sublabel 从 `文档读写 · 知识库 · 个人库` 扩到 `文档读写 · 知识库 · 个人/公司库 · 画像更新`，字号从 9 降到 7.6。这个数字在 Archify 的设计系统里没有对应层级，看起来是为"塞进去"临时调的。

**建议：** 要么精简文字（比如 `文档读写 · 知识库 · 画像更新`），回到 font-size=9；要么拆两行（第一行 `文档读写 · 知识库`，第二行 `个人/公司库 · 画像更新`），保持 9 号字。

### 8. `accountdata` 的边界框包一个节点

```html
<rect x="10" y="80" width="240" height="114" class="c-region" 
      data-composition-frame-label="账号数据（按账号隔离）"/>
```

框里只有 `accountdata` 一个节点。这种"单节点边界框"通常表示"这一块是一个独立的部署单元/隔离域"，如果确实是这个意思，建议在框的样式上区别于 `自配来源`（比如用 dashed 而不是 solid，或者用更浅的填充），否则两个 region 视觉权重一样，读者不知道哪个更"重"。

## 四、引导视图的"执行与回流"章可以再真实一点

```json
{"id":"exec","label":"③ 执行与回流","focus":["main","gateway","cli","apimcp","external"]}
```

note 说"结果与错误原文本轮回流给模型"，但 focus 的节点列表**停在 external**，没有回到 main。视觉上是一条"出去就没了"的链。

**建议改法（任选）：**

- A. focus 里加一次 main：`["main","gateway","cli","apimcp","external","main"]`（重复 main 表示回环）—— Archify 的 story 机制支持节点重复吗？看代码 `seen[id]` 会去重，不支持。所以这个方案不行。
- B. 把 external 的 sublabel 改成 `第三方 API · MCP · 本机 CLI → 结果原文本轮回流`，让回流发生在终点节点上
- C. 更简单：把 note 改成 `自配工具一律过网关；此处终点即回流起点——结果原文本轮进模型上下文，失败走 failure_log 归类`

我推荐 **C**，不动任何 SVG，只调一句文案，把"闭环"这个意思补上。

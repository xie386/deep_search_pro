### L0 · 非 Python 代码文件（契约与配置面）

#### L0-1 `prompt/prompts.yml`（8 个顶层键）

**职责**：静态提示词。路由相关的只有三处 —— ①主 Agent 的「工具使用总则 + 三类工具」；
②`ability_writer`（CLI 能力描述撰写 AI）；③`capability_writer`（API/MCP 工具描述撰写 AI）。

**关键位置**：

| 行 | 内容 | 为什么重要 |
|---|---|---|
| :10-13 | 注释：**机械细节不重复**（argv 形状写在 `shell_executor` 的 `@tool` 文档串、注入块里）；「动了工具或路由相关措辞，再跑真机 `tests/m5_probe_e2e.py`」 | 项目的提示词维护纪律：**一处写、别处不抄**（防止改一处漏三处） |
| :38-44 | 工具使用总则（私有数据优先 → 一次只调一个 → 失败不许原样重试 → 被拒要如实转述） | 「一次只调一个」是**抑制重试风暴**的静态侧约束 |
| :46-51 | **你手上的三类工具**（内置 / 子智能体 / 用户自配 CLI），含「**只列名称不等于不可用**」 | 三形态注入（第 3 形态=仅名称行）能成立的前提就是这一句 |
| :53-55 | 口语提问先按**关键词**判断；few-shot 区块「只是格式示范」，不许编造 | 与 `lexical_scores` 的「关键词行」设计互为表里 |
| :250-283 | `ability_writer`：草稿格式（**第一行：关键词：<8~15 个，用 / 分隔>**，:265） | 决定了 `_KEYWORDS_PREFIX` 能认到什么（`capability_pool.py:34`） |
| :72-79 | **助手笔记的经验沉淀**（2026-10-02 新增）：三条写法（**可复用** / 结论+最小证据、**单次偶发不许写成规律** / 不写隐私）＋ ★ **经验类内容必须在回答里提醒用户复核** | 与路由间接相关：笔记里的「工具经验」（如某 CLI 参数口径）会被**每轮注入**，写歪了会长期影响模型选工具/用工具 见 `docs/v3.1/助手笔记-工具经验沉淀与复核提醒.md` |
| :291+ | `capability_writer`：API/MCP 的**工具级描述**（M5c-2'） | 与 `capability_draft.py` 的解析器配对 |
| — | `soul_writer`(:224) / `memory_initializer`(:336) / `memory_suggester`(:362) | 与路由无关（但同属「人格/记忆」这条装配线） |

**逐行检查要点**：① 这里**不许**出现端点 URL / 命令行 / env / 密钥（`tests/live/test_capability_draft.py`
有断言钉着）；② 三类工具的定义与 `capability_pool` 的三种 `source` 是**同一件事的两种表述**，改一处要

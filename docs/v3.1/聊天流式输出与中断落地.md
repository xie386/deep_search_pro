# 聊天正文/思考的流式输出 + 中断真正落地（2026-10-02）

> **配套**：**逐行检查**这份实现请读 `docs/v3.1/聊天流式输出-逐文件带读.md`（六层阅读指南 + 每文件关键行号 + 逐行检查要点 + 思考题 + 六条不变量）
> **体例**：现象 → 现状（代码定位）→ 调研与实测 → 方案 → 落地 → 验证 → 边界与已知问题（`docs/README.md` §一 小数版规则）
> **一句话**：原来一轮回答是「整轮跑完一次性返回」—— 用户看不见正文与思考、也就没机会在方向错时按中断 
>（中断机制一直存在，缺的是**可见性**）。本期改成：**主图逐 token 增量经既有 WS 推前端**，
> 中断粒度从「每次模型调用前」加密到「每个增量之间」，**前端与落库契约不变**

## 一、现状（改造前，逐处代码定位）

| 环节 | 改造前 | 位置 |
|---|---|---|
| 后端 | `answer = await asyncio.to_thread(_run_agent, …)` → **整轮跑完才返回一次性 JSON** | `api/server.py::api_chat` |
| 前端 | `const data = await r.json();` | `front/index.html` 的 `send()` |
| 思考 | `thinking_capture` 在 **invoke 完成后**遍历 `result["messages"]` 提取（post-hoc） | `agent/thinking_capture.py` |
| 运行中可见性 | 只有 WS 的**事件级** `monitor_event`（工具开始/结束、阶段提示）——不是模型的 token | `api/monitor.py` |
| 模型层 | ★ `ReasoningChatOpenAI` **早已写好**流式的 reasoning delta 处理（`_convert_chunk_to_generation_chunk`） 但全项目 `.stream(` / `astream` / `stream_mode` **零调用** | `agent/reasoning_model.py` |
| 中断 | **机制是有的**（`agent/cancel.py` + `_generate`/`_stream` 前置检查 + `/api/chat/cancel` + 前端 `stopping`/`chatAbort`） 但没环境：看不见过程 → 判断不了"方向错了"；且前端 `abort()` **停不掉后端**（线程池任务不可取消，真正省 token 的是 cancel 标记） | — |

## 二、调研与实测（不靠推理，先跑）

先用项目自己的 agent 单例跑 spike（`tests/debug/_spike_stream_probe.py`，一句话、零工具、不写库）：

| 观测 | 结果 |
|---|---|
| `agent.stream(stream_mode=['messages','values'])` | ★ **可用** 收到 5~9 个 token 块、`metadata['langgraph_node']='model'`—— 原本担心的拦路石（`langchain/agents/factory.py:1406` 的 `_execute_model_sync` 是 `model_.invoke(messages)`，**没显式传 config**）**靠 contextvar 依然透传成功** |
| 正文增量 | 分块到达 |
| 思考增量 | 走 `additional_kwargs['reasoning_content']`（OpenRouter 的 `reasoning` 字段已在 `ReasoningChatOpenAI` 归一） |
| 聚合后消息形态 | **不变**（content + reasoning_content 都在）→ `thinking_capture` / `answer_text` 提取逻辑**不用改** |
| ★ 用量 | `usage_metadata` **完整**（input/output/cache_read）→ **成本表与用量计数不受影响** |
| 时延 | 首块 ~5ms、首个正文 token ~2.7s（前面是思考） |

## 三、方案（选定的那条）

**图级流式 + 复用既有 WS + 调用侧开关**（不引 SSE 新端点、不写第二套传输）：

- **后端**：`api/server.py::_invoke_or_stream()` —— 用 `agent.stream(stream_mode=['messages','values'])`：
 `messages` 出 token 增量、`values` 取**最后一个**状态 = `invoke` 的返回值（**下游一行都不用改**）；
- **过滤**：只推**主图**—— 实测主图 `langgraph_node='model'` 且 `checkpoint_ns='model:<uuid>'`（不含 `|`）；
 langgraph 子图（子 Agent 作为工具跑）的 `checkpoint_ns` 含 `|` → 一律不推（否则子 Agent 的 token 会串进聊天气泡）；
- **节流**：`agent/stream_sink.py::DeltaSink` 默认「60ms 或 80 字符」推一次（每 token 一次 WS 写是洪峰）；
 首块**立即**推（第一眼就要看到字）；
- **传输**：复用 `/ws/{thread}` 的 `monitor_event` 通道 新增事件 `{event:'delta', data:{kind:'answer'|'reasoning', text, seq}}` 
 （`api/monitor.py::report_delta` 控制台/CLI 侧跳过增量 不刷屏）；
- **中断**：每个增量过一次 `agent_cancel.check()` → 从「每次模型调用前」加密到「每个 token 段之间」
 真正省下本轮剩余 token；已流出的半截附在异常上传回 → **落库与前端看到的是同一条内容**（刷新后不会只剩占位语）；
- **开关**：`.env` 的 `ZX_STREAM`（**默认开** `=0` 回退到改造前的一次性 `invoke` 便于 A/B 与回滚）；
 只有前台问答走流式 子 Agent / digest / CLI 继续同步（它们共用同一个 model 对象，"按调用方开"是必须的）。

## 六、边界与已知问题（如实）

- ✅ **e2e 收尾不退出 —— 已定位并修复**（真根因 = **`TestClient.__exit__` 关闭 portal 时在等 reader 线程那条挂着的
 WS 会话**；`taskkill /T` **0.2s** / `purge_account` **0.0s** 实测都不卡 三个旧怀疑全不成立）。
 现为真 uvicorn 版：**7/7 · `exit=0` · 无残留**—— 详见 `docs/v3.1/聊天流式输出-逐文件带读.md` §四 4.1 ✓。
- ✅ **思考增量—— 已证实经 WS 到达**（真原因不是供应商，是**问题不激发推理**：
 换「17×23 两步推理」后思考 **4 块 / 274 字** ✓）—— 详见同文件 §四 4.2 ✓。
- ⚠️ **工具轮是分段流**：每次模型调用一段 中间工具执行期会停顿—— 这一段靠既有 `monitor` 事件填。
- ⚠️ 别的供应商可能**不返回 usage**（本模型实测有）→ 换供应商要复核成本表。
- ⚠️ 尚未做的：中断的"半截文本"在前端与库两端都有，但**没有**给用户一个"继续生成"的入口（本轮不做）。

## 七、回滚

`.env` 里 `ZX_STREAM=0` → 立刻回到改造前行为（`agent.invoke` 一次性返回 前端仍能正常渲染 因为它走 `finishStreaming` 返回 false 的老分支）。

# 助手笔记：工具经验沉淀与「复核提醒」（2026-10-02 用户拍板 A + 新增第 4 条）

> **体例**：现象 → 证据 → 定性 → 方案 → 落地 → 验证 → 边界（`docs/README.md` §一 的小数版规则）
> **一句话**：agent 会**自主**把工具使用经验（能力边界、参数口径、踩过的坑）写进 `MEMORY.md` 的
> 助手笔记段—— 这不是项目设计要求的，是**模型自己的行为倾向**；
> 拍板**保留这个行为**并给最小规范，同时要求：**经验类内容写入后必须在回答里提醒用户复核** 

---

## 一、现象（用户 2026-10-02 发现）

修 `MEMORY.md` 时注意到：agent 会总结**自己用工具时报错后的修正经验**并沉淀成笔记（例：
「微信 CLI 检索经验（与「袁战」会话实操得出）」里写着 `--chat` 中文会话名会 mojibake、
`history` 的时间参数要用完整时间戳）。

但同样的场景在 **agnes-2.5-flash** 时期也出现过工具报错，**没有**形成类似笔记 
→ 用户提出两种解释：**项目 agent 设计使然**？（印象里只有长期状态与用户喜恶进画像）还是**模型倾向**
（即模型质量问题）？

## 二、证据（都查了库与提示词）

| # | 证据 | 结论 |
|---|---|---|
| 1 | `prompt/prompts.yml:72` 只有一句「助手笔记（`## MEMORY` 段）仍用【写入文档工具】维护（那是流水笔记，不是画像）」 | **授权**（指定工具 + 划清与画像的界限），**零内容规范** |
| 2 | 注入块的 `mem_hint`（`agent/build_context.py`）每轮都告诉模型「记忆文件：`<用户名>/MEMORY.md`，读写工具的 filename 用这个相对路径」 | 设计**提醒了这个文件可写**（但不是要求它写什么） |
| 3 | 画像段有**严格规则**（9 维白名单 + 两个触发源 + 就地更新 + 不许用写入工具整份重写）；笔记段**一条都没有** | **结构性诱因**：任何「想长期记住的东西」都会自然流向笔记段 |
| 4 | 全文 grep `prompts.yml`：**没有一处**出现「经验 / 教训 / 踩坑 / 复盘 / 工具使用记录」 | **不是设计承诺的行为** |
| 5 | `conversations.id=604`（2026-09-28）：用户只问「Jev 模型情报」 → agent 答完后**主动** `write_agent_doc`，回执「写入成功：尼古喵喵/MEMORY.md（追加，215 字符）」 | **自发**写笔记（用户没让它记）；且**不是 space-bunny 独有** |
| 6 | `conversations.id=1543`（2026-10-02 19:58）：用户问「总结一下你对 wechat-cli 工具的使用经验」→ agent 先 `read_agent_doc`，回答「**笔记里已经有一份实操沉淀**」 | ★ 那段工具经验是**更早的会话里自主写下的**（该轮它没有写笔记） |
| 7 | `usage_events`：agnes-2.5-flash 期（09-29/09-30，20 条模型事件）同提示词、同工具、同账号，**没有**经验类沉淀 | 唯一变量是模型 |

⚠️ **诚实说明**：10 月那两条工具经验笔记的**原始会话已被清理**（探针会话，按水位线删除），
所以「哪一轮写的」已无法直接查证；但第 6 条证明它们**先于**用户的这次提问就存在。
另外第 5 条那次写入的模型在库里 `model_name` 为空 已不可考—— 所以**不能**断言「只有 space-bunny 会写笔记」，
能断言的是：**写什么内容**的取舍由模型定，且 agnes 期没有形成「工具经验」这类沉淀。

## 三、定性

- **不是项目设计使然**：设计只提供「可写 + 每轮告知路径 + 笔记段无规范」这套**自由度**，
 提示词从未要求记录工具经验；
- **也不是笼统的「模型质量问题」**：agnes 也真把问题解决了 只是没沉淀——
 差别在**是否把过程性教训当成值得持久化的知识**，是**后训练出来的行为倾向**（复盘型 vs 完成型）；
- **准确表述**：`模型倾向 × 提示词留下的自由度` 的乘积—— 属于**意外的正向涌现**（可保留、需收边）。

## 四、方案（用户拍板 A + 新增第 4 条）

在 `prompt/prompts.yml` 的记忆维护段，给笔记段**补最小规范**，并新增一条**硬要求**：

| # | 规则 |
|---|---|
| 1 | 只记**可复用**的经验（能力边界、参数口径、踩过一次的坑）；一次性的用户信息不进笔记（那些进画像） |
| 2 | 写成「**结论 + 最小证据**」；**单次偶发不许写成规律**（拿不准就写「某次出现这样」而不是「总是/根本不能用」） |
| 3 | 不写隐私与账号数据（会话原文、密钥、他人信息一律不写） |
| 4 | ★ **经验类内容必须提醒复核**：只要新增/修改了「工作经验类」的记忆（工具、来源、命令的使用经验 —— **无论落在助手笔记还是画像维度里**），都要在回答里一句话说明「我记了一条工具经验：…」，请用户确认是否准确、要不要改或删；**没提醒就等于没记完** 未经确认前只当参考，不许在后续对话里当铁律 |

★ 第 4 条的**范围**：明确写了「其余普通画像更新按第 1 条办（告知记了什么即可，**不必**要求复核）」——
否则每轮普通画像更新都要催复核，用户会被烦到。

## 六、边界与风险

- **注入预算**：笔记段注入上限 `NOTES_MAX_CHARS=300` / 最多 5 条（`agent/build_context.py`）
 现在这段笔记已超预算 → 注入时按与问句的词法相关度裁剪 = **写太多反而记不住**（用户可随手删旧的）；
- **换模型仍会波动**：第 4 条只管「写进去之后必须提醒复核」；「是否愿意沉淀」仍取决于模型 
（这是本方案接受的代价）；
- **不做的事**：不引入自动写笔记的机制（不替模型决定记什么）、不改笔记段与画像段的结构、
 不动前端。

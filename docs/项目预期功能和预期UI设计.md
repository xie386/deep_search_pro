# 项目预期功能 & 预期 UI 设计（智选情报官）

> 状态：v0.4（定稿版，产品名「智选情报官」已确认，可作为开发准绳）。
> 基于现有框架能力撰写：主 Agent 调度 + 网络搜索子 Agent（Tavily）+ 数据库子 Agent（MySQL）+ 监控埋点（api/monitor.py）+ 多轮上下文记忆（MemorySaver）+ Word/PDF 导出（utils/word_converter.py）。
> 本阶段 RAGFlow 知识库助手暂未装配（学习进行中），文档中标注为「二期」。

## 一、产品定位

**一句话**：一个**本地纯个人使用**的 AI 情报助手。登录后按账号角色提供两类服务——
- **公司账号**：输入竞品公司 / 产品 / 行业关键词，AI 情报官联网搜集公开情报、结合内部市场/产品/销售数据，产出带引用来源、可导出 PDF 的竞品情报简报；
- **个人账号**：为你推送感兴趣产品领域的**快讯**，并对同类商品做**多品牌性价比入手分析**，帮你做购买决策。

**核心价值**（区别于普通 ChatGPT）：
- 外（全网公开信息）× 内（你的数据库）双源融合交叉推理；
- 每个结论标注来源（网络 / 数据库表 / 知识库文档），可追溯、抗幻觉；
- 为客户（买家）多方面展示各个品牌商品的情报，综合对比出性价比好的产品；
- 产出结构化报告，可定时生成，从「问答工具」升级为「情报同事」。

**目标用户**：**客户买家**（关注性价比的消费者）、创业者、产品经理、投资人、市场/战略分析岗。
> 即：同一套框架，既服务「公司做竞品分析」，也服务「个人做选购决策」。

## 二、账号与角色设计（新增）

> 定位：**本地纯个人使用**，非多租户 SaaS。账号体系用于「切换服务视角」与「隔离个人/公司数据」，不涉外部认证。

| 账号类型 | 服务对象 | 主要功能 | 数据范围 |
| --- | --- | --- | --- |
| **公司账号** | 创业者/产品经理/分析师 | 竞品情报官（见第三节公司侧功能） | 本公司产品/销售库、关注竞品清单 |
| **个人账号** | 买家/消费者 | 快讯推送 + 多品牌性价比入手分析（见第三节个人侧功能） | 个人兴趣领域、关注商品/品牌、历史分析 |

**账号库表设计**（建议新增 `accounts` 表，字段示意）：
```
accounts(
  id, username, password_hash,
  role ENUM('company','personal'),
  display_name,
  created_at
)
```
- 个人账号额外关联：`user_interests`（兴趣领域，如「耳机/显卡/咖啡机」）、`user_watchlist`（关注品牌/商品）。
- 公司账号额外关联：原有 `our_products` / `our_sales` / `competitors` 等业务表。

> 已定：账号/个人数据用 **SQLite 本地文件**（零部署、纯个人场景最合适）；公司业务数据仍用 **MySQL**。双库并存。

## 四、预期数据库设计（一期）

基于现有 `db_tools.py` 的 `list_sql_tables / get_table_data / execute_sql_query` 工具，一期建表（样例数据由我们造）：

**账号 & 个人库（建议 SQLite 本地文件）**
| 表名 | 作用 | 关键字段（示意） |
| --- | --- | --- |
| `accounts` | 账号与角色 | id, username, password_hash, role, display_name, created_at |
| `user_interests` | 个人兴趣领域 | id, account_id, interest_tag |
| `user_watchlist` | 个人关注品牌/商品 | id, account_id, brand, product, note |

**公司业务库（沿用 MySQL）**
| 表名 | 作用 | 关键字段（示意） |
| --- | --- | --- |
| `our_products` | 本公司产品/定价/功能矩阵 | id, product_name, price, core_features, launch_date |
| `our_sales` | 本公司销售/营收数据 | id, product_id, month, revenue, region |
| `competitors` | 关注的竞品清单（F7 用） | id, comp_name, category, website, note |
| `competitor_news` | （可选）人工维护的竞品动态缓存 | id, comp_id, title, source_url, captured_at |

> 说明：网搜拿到的公开情报**不落库**（实时检索），只有「我们自己的数据」「关注清单」「账号/个人偏好」落库——这正体现「内×外融合」的设计哲学。

## 五、预期 UI 设计

### 5.1 整体形态
- **形态**：Web 应用（FastAPI 后端 + 轻量前端，WebSocket 实时推送）。
- 为什么不是纯命令行：F4 实时过程可视化、F6 报告导出、账号切换均依赖图形界面；CLI（`main.py`）已跑通，Web 是能力放大器。
- 前端技术：**Vue/React**（用户已确认，非纯 HTML/JS）。
